# 📓 THM - OWASP Top 10 2025: Application Design Flaws (Yazılım Tasarımı ve Mimari Hataları)

**Tags:** #BlueTeam #AppSec #OWASP2025 #InsecureDesign #SecurityMisconfiguration #SupplyChain #CryptographicFailures #CyberChef #SOC_L1 #TryHackMe #Walkthrough

## 🏗️ Mimari Yapı

**OWASP Top 10: 2025** standartlarında uygulama güvenliği, artık sadece kod seviyesindeki basit yazım hatalarından (syntax bugs) ziyade, sistemlerin **yapısal, mantıksal ve mimari tasarım eksikliklerine (architectural & design flaws)** kaymıştır. Güvenlik, geliştirme sürecinin (SDLC) sonuna eklenen geçici bir yama değil; sistemin temel mimari gereksinimi olmak zorundadır.

```
                  [ Uygulama Tasarım ve Mimari Zafiyetleri ]
                                      │
    ┌──────────────────┬──────────────┴───────────────┬──────────────────┐
    ▼                  ▼                              ▼                  ▼
 [ AS02 ]           [ AS03 ]                       [ AS04 ]           [ AS06 ]
Misconfiguration  Supply Chain Failure            Crypto Failure    Insecure Design
- Yanlış ayarlar   - Üçüncü taraf kütüphaneler    - Zayıf algoritmalar - Yanlış varsayımlar
- Verbose error    - Zafiyetli bağımlılıklar      - Hardcoded keys    - Tehdit modeli yok
```

Bu döküman, tasarım aşamasında yapılan mantıksal hataların yol açtığı 4 ana OWASP 2025 kategorisini ele almaktadır:

1. **AS02: Security Misconfigurations (Güvenlik Yanlış Yapılandırması):** Sunucuların, servislerin veya uygulamaların güvensiz varsayılan ayarlarla (default credentials, açık S3 bucket'ları) yayına alınması veya hata mesajlarında sistem detaylarının (**Verbose Errors**) dışarı sızdırılmasıdır.
    
2. **AS03: Software Supply Chain Failures (Yazılım Tedarik Zinciri Hataları):** Uygulamaların güvendiği dış kütüphane, paket (pip, npm) veya AI modellerinin doğrulanmadan otomatik güncellenmesi veya zararlı kod içermesidir (Örn: SolarWinds skandalı).
    
3. **AS04: Cryptographic Failures (Kriptografik Hatalar):** Şifrelemenin hiç uygulanmaması, zayıf/eskimiş modların (MD5, AES-ECB) seçilmesi veya gizli anahtarların kaynak koda gömülmesi (**Hardcoded Keys**).
    
4. **AS06: Insecure Design (Güvensiz Tasarım):** Tehdit modellemesi yapılmadan, _"API'ye sadece mobil cihazlar erişebilir"_ gibi yanlış mimari varsayımlarla (flawed assumptions) sistem inşa edilmesidir.
    

## 💻 Tüm Komutlar, HTTP İstekleri ve Kod Parçacıkları

### A. AS02: Verbose Error / API Hata Analizi

- **İstek Adresi:** `http://MACHINE_IP:5002`
    
- **Zafiyetli Parametre:** `User ID`
    
- **Saldırı Vektörü (Input Injection):**
    
    İstenecek User ID alanına sayısal değer yerine alfabetik bir dizecik (string) gönderildiğinde:
    
    Plaintext
    
    ```
    Input: "abc" veya "test"
    ```
    
    - **Sistem Tepkisi (Verbose Error):** Sistem `400/500 Error` üretirken arka plandaki veritabanı sorgu formatını, stack trace dökümünü ve içeride gizlenmiş bayrağı (flag) sızdırır.
        

### B. AS03: Supply Chain Debug Parametre Manipülasyonu

- **İstek Adresi:** `http://MACHINE_IP:5003/api/process`
    
- **Geliştirici Araçları Adımı:** Tarayıcıda `Sağ Tık -> İncele (Inspect) -> Network Sekmesi -> Reload`.
    
- **Orijinal HTTP İsteği:** `GET /api/process HTTP/1.1`
    
- **Manipüle Edilmiş HTTP POST İsteği (Burp Suite veya DevTools Network Replay):**
    
    HTTP
    
    ```
    POST /api/process HTTP/1.1
    Host: MACHINE_IP:5003
    Content-Type: application/json
    
    {
      "data": "debug"
    }
    ```
    
    - **Açıklama:** Zafiyetli dış kütüphaneyi (`vulnerable_utils.py`) import eden eski kod blokları, JSON payload alanında `"debug"` parametresini gördüğünde dahili sistem kontrollerini atlayarak yanıt (Response) gövdesinde bayrağı döner.
        

### C. AS04: Hardcoded Secret Key ve CyberChef AES-ECB Reçetesi

- **İstek Adresi:** `http://MACHINE_IP:5004`
    
- **DevTools İnceleme Adımı:** Tarayıcıda `Inspect -> Debugger / Sources -> static/js/app.js` içerisine bakıldığında:
    
    JavaScript
    
    ```
    // Kaynak koda gömülmüş sabit simetrik anahtar (Hardcoded Secret Key)
    const SECRET_KEY = "my-secret-key-16";
    ```
    
- **CyberChef Deşifreleme (Decryption) Reçetesi:**
    
    Şifreli döküman metni CyberChef aracına `Input` olarak yapıştırılır ve sırasıyla şu modüller uygulanır:
    
    1. **From Base64** (Sıkıştırılmış/kodlanmış metni ham baytlara çevirir).
        
    2. **AES Decrypt:**
        
        - **Key:** `my-secret-key-16` (UTF-8 / Plaintext)
            
        - **Mode:** `ECB` (Electronic Codebook - Desene açık zayıf mod)
            
        - **Input:** `Raw` / `Base64`
            

### D. AS06: Insecure Design & Direct API Query

- **Zafiyetli Varsayım:** Geliştiriciler API'ye yalnızca mobil uygulamanın erişebileceğini varsaymış, backend uç noktasına kimlik doğrulama koymamıştır.
    
- **Masaüstü/Tarayıcı Sorgusu:**
    
    HTTP
    
    ```
    GET /api/messages/admin HTTP/1.1
    Host: MACHINE_IP:5005
    ```
    
    - **Açıklama:** Mobil cihaz kontrolü yapılmadan doğrudan tarayıcıdan admin mesajlaşma API endpoint'ine atılan istek, hiçbir session/token sormadan gizli verileri dökümante eder.

## 🧠 Uzman Notları ve Kritik Uyarılar

> ⚠️ **MÜLAKAT HAPI - AES-ECB MODU NEDEN TEHLİKELİDİR?**
> 
> Sızma testi ve uygulama güvenliği mülakatlarında en çok sorulan kriptoloji sorusu: _"AES şifrelemede Electronic Codebook (ECB) modu neden asla kullanılmamalıdır?"_
> 
> **Analist Yanıtı:** ECB modu, girdiyi bağımsız bloklara böler ve **her aynı düz metin bloğunu (plaintext block) birebir aynı şifreli metin bloğuna (ciphertext block) dönüştürür**. Bu durum rastgeleliği (randomness/IV) ortadan kaldırır. Saldırgan anahtarı bilmese bile şifreli verinin içindeki desenleri (pattern analysis - Örn: ECB Penguin görseli) analiz ederek verinin içeriğini çözebilir. Şifrelemede daima IV/Nonce kullanan **GCM (Galois/Counter Mode)** veya **CBC** tercih edilmelidir.

> 💡 **SEKTÖREL İPUCU - VERBOSE ERROR MESSAGES (DETAYLI HATA MESAJLARI):**
> 
> Bir web uygulamasında `400 Bad Request` veya `500 Internal Server Error` döndüğünde ekranda `SQL Syntax Error...`, `Django Stacktrace` veya `Uncaught TypeError at line 42...` görmek bir siber güvenlik analisti için altın değerinde bir istihbarattır (Reconnaissance). Bu mesajlar saldırgana uygulamanın veritabanı türünü, kullanılan kütüphane versiyonlarını ve kod mimarisini sunar. Canlı (production) ortamlarda kullanıcıya daima jenerik hata mesajları (`"Bir hata oluştu, lütfen destekle iletişime geçin"`) gösterilmeli, detaylı hata logları ise sunucu içinde izole saklanmalıdır.

> 🚨 **SOC ANALİSTİ UYARISI - MOBİL API VARSAYIMI VE FUZZING:**
> 
> Geliştiricilerin en sık düştüğü tuzak: _"Bu API'yi sadece bizim Android/iOS mobil uygulamamız çağırıyor, o yüzden kimlik doğrulamaya gerek yok, kimse URL'i bilemez."_ Saldırganlar mobil uygulamaların ağ trafiğini Frida veya Burp Suite ile dinleyerek (HTTP History) veya endpoint fuzzing (`ffuf`, `gobuster`) yaparak arka plandaki `/api/messages/admin` gibi gizli yolları saniyeler içinde keşfederler. Her API ucu, istemciye bakılmaksızın **sunucu tarafında (server-side) zorunlu Authentication ve Authorisation** denetiminden geçmelidir!
