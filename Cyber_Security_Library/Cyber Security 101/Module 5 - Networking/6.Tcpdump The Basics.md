## 🎛️ 1. Mimari Temeller ve Altyapı Kütüphaneleri

> **Mavi Takım Notu:** Ağ protokollerini öğrenirken en büyük engel, kurumsal trafik trafiğinin şık kullanıcı arayüzlerinin arkasına saklanmasıdır. `tcpdump`, ağdaki tüm üçlü el sıkışmaları, ARP sorgularını ve ham paket akışlarını en yalın haliyle terminale dökerek anomalileri avlamamızı sağlar.

- **Geliştirme Altyapısı:** `tcpdump` aracı ve arkasındaki asıl paket yakalama motoru olan **`libpcap`** kütüphanesi C ve C++ dilleriyle yazılmıştır. Unix tabanlı sistemler için 1980'lerin sonu ile 1990'ların başında optimize edilerek piyasaya sürüldüğünden ötürü inanılmaz kararlı çalışır ve minimum kaynak tüketimiyle maksimum hız sunar.
    
- **Genişletilebilirlik:** `libpcap` kütüphanesi günümüz siber dünyasındaki birçok modern ağ analiz aracının (Wireshark dahil) temel çekirdeğini oluşturur. Bu kütüphane Microsoft Windows mimarisine **`winpcap`** ismiyle port edilmiştir.
    

## ⚙️ 2. Temel Komut Satırı Seçenekleri (CLI Arguments)

`tcpdump` aracını hiçbir argüman vermeden çalıştırmak sadece kurulumu test etmeye yarar. Gerçek olay müdahalesi (_Incident Response_) ve log izleme senaryolarında aşağıdaki operasyonel parametrelerin kullanılması zorunludur:

- **`-i INTERFACE`:** Paketlerin hangi ağ kartından (arayüzünden) dinleneceğini belirler. Sistemdeki tüm aktif kartları dinlemek için `-i any`, belirli bir Ethernet kartı için `-i eth0` veya `-i ens5` yazılır.
    
- **`-w FILE.pcap`:** Yakalanan canlı ağ trafiğini ekrana basıp terminali şişirmek yerine, daha sonra Wireshark veya tshark gibi gelişmiş araçlarla derinlemesine analiz etmek üzere bir dosyaya ham olarak kaydeder.
    
- **`-r FILE.pcap`:** Daha önceden kaydedilmiş bir paket yakalama dosyasını (_PCAP_) analiz etmek amacıyla terminale okur ve çözümler.
    
- **`-c COUNT`:** Yakalanacak veya dosyadan okunacak maksimum paket sayısını sınırlar (Örn: `-c 5`). Sınır konmazsa kullanıcı `CTRL + C` ile kesene kadar akış devam eder.
    
- **`-n`:** **[DNS Çözümlemesini Kapatır].** IP adreslerinin alan adlarına (_hostname_) dönüştürülmesini engelleyerek gereksiz DNS gecikmelerini önler ve analiz hızını maksimuma çıkarır.
    
- **`-nn`:** **[Port Çözümlemesini Kapatır].** IP adreslerinin yanı sıra, port numaralarının da servislere dönüşmesini engeller (Örn: 80 portunun ekranda `http` olarak yazılmasını önler, direkt sayısal `80` olarak bırakır).
    
- **`-v / -vv / -vvv`:** Detay seviyesini (_Verbosity_) kademeli olarak artırır. Paketlerin TTL (Time to Live), IP ID, toplam uzunluk ve opsiyonel başlık parametrelerini ekrana basar.
    

## 🎨 3. Çıktı Özelleştirme ve Gösterim Modları (Display Options)

Trafikteki paketlerin terminal ekranında nasıl listeleneceğini belirleyen görsel bayraklar:

- **`-q` (Quick Output):** Zaman damgası, kaynak/hedef IP'leri, port numaraları ve protokol tipini içeren çok kısa, özet satırlar basarak gürültüyü azaltır.
    
- **`-e` (Link-Level Header):** OSI modelinde Katman 2 (_Data Link_) katmanını açar. Paket listesine cihazların fiziksel **MAC adreslerini** dahil eder. Özellikle ARP ve DHCP saldırı analizlerinde (Spoofing tespiti) hayati öneme sahiptir.
    
- **`-A` (ASCII Mode):** Paket içerisindeki verileri doğrudan İngilizce karakterler, sayılar ve semboller (_Plain-text_) olarak ekrana yansıtır. Web trafiği veya düz metin e-posta içeriklerini okumak için idealdir.
    
- **`-xx` (Hexadecimal Mode):** Paketin tüm içeriğini (IP ve TCP başlıkları dahil) ikişer haneli Hex formatında ekrana basar. Sıkıştırılmış verilerde tercih edilir.
    
- **`-X` (Hex & ASCII Combo):** En popüler gösterim modudur. Paketin hem Hexadecimal kodlarını hem de yan tarafta ASCII metin karşılığını aynı anda göstererek analistin iki taraflı doğrulamasını sağlar.
    

## 🎯 4. Temel ve Mantıksal Filtreleme Kuralları (Filtre Sözdizimi)

Milyonlarca paket arasındaki gürültüyü azaltmak için `tcpdump` üzerinde doğrudan mantıksal operatörler (`and, or, not`) kullanılarak güçlü filtre ifadeleri örülebilir:

### 🟢 Mantıksal Operatörlerin Kullanımı

- **`and`** ➡️ Her iki koşulun da doğru olmasını zorunlu kılar. (Örn: `tcpdump host 1.1.1.1 and tcp`).
    
- **`or`** ➡️ Koşullardan en az birinin doğru olmasını yeterli sayar. (Örn: `tcpdump udp or icmp`).
    
- **`not`** ➡️ Belirtilen koşulun dışındaki paketleri yakalar. (Örn: `tcpdump not tcp` ile tüm TCP dışı ağ trafiği filtrelenir).
    

### 🔵 Temel Filtre Kalıpları

- **Host Filtreleme:** `host IP` veya `host HOSTNAME`. Sadece belirli yöne göre filtrelemek için `src host IP` (kaynak) veya `dst host IP` (hedef) süzgeçleri koşturulur.
    
- **Port Filtreleme:** `port PORT_NUMBER`. Yöne göre `src port PORT_NUMBER` veya `dst port PORT_NUMBER` şeklinde özelleştirilebilir.
    
- **Protokol Filtreleme:** Doğrudan protokolün adı filtre alanına yazılır: `ip, ip6, udp, tcp, icmp, arp`.
    

## ⚙️ 5. Gelişmiş Filtreleme ve Başlık Bayt Analizi (Header Bytes)

`tcpdump`, paket başlıklarının (_header_) içindeki belirli bayt ve bit değerlerine doğrudan lojik müdahale etmeye izin verir. Sözdizimi standardı şu şekildedir: `proto[expr:size]`

- `proto`: Hedef alınan protokol (_arp, ether, icmp, ip, tcp, udp_).
    
- `expr`: İncelenecek baytın başlangıç ofset adresidir (0 değeri ilk baytı belirtir).
    
- `size`: İncelenecek bayt miktarıdır (İsteğe bağlıdır, varsayılan değer 1 bayttır).
    

### 📊 Matematiksel Bit İşlemleri (Binary Operations)

- **`&` (And / VE):** İki girdi biti de 1 ise sonuç 1 döner, aksi halde 0 döner. (Örn: `ether[0] & 1 != 0` ➡️ Multicast Ethernet adreslerini yakalamak için ilk bayta maske uygular).
    
- **`|` (Or / VEYA):** İki girdiden en az biri 1 ise sonuç 1 döner.
    
- **`!` (Not / DEĞİL):** Girişteki bit değerini tersine çevirir (1 ise 0, 0 ise 1 yapar).
    

### 🚩 TCP Bayraklarının (Flags) Doğrudan Filtrelenmesi

TCP bayrakları alanına erişmek için karmaşık ofset hesapları yapmak yerine `tcp[tcpflags]` ifadesi kullanılır. Kıyaslama için kullanılabilecek anahtar kelimeler: `tcp-syn, tcp-ack, tcp-fin, tcp-rst, tcp-push`.

- `tcp[tcpflags] == tcp-syn` ➡️ Sadece ve sadece SYN bayrağı açık (1), diğer tüm bayrakları kapalı olan paketleri yakalar.
    
- `tcp[tcpflags] & tcp-syn != 0` ➡️ Diğer bayrakların durumuna bakmaksızın, içerisinde **en azından** SYN bayrağı set edilmiş olan paketleri cımbızlar.
    

## 🕵️‍♂️ 6. Laboratuvar Operasyonları ve Adli Analiz Bulguları

İçerisinde siber trafik logları barındıran `traffic.pcap` dosyası üzerinde gerçekleştirilen adli ve operasyonel sorgu çıktıları:

### A) ICMP Protokol Paketlerinin Sayılması

Bash

```
tcpdump -r traffic.pcap icmp -n | wc -l
# Adli Sonuç: traffic.pcap içerisinde tam 26 adet ICMP paketi saptanmıştır.
```

### B) Ağda Kim Kimin MAC Adresini Arıyor? (ARP Analizi)

Bash

```
tcpdump -r traffic.pcap arp and host 192.168.124.137
# Çıktı: ARP, Request who-has ip-192.168-124-137... tell ip-192-168-124-148...
```

- **Adli Bulgusu:** `192.168.124.137` IP adresine ait donanımsal MAC adresini öğrenmek için ağa broadcast feryadı fırlatan kaynak hostun IP adresi **`192.168.124.148`** olarak tespit edilmiştir.
    

### C) İlk DNS Sorgusundaki Subdomain Bilgisinin Cımbızlanması

Bash

```
tcpdump -r traffic.pcap port 53 -A -c 1
# Çıktı: ... IP ip-192-168-124-137... > ip-192-168-124-1... 39913+ A? mirrors.rockylinux.org.
```

- **Adli Bulgusu:** Ağ trafiğinde gerçekleştirilen ilk DNS sorgusunda talep edilen hedef subdomain/hostname bilgisi **`mirrors.rockylinux.org`** olarak okunmuştur.
    

### D) Sadece TCP Reset (RST) Flag'i Aktif Paketlerin Sayılması

Bash

```
tcpdump -r traffic.pcap 'tcp[tcpflags] == tcp-rst' | wc -l
# Adli Sonuç: Diğer tüm bayrakları kapalı, sadece RST bayrağı açık tam 57 adet paket saptanmıştır.
```

### E) Veri Sızdırma Avı: Devasa Boyuttaki Paketlerin Tespiti

Bash

```
tcpdump -r traffic.pcap 'greater 15000' -n -c 1
# Çıktı: 07:18:24.967023 IP 185.117.80.53.80 > 192.168.124.137.60518: Flags [.], length 20820
```

- **Adli Bulgusu:** Ağda anormal boyutta (15000 byte üzeri) veri paketleri basarak veri sızdırma (_Data Exfiltration_) şüphesi uyandıran kaynak hostun harici IP adresi **`185.117.80.53`** olarak saptanmıştır.
    

### F) ARP İsteği Gönderen Cihazın Fiziksel MAC Adresi

Bash

```
tcpdump -r traffic.pcap arp -e -c 1
# Çıktı: 07:18:29.940761 52:54:00:7c:d3:5b > Broadcast, ethertype ARP (0x0806)...
```

- **Adli Bulgusu:** Ağda broadcast feryadı başlatarak ARP isteği gönderen şüpheli cihazın fiziksel kaynak MAC adresi **`52:54:00:7c:d3:5b`** olarak mühürlenmiştir.
