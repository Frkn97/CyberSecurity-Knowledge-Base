# 🦈 TryHackMe: Wireshark: The Basics (SOC Level 1)

## 🏗️ Mimari Yapı ve Paket Ayrıştırma (Dissection) Mekanizması

Wireshark; canlı ağ trafiğini dinleme (sniffing) ve kayıtlı paket yakalama (**PCAP / PCAPNG**) dosyalarını derinlemesine analiz etme kabiliyetine sahip açık kaynaklı bir paket analiz aracıdır.

  

Wireshark bir **Saldırı Tespit Sistemi (IDS)** veya **Saldırı Engelleme Sistemi (IPS)** değildir; paketleri modifiye etmez, sadece okur ve ayrıştırır (dissect eder). Bu nedenle bir anomali veya güvenlik ihlalinin tespiti tamamen analistin paket protokol bilgisine ve sorgulama yeteneğine bağlıdır.

  

```
                    [ Wireshark GUI Mimarisi ]
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
[ Packet List Pane ]    [ Packet Details Panel ]  [ Packet Bytes Pane ]
- Paket No & Zaman      - OSI Katman Ayrıştırması - Ham Hex Dökümü
- Kaynak / Hedef IP     - Frame (L1) -> Eth (L2)  - Decode Edilmiş ASCII Karşılığı
- Protokol & Özet Bilgi - IP (L3) -> TCP/UDP (L4) - Seçilen alanın anlık
                          - App (L5-L7: HTTP/SMB)   hex üzerinde vurgulanması
```

## 🧰 Wireshark Temel Arayüzü ve Menü Hiyerarşisi

|**Arayüz Bölümü / Menü**|**Konum / Kısayol**|**İşlev ve Analizdeki Görevi**|
|---|---|---|
|**Toolbar (Ana Araç Çubuğu)**|Üst Menü Çubuğu|Paket dinleme (Başlat: Mavi Köpekbalığı Yüzgeci, Durdur: Kırmızı Kare, Yeniden Başlat: Yeşil Ok), filtreleme, sıralama, dışa aktarma.|
|**Display Filter Bar**|Araç Çubuğunun Altı|Paketleri belirli sorgulara göre (protokol, IP, port, hata kodu) ekranda dinamik olarak filtreleme çubuğu.|
|**Capture Filter & Interfaces**|Başlangıç Ekranı|Canlı yakalama yapılacak arayüzün (`eth0`, `lo`, `ens33`) seçildiği ve yakalama filtresinin girildiği alan.|
|**Status Bar (Durum Çubuğu)**|En Alt Çubuk|Toplam paket sayısı, filtrelenen/görüntülenen paket sayısı (`Displayed`), kullanılan profil ve hata bildirimleri.|
|**Capture File Properties**|`Statistics -> Capture File Properties`|Dosya hash değeri (SHA256), yakalama süresi, paket sayısı, arayüz detayları ve analist yorumlarını gösterir.|
|**Expert Information**|`Analyze -> Expert Information` / Sol Alt İkon|Protokol durum anomalilerini (Sahte paket, TCP retransmission, Checksum hatası) önem derecesine göre listeler.|

## 🧩 1. OSI Katmanlarına Göre Paket Ayrıştırma (Packet Dissection)

Wireshark, seçilen her paketi OSI / TCP-IP modelinin katmanlarına göre 5 ila 7 alt seviyeye ayırarak detaylandırır.

  

```
┌────────────────────────────────────────────────────────────────────────┐
│ Layer 1: Frame (Fiziksel / Paket Genel Bilgisi: Varış Tarihi, Boyut)   │
├────────────────────────────────────────────────────────────────────────┤
│ Layer 2: Ethernet II (Veri Bağlantı: Kaynak / Hedef MAC Adresleri)     │
├────────────────────────────────────────────────────────────────────────┤
│ Layer 3: Internet Protocol (Ağ: Kaynak / Hedef IPv4-IPv6, TTL Değeri)  │
├────────────────────────────────────────────────────────────────────────┤
│ Layer 4: Transmission Control Protocol (İletim: Portlar, Seq/Ack, Payload Boyutu) │
├────────────────────────────────────────────────────────────────────────┤
│ Layer 4 Continuation: Protocol Errors / Reassembled TCP Segments       │
├────────────────────────────────────────────────────────────────────────┤
│ Layer 5-7: Application Protocol (Uygulama: HTTP, DNS, SMB, XML Başlıkları)│
├────────────────────────────────────────────────────────────────────────┤
│ Layer Extension: Application Data / Decoded Payload                    │
└────────────────────────────────────────────────────────────────────────┘
```

> [!TIP]
> 
> **Paket Detayı ve Hex Eşleşmesi:**
> 
> Packet Details panelinde tıklanan herhangi bir protokol alanı (Örn: `TTL` veya `User-Agent`), alttaki Packet Bytes panelinde ilgili **Hex ve ASCII** baytlarını otomatik olarak sarı/mavi renkle vurgular.
> 
>   

## 🎯 2. Paket Gezinme, Arama ve Dışa Aktarma Mekanizmaları

### A. Paket Arama Türleri ve Alanları (`Ctrl + F`)

`Edit -> Find Packet` menüsü üzerinden dört farklı girdi türüyle arama yapılabilir:

  

|**Girdi Türü**|**Kullanım Senaryosu**|**Örnek**|
|---|---|---|
|**Display Filter**|Protokol sözdizimi ile arama|`http.response.code == 200`|
|**Hex Value**|Bayt dizilimi arama|`00:11:22:33:44:55`|
|**String**|Düz metin veya anahtar kelime arama|`r4w`, `password`, `artist`|
|**Regex**|Düzenli ifade kalıpları arama|`^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$`|

> [!WARNING]
> 
> **Arama Alanı Uyuşmazlığı Tuzağı:**
> 
> Arama yaparken aranacak alan doğru seçilmelidir (`Packet List`, `Packet Details` veya `Packet Bytes`). Örneğin, HTTP gövdesindeki bir metin aranırken arama alanı `Packet List` olarak bırakılırsa Wireshark ilgili paketi bulamaz.
> 
>   

### B. Nesne Dışa Aktarma (Export Objects)

Ağ üzerinden aktarılan ham dosyaları (dokümanlar, resimler, çalıştırılabilir dosyalar, betikler) doğrudan disk ortamına kaydetmek için kullanılır:

  

- **Desteklenen Protokoller:** `DICOM`, `HTTP`, `IMF` (E-posta), `SMB`, `TFTP`.
    
      
    
- **Menü Yolu:** `File -> Export Objects -> HTTP`
    
      
    

### C. Zaman Gösterim Formatı (Time Display Format)

Wireshark varsayılan olarak paketleri yakalamanın başlangıcından itibaren geçen saniye cinsinden (`Seconds Since Beginning of Capture`) gösterir. SOC analizlerinde log korelasyonu yapabilmek için **UTC Tarih/Saat** görünümüne geçilmelidir:

  

- **Menü Yolu:** `View -> Time Display Format -> UTC Date and Time of Day`
    
      
    

## 🚦 3. Expert Information (Uzman Bilgilendirme Sistemi)

Wireshark protokol anomalilerini, hataları ve dikkat çekici durumları otomatik sınıflandırır:

  

|**Şiddet Derecesi (Severity)**|**Renk**|**Anlamı ve Tanımı**|**Örnek Olay**|
|---|---|---|---|
|**Chat**|Mavi|Standart iş akışı ve genel bilgi.|TCP bağlantı kurulumu / kapanışı.|
|**Note**|Camgöbeği (Cyan)|Dikkate değer protokol durumları.|Uygulama hata kodları (HTTP 404 vb.).|
|**Warn (Warning)**|Sarı|Olağandışı hata kodları veya potansiyel sorunlar.|TCP Retransmission, Paket Kayıpları, ACK Anomalileri.|
|**Error**|Kırmızı|Protokol bozulmaları ve kritik hatalar.|Malformed Packet (Bozuk paket), Checksum Error.|

## 🔍 4. Görüntüleme Filtreleri (Display Filters) ve Akış Takibi

> [!NOTE]
> 
> **Altın Analist Kuralı:**
> 
> _"If you can click on it, you can filter and copy it."_ (Ekranda tıklayabildiğin her alana sağ tıklayarak filtre oluşturabilir veya değerini kopyalayabilirsin).
> 
>   

### A. Temel Filtreleme Sözdizimleri

- **Protokol Adına Göre:** `http`, `dns`, `arp`, `dhcp`, `smtp`, `icmp`, `smb`
    
      
    
- **Port Numarasına Göre:** `tcp.port == 80`, `udp.port == 53`
    
      
    
- **IP Adresine Göre:** `ip.addr == 192.168.1.2`, `ip.src == 10.0.0.1`, `ip.dst == 172.16.0.5`
    
      
    

### B. Akış Takibi (Follow Stream)

Parçalanmış TCP/UDP paketlerini uygulama katmanında birleştirerek istemci ve sunucu arasındaki ham sohbeti metin olarak görüntüler:

  

- **Kırmızı Metin:** İstemciden sunucuya giden istekler (Client $\rightarrow$ Server).
    
      
    
- **Mavi Metin:** Sunucudan istemciye dönen yanıtlar (Server $\rightarrow$ Client).
    
      
    
- **Menü Yolu:** `Sağ Tık -> Follow -> TCP / HTTP / UDP Stream`
    
      
    

## 💻 5. Canlı Terminal ve Adli Analiz Komutları

Linux ortamında paket dökümünden çıkarılan baytların veya dosyaların bütünlük/hash doğrulamasını yapmak için kullanılan komut:

  

Bash

```
# Çıkarılan dosyanın MD5 hash değerini hesaplama
md5sum extracted_file.bin

# Örnek Çıktı:
# 911cd574a42865a956ccde2d04495ebf  extracted_file.bin
```

- `md5sum`: Dosyaların 128-bitlik MD5 kriptografik özetini üretir.
