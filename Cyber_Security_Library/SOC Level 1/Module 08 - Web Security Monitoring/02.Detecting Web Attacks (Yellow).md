# 🌐 Detecting Web Attacks —  Web Olay Müdahale Notu

**Etiketler:** `#SOC` `#WebAttacks` `#AccessLogs` `#Wireshark` `#WAF` `#SQLi` `#BruteForce` `#DirectoryFuzzing` `#CyberChef` `#TryHackMe`

## 🏛️ 1. Mimari Yapı ve Tespit Katmanları (Detection Architecture)

Web uygulamaları internete doğrudan açık oldukları ve arka planda hassas veri depolarıyla (SQL, NoSQL, dosya sistemleri) konuştukları için saldırganların birincil hedefidir. Bir saldırıyı tespit etmek, **istemci tarafı (client-side)** ile **sunucu tarafı (server-side)** arasındaki farkı ve analistin elindeki iki temel telemetri kaynağını (**Erişim Logları** vs. **Ağ Paketleri**) anlamaktan geçer.

  

```
                                [ 🌐 INTERNET (Saldırgan / İstemci) ]
                                                  │
                                                  ▼
                                    [ 🛡️ WAF (Web App Firewall) ]
                                    (İstek Filtreleme & TLS İnceleme)
                                                  │
                                                  ▼
┌──────────────────────────────────────────────────────────────────────────────────────────────┐
│ 🖥️ WEB SUNUCUSU (Nginx / Apache / IIS)                                                       │
│                                                                                              │
│   [ 📜 Erişim Logları (Access Logs) ]                 [ 📦 Ağ Trafiği (PCAP / Wireshark) ]   │
│   • Kaynak IP, Zaman, Metot, URI                      • Tüm HTTP Başlıkları (Headers)        │
│   • HTTP Yanıt Kodu (200, 302, 404)                   • POST İstek Gövdeleri (Body Data)     │
│   • User-Agent (Araç Tespiti: FFUF, sqlmap)            • İletilen Parolalar, Dosyalar, Çerezler│
│   ⚠️ Kısıt: POST gövdesini (parola/veri) kaydetmez!   ⚠️ Kısıt: Şifreli (HTTPS) ise anahtar ister│
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 🔹 İstemci Tarafı (Client-Side) vs. Sunucu Tarafı (Server-Side) Saldırılar

|**Kriter**|**💻 İstemci Tarafı (Client-Side)**|**🖥️ Sunucu Tarafı (Server-Side)**|
|---|---|---|
|**Hedef**|Kullanıcının tarayıcısı, yerel cihazı ve oturum çerezleri.|Web sunucusu, uygulama kodu ve arka plan veritabanı.|
|**Örnek Saldırılar**|**XSS (En yaygın)**, CSRF, Clickjacking.|**SQL Injection (SQLi)**, Brute-Force, Command Injection, File Inclusion (LFI/RFI).|
|**İz Bırakma Durumu**|Sunucuya istek düşmeyebilir (DOM-based XSS vb.); sunucu loglarında görünmez.|Sunucu erişim loglarında, hata loglarında ve ağ trafiğinde somut iz bırakır.|
|**SOC / Analist Görünürlüğü**|**Çok Kısıtlı / İmkansız:** Uç nokta EDR veya tarayıcı içi ajan olmadan SOC göremez.|**Yüksek:** Web logları, WAF alarmları ve SIEM korelasyonuyla tespit edilebilir.|

> [!WARNING]
> 
> **SOC Analistinin Sınırı (Client-Side Kör Noktası):** İstemci tarafı saldırılar kurbanın yerel tarayıcısında icra edilir. Örneğin gizli bir iframe (Clickjacking) veya yerel DOM manipülasyonu sunucuya anormal bir HTTP isteği üretmeyebilir. Bu nedenle geleneksel sunucu logları üzerinden client-side saldırıları doğrudan yakalamak çoğunlukla mümkün değildir.
> 
>   

## 📜 2. Web Sunucu Erişim Loglarının Anatomisi ve Kısıtları (Access Logs)

Erişim logları (Apache/Nginx access log), sunucuya gelen her HTTP isteğini satır satır belgeler.

  

Plaintext

```
10.10.10.100 [12/Aug/2026:14:32:10] "POST /login.php HTTP/1.1" 302 532 "/home.html" "Mozilla/5.0"
└──────┬───┘  └──────────┬────────┘  └───┬──┘ └────┬────┘ └──┬──┘ └──┬──┘ └───┬──────┘ └────┬────┘
    Kaynak IP          Zaman Damgası   Metot     İstenen   Durum   Boyut   Referrer   User-Agent
                                                   Sayfa   Kodu    (Byte)
```

### 🔹 Log Alanları ve Güvenlik Göstergeleri (IoA)

|**Log Alanı (Field)**|**Anomali / Saldırı Belirteci**|**Analist Ne Aramalı?**|
|---|---|---|
|**1. Client IP Address**|Coğrafi alan dışı (Geo-IP) veya bilinen tehdit istihbaratı (Tor, Proxy, Botnet) IP'leri.|Tek bir IP'den aşırı yoğun trafik akışı.|
|**2. Timestamp & Page**|Anormal mesai dışı saatler veya kısa sürede yüzlerce istek.|Dizin tarama (Directory Fuzzing / Brute-Force).|
|**3. Status Code**|Peş peşe `404 Not Found` (dizin tarama), peş peşe başarısız login ardından gelen `302 Found` (başarılı giriş).|Giriş yönlendirmeleri (`302`) ve yetki hataları (`401/403`).|
|**4. Response Size**|Normal sayfa boyutundan belirgin şekilde büyük/küçük dönen bayt miktarı.|SQLi ile veritabanı dökülmesi (büyük boyut) veya hata mesajı dönüşü.|
|**5. Referrer**|Sitedeki normal gezinti akışına uymayan dış veya anlamsız yönlendiriciler.|CSRF veya dış saldırı kökenli yönlendirmeler.|
|**6. User-Agent**|Otomatik saldırı ve tarama araçlarının varsayılan başlıkları.|`sqlmap`, `wpscan`, `nikto`, `gobuster`, `FFUF v2.1.0`.|

> [!NOTE]
> 
> **Erişim Loglarının En Büyük Kısıtı (POST Body Eksikliği):** Geleneksel erişim logları `POST` isteğinin gövdesini (**POST Body / Payload**) kaydetmez. Logda yalnızca `POST /login.php HTTP/1.1 302` görürsün; ancak saldırganın hangi parolayı veya hangi SQLi parametresini girdiğini logdan **okuyamazsın**. Bunun için **Ağ Trafiği Analizi (PCAP / Wireshark)** veya **WAF logları** şarttır.
> 
>   

## 🔍 3. TryBankMe İhlal Soruşturması: 3 Aşamalı Saldırı Zinciri

TryBankMe bankacılık platformunun sızdırılan verilerini aydınlatmak için yürütülen soruşturmada saldırganın işletttiği zincir:

  

```
[ AŞAMA 1: Keşif / Dizin Tarama ]
 Saldırgan (FFUF v2.1.0) ──── Peş peşe HTTP GET ────► 404'ler arasında /login.php (200 OK) bulundu.
                                      │
                                      ▼
[ AŞAMA 2: Parola Kaba Kuvveti ]
 Saldırgan ──── Peş peşe POST /login.php (200) ────► Son istek: 302 Found (Yönlendirme / Başarılı Giriş!)
                                      │
                                      ▼
[ AŞAMA 3: SQL Injection & DB Dump ]
 Saldırgan (sqlmap) ──── /changeusername.php?username=... ────► Veritabanı döküldü (THM Bayrağı çalındı).
```

### 🔹 Adım 1: Erişim Logu Analizi (`access.log`)

Masaüstündeki `access.log` dosyasını terminal veya metin editörüyle incelerken izlenen adımlar:

  

1. **Dizin Tarama Aracının Tespiti:**
    
    Loglarda kısa sürede binlerce bilinmeyen sayfaya istek atan IP incelendiğinde `User-Agent` başlığında **`FFUF v2.1.0`** aracının kullanıldığı görülür.
    
      
    
2. **Kaba Kuvvet (Brute-Force) Hedefinin Belirlenmesi:**
    
    Saldırganın `POST` metoduyla art arda istek gönderdiği sayfa **`/login.php`** formudur.
    
      
    
3. **Başarılı Girişin Tespiti (`302 Found`):**
    
    Başarısız login denemeleri sunucu tarafından `200 OK` (tekrar aynı form sayfası) olarak dönerken, son istekte durum kodu **`302 Found`** olmuş ve kullanıcı `/account` sayfasına yönlendirilmiştir.
    
      
    
4. **SQLi Payload Analizi & URL Decoding:**
    
    Log dosyasında `/changeusername.php` sayfasına gönderilen URL parametresi incelendiğinde:
    
      
    - _Ham (URL Encoded) Payload:_ `%25%27%20OR%20%271%27%3D%271`
        
          
        
    - _CyberChef veya Terminal ile URL Decode İşlemi:_
        
        `%25` $\rightarrow$ `%`
        
          
        
        `%27` $\rightarrow$ `'`
        
          
        
        `%20` $\rightarrow$ `[Boşluk]`
        
          
        
        `%3D` $\rightarrow$ `=`
        
          
        
    - _Çözülmüş (Decoded) SQLi Payload:_ **`%' OR '1'='1`**
        
          
        

### 🔹 Adım 2: Ağ Paketi Analizi (`traffic.pcap` / Wireshark)

Logların yetersiz kaldığı (POST içeriğini ve çalınan veriyi göstermediği) noktada `traffic.pcap` dosyası Wireshark ile açılır.

  

#### Kullanılan Wireshark Filtreleri ve Parametreleri:

Kod snippet'i

```
# 1. Sadece HTTP protokolüne ait trafiği filtreleme
http

# 2. Belirli bir hedef sunucu ve User-Agent filtresi kurma
ip.dst == 10.10.20.200 && http.user_agent

# 3. Başarılı HTTP yönlendirme (302) yanıtlarını filtreleme
http.response.code == 302

# 4. Otomatik SQL injection aracı (sqlmap) ile yapılan istekleri yakalama
http.user_agent contains "sqlmap"
```

#### Adli Bulgular (Follow HTTP Stream):

- **Ele Geçirilen Parola:** `http.response.code == 302` veren istek öncesindeki `POST /login.php` paketine sağ tıklayıp **Follow $\rightarrow$ HTTP Stream** yapıldığında, form gövdesinde gönderilen gerçek parolanın **`astrongpassword123`** olduğu açık metin olarak görülür.
    
      
    
- **Veritabanından Çalınan Bayrak (DB Dump):** `sqlmap` isteklerinin döndürdüğü HTTP yanıtları incelendiğinde, veritabanından çekilen tablo verilerinin içinde gizli bayrak yakalanır: **`THM{dumped_the_db}`**.
    
      
    

## 🛡️ 4. Web Application Firewall (WAF) Mimarisi ve Kural Tasarımı

WAF, HTTP/HTTPS isteklerini sunucuya ulaşmadan önce paket seviyesinde denetleyen, gerekirse TLS şifresini çözüp analiz eden 7. katman güvenlik duvarıdır.

  

```
[ İstemci İsteği ] ──► [ WAF Kural Motoru ] ──┬──► (İhlal Var)  ──► 🚫 BLOCK / DROP
                                              ├──► (Şüpheli Bot)──► 🧩 CAPTCHA Challenge
                                              └──► (Temiz İstek)──► ✅ Sunucuya İlet
```

### 🔹 WAF Kural Kategorileri

|**Kural Tipi**|**Açıklama**|**Kullanım Senaryosu / Örnek**|
|---|---|---|
|**Block Common Attack Patterns**|Bilinen zararlı payload ve araç göstergelerini engeller.|`sqlmap`, `nikto` gibi otomatik araçların User-Agent dizilimlerini engelleme.|
|**Deny Known Malicious Sources**|IP itibarı, tehdit istihbaratı ve Geo-IP filtreleriyle zararlı IP'leri durdurur.|Bilinen botnet, Tor çıkış noktaları ve saldırgan ASN bloklarını engelleme.|
|**Custom-Built Rules**|Uygulamanın özel mantığına göre yazılmış kurallar.|`/admin` veya `/login` yoluna sadece belirli HTTP metotlarına (GET/POST) izin verme.|
|**Rate-Limiting & Abuse Prevention**|İstek frekansını sınırlandırarak DoS ve Brute-Force'u önler.|Tek bir IP'den dakikada 5'ten fazla login denemesini bloklama.|

> [!TIP]
> 
> **Challenge-Response (CAPTCHA) Mekanizması:** Küresel web trafiğinin yaklaşık %37'si zararlı botlardan oluşur. WAF'lar şüpheli ama meşru olma ihtimali bulunan istekleri doğrudan bloklamak yerine **CAPTCHA doğrulaması** ile sınar; böylece yanlış pozitiflerin (False Positive) müşteri kaybına yol açması engellenir.
> 
>   

### 🔹 Özel WAF Kuralı Sözdizimi Örneği

Saldırganların geliştirdiği özel bir bot aracını (`BotTHM`) sınırda durdurmak için yazılan kural:

  

Plaintext

```
IF User-Agent CONTAINS "BotTHM" THEN block
```

## 🚦 6. Tekrar Kategorisi & 3 Dakikalık Pazar Tekrar Stratejisi

### 🟡 Sarı Sınıf: Kavramsal / Log Belirteçleri & Mülakat Refleksi

Bu modül **Sarı Sınıf** (Kavramsal / Hızlı Soru-Cevap & Log Ayrımı) kategorisindedir.

  

### ⏱️ Pazar Günü 3 Dakikalık Hızlı Tekrar Rutini

1. **Erişim Logu vs. PCAP Kısıtını Hatırla (1. Dakika):**
    
      
    - _Access Log:_ Hangi IP, ne zaman, hangi sayfayı istedi, hangi durum kodu döndü (`200`, `302`, `404`)? $\rightarrow$ **POST gövdesini (parola/veri) KAYDETMEZ.**
        
          
        
    - _PCAP / Wireshark:_ İstek ve yanıtın içindeki tüm açık metin veriler (POST body, şifre, dönen veritabanı satırları) incelenebilir.
        
          
        
2. **Saldırı İmzalarını Durum Kodlarıyla Eşleştir (2. Dakika):**
    
      
    - Peş peşe `404 Not Found` + Tanınan User-Agent (`FFUF`, `Gobuster`) $\rightarrow$ **Directory Fuzzing / Enumeration**.
        
          
        
    - Peş peşe `POST` + aynı sayfada `200` ardından tek bir `302 Found` $\rightarrow$ **Başarılı Brute-Force Girişi**.
        
          
        
    - URL parametresinde `' OR 1=1` veya URL encoded `%27` dizilimi $\rightarrow$ **SQL Injection**.
        
          
        
3. **Mülakat Cümlesi (3. Dakika):**
    
    _"Bir web sunucu saldırısını incelerken erişim logları bana saldırganın adımlarını (dizin taraması, brute-force ve SQLi girişimleri) gösterir. Ancak saldırganın hangi parolayı bulduğunu veya veritabanından hangi veriyi çaldığını kesinleştirmek için ağ paketlerindeki HTTP stream içeriğini takip ederim."_
