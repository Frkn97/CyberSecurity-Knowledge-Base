**Etiketler:** `#SOC` `#DDoS` `#DoS` `#Splunk` `#SPL` `#AccessLogs` `#WAF` `#CDN` `#RateLimiting` `#Layer7` `#TryHackMe`

  

## 🏛️ 1. Mimari Yapı ve Saldırı Mekaniği (OSI Layer 7 DDoS Architecture)

Hizmet Engelleme (**Denial-of-Service - DoS**) ve Dağıtık Hizmet Engelleme (**Distributed Denial-of-Service - DDoS**) saldırılarının temel amacı sistemin **Erişilebilirliğini (Availability - CIA Üçgeni)** tamamen çökertmektir.

  

Bu odada incelenen saldırılar, alt ağ katmanlarından (SYN Flood, UDP Amplification - Layer 3/4) ziyade doğrudan web sunucusunun ve veritabanının işlem gücünü tüketen **Uygulama Katmanı (OSI Layer 7)** saldırılarıdır.

  

```
[ GELENEKSEL DoS ]
  Tek Saldırgan (1 IP) ───────── Ağır Sorgu / HTTP Flood ─────────► [ Web Sunucusu ] (Kapasite Sınırı)

[ DAĞITIK DDoS (Botnet Mimarisi) ]
  Saldırgan (C2)
     │
     ├──► Zombi Cihaz 1 (PC)      ┐
     ├──► Zombi Cihaz 2 (IoT/Kamera)├─► [ 🌐 CDN Edge ] ──(Bypass)──► [ 🖥️ Menşe Sunucu (Origin) ]
     └──► Zombi Cihaz 60 (Server) ┘     (Cloudflare)                (CPU/RAM Tükendi -> 503 Hatası)
```

### 🔹 Layer 7 DoS/DDoS Saldırı Türleri

|**Saldırı Türü**|**Çalışma Mekanizması**|**Tüketilen Kaynak & Hedef**|
|---|---|---|
|**Slowloris**|Tamamlanmamış HTTP başlıklarını (partial headers) çok yavaş aralıklarla gönderir; bağlantıyı açık tutar.|Web sunucusunun eşzamanlı bağlantı havuzunu (connection pool) tüketir.|
|**HTTP Flood**|Çok sayıda geçerli `GET` veya `POST` isteğini hedefe arka arkaya yığar.|Ağ bant genişliğini, web sunucu thread'lerini ve CPU'yu tüketir.|
|**Cache Bypass**|Önbelleğe alınmış URL'lerin sonuna rastgele parametreler ekler (`/products?a=abcd`).|CDN Edge katmanını atlayıp doğrudan menşe sunucuyu (Origin) cevaba zorlar.|
|**Oversized Query**|Sunucuyu devasa veri dizilerini işlemeye zorlayan sorgular atar (`?limit=999999`).|Veritabanı (SQL) motorunu ve sunucu RAM belleğini kilitler.|
|**Login / Form Abuse**|Kimlik doğrulama veya şifre sıfırlama formlarını döngüye sokar.|Parola hashleme (bcrypt/argon2 CPU yükü) ve DB yazma işlemlerini boğar.|
|**Faulty Input Validation**|Hatalı girdi denetimlerini suistimal ederek uygulamanın çökmesini sağlar.|Uygulama iş mantığını (Business Logic) ve servis sürecini (crash) durdurur.|

> [!NOTE]
> 
> **DoS vs. DDoS Ayrımı:** DoS tek bir makine ve tek bir internet bağlantısı ile yapılır; saldırganın işlemci, bellek ve hat kapasitesiyle sınırlıdır. DDoS ise zararlı yazılım bulaştırılmış binlerce cihazdan oluşan bir **Botnet (Zombi Ağı)** ordusu kullanılarak dağıtık şekilde icra edilir; tekil IP engellemesini zorlaştırır.
> 
>   

## 🎯 2. Tehdit Aktörü Motivasyonları ve Gerçek Dünya Vakaları

Saldırganlar web servislerini devre dışı bırakırken farklı motivasyonlarla hareket ederler:

  

|**Tehdit Motivasyonu**|**Açıklama**|**Sektörel / Gerçek Senaryo**|
|---|---|---|
|**Financial Loss (Maddi Kayıp)**|Satışları ve geliri kesintiye uğratmak.|Kara Cuma (Black Friday) günü bir e-ticaret devini çökertmek.|
|**Extortion (Fidye / Şantaj)**|Saldırıyı durdurmak veya başlatmamak için fidye talep etmek.|Borsa veya finans platformunu fidye ödemezse saldırmakla tehdit etmek.|
|**Hacktivism (Haktivizm)**|Sosyal veya politik bir protesto amacıyla kamuoyuna ses duyurmak.|Seçim dönemlerinde hükümet ve bakanlık sitelerini erişilmez kılmak.|
|**Distraction (Dikkat Dağıtma)**|Savunma ekibini meşgul ederken arka planda veri sızdırmak.|Ağ güvenliğini DDoS ile kilitlerken asıl hedef olan veritabanını soymak.|
|**Competition (Haksız Rekabet)**|Rakip firmanın operasyonel maliyetini artırmak veya pazar payı çalmak.|Rakip şirketin yeni ürün lansmanı sırasında altyapısını çökertmek.|
|**Denial of Wallet (Maddi Tüketim)**|Kurbanın kullandığı bulut kaynaklarının faturasını şişirmek.|AWS S3 veya API isteklerini döngüye sokarak kurbana astronomik fatura çıkarmak.|
|**Reputational Damage (İtibar Kaybı)**|Şirketin güvenilirliğini ve marka değerini müşteriler gözünde sıfırlamak.|Büyük bir online oyunun çıkış gününde sunucuları kilitlemek.|

### 📜 Tarihsel DDoS Vakaları

- **BBC Saldırısı (2015):** Yılbaşı gecesi _New World Hacking_ grubu yeteneklerini test etmek amacıyla BBC web sitesini saatlerce erişilmez hale getirdi.
    
      
    
- **Microsoft Azure / Outlook Saldırısı (2023):** _Anonymous Sudan_ isimli haktivist grup HTTP Flood ve Slowloris kullanarak Microsoft'un Layer 7 altyapısını kilitledi; dünya genelinde OneDrive ve Outlook kesintileri yaşandı.
    
      
    

## 🔍 3. Web Erişim Loglarında DoS/DDoS Belirteçleri (IoA)

Web sunucusu erişim loglarında (`access.log`) bir hizmet engelleme saldırısı şu semptomlarla kendini belli eder:

  

Plaintext

```
[ NORMAL KULLANICI ]
10.10.0.15 - - [12/Sep/2026:10:01:02] "GET /index.php HTTP/1.1" 200 4521 "-" "Mozilla/5.0..."
10.10.0.18 - - [12/Sep/2026:10:01:05] "GET /contact.php HTTP/1.1" 200 1200 "-" "Mozilla/5.0..."

[ SALDIRI ANISI (DoS Burst) ]
203.12.23.195 - - [12/Sep/2026:10:01:10] "GET /login HTTP/1.1" 200 890 "-" "curl/7.68.0"
203.12.23.195 - - [12/Sep/2026:10:01:10] "GET /login HTTP/1.1" 200 890 "-" "curl/7.68.0"
... (Saniyede Yüzlerce İstek) ...

[ SUNUCU TÜKENMESİ (Post-Attack Crash) ]
10.10.0.27 - - [12/Sep/2026:10:01:25] "GET /index.php HTTP/1.1" 503 9 "-" "Mozilla/5.0..."
```

### 🔹 Analistin İzleme Listesi (Watchlist)

1. **High Request Rate (Aşırı İstek Oranı):** Tek bir IP veya dar bir IP grubunun `/login` gibi ağır servislere saniyeler içinde binlerce istek göndermesi.
    
      
    
2. **Odd User-Agents (Anormal İstemci Başlıkları):** `curl/7.x`, `Python-urllib`, `Java/1.8.0_181` veya `libwww-perl` gibi kütüphane başlıkları.
    
      
    
3. **Burst Timestamps (Zaman Patlamaları):** Aynı saniye içerisinde onlarca veya yüzlerce isteğin sıkışması.
    
      
    
4. **Server Errors (`503 Service Unavailable`):** Sunucu kaynakları tükendiğinde (Thread exhaustion) dönen HTTP 5xx hataları.
    
      
    
5. **Logic Abuse (İş Mantığı İstismarı):** URL parametrelerinde mantıksız filtrelemeler (`?limit=999999`).
    
      
    

## 🛠️ 4. Splunk ile DDoS Tehdit Avcılığı (Hands-On Lab)

Bu laboratuvarda `http://MACHINE_IP:8000` adresinde yer alan Splunk arayüzünde `index="main"` altındaki erişim kayıtları incelenmiştir.

  

```
[ ADLİ SIEM SORUŞTURMA ADIMLARI ]
1. En Çok Hedeflenen URI ──► top uri_path (/search %81.8)
2. En Çok İstek Atan Saldırgan IP ──► uri_path="/search" | top clientip (203.0.113.7)
3. Botnet Ordusunun Boyutu ──► clientip="203.0.113.*" | dc(clientip) (60 IP)
4. Botnet User-Agent İmzası ──► top useragent (Java/1.8.0_181)
5. Saldırının Zirve Hızı (Peak) ──► timechart span=1s count (207 req/sec)
6. İlk Etkilenen Masum Kullanıcı ──► status=503 clientip="10.*" (10.10.0.27)
```

### 🔹 Çalıştırılan SPL (Splunk Processing Language) Komutları

#### 1. En Çok Hedeflenen URI ve Saldırgan IP Tespiti

Kod snippet'i

```
index="main"
| top uri_path
```

- **Bulgu:** Trafiğin %81.8'i `/search` adresine akmıştır.
    
      
    

Kod snippet'i

```
index="main" uri_path="/search"
| top clientip
```

- **Bulgu:** `/search` adresine en çok istek gönderen lider bot IP'si: **`203.0.113.7`**.
    
      
    

#### 2. Botnet Ağının Boyutunu ve En Yaygın User-Agent'ı Bulma

Saldırgan IP'lerinin `203.0.113.0/24` bloğunda toplandığı görülür:

  

Kod snippet'i

```
index="main" clientip="203.0.113.*"
| stats dc(clientip) as BotCount
```

- **Bulgu:** Saldırıya katılan benzersiz IP (botnet) sayısı: **`60`**.
    
      
    

Kod snippet'i

```
index="main" clientip="203.0.113.*"
| top useragent
```

- **Bulgu:** Botnet trafiğinde en çok kullanılan User-Agent: **`Java/1.8.0_181`**.
    
      
    

#### 3. Saldırının Zirve Noktasını (Peak Rate) Görselleştirme

Saniyedeki istek sayısını grafiklemek için zaman tablosu çıkarılır:

  

Kod snippet'i

```
index="main" uri_path="/search"
| timechart span=1s count by uri_path
```

- `timechart`: Zaman serisi grafiği oluşturur.
    
      
    
- `span=1s`: Olayları 1 saniyelik bloklar halinde sayar.
    
      
    
- **Bulgu:** Saldırının tepe noktasında saniyede tam **`207`** istek üretilmiştir.
    
      
    

#### 4. Hizmet Kesintisinden Etkilenen İlk Meşru Kullanıcıyı Yakalama

Saldırı sonrası sunucu çöktüğünde `503 Service Unavailable` hatası alan yerel (`10.10.0.0/24`) meşru istemci:

  

Kod snippet'i

```
index="main" status=503 clientip="10.*"
| table _time, clientip, status, uri_path
| sort _time asc
```

- **Bulgu:** Saat olarak ilk 503 hatasına çarpan masum iç istemci: **`10.10.0.27`**.
    
      
    

## 🛡️ 5. DDoS Savunma, Önleme ve Hafifletme (Mitigation) Mimarisi

DDoS savunması çok katmanlı (**Defense-in-Depth**) bir mimari gerektirir:

  

```
[ GELEN TRAFİK ] ──► [ 🌐 CDN (Edge Önbellek & Load-Balancing) ]
                               │
                               ▼
                     [ 🛡️ WAF (Kural Motoru & CAPTCHA) ]
                               │
                               ▼ (Filtrelenmiş Trafik)
                     [ 🖥️ GÜVENLİ KODLANMIŞ SUNUCU ]
```

### 🔹 Katman Bazlı Savunma Araçları

1. **Uygulama Seviyesi Savunma:**
    
      
    - **Girdi Sınırlandırması (Input Validation):** Arama kutularına maksimum karakter limiti (örneğin en fazla 50 karakter) koyarak aşırı büyük sorguları engellemek.
        
          
        
    - **Zorluk Sınamaları (Challenges):**
        
          
        - **CAPTCHA:** Kullanıcıya bulmaca/görsel çözdürerek botları durdurur.
            
              
            
        - **JavaScript Challenges:** Tarayıcı arkasında sessizce çalışan kodlarla ziyaretçinin gerçek bir tarayıcı olup olmadığını test eder; bot araçlarını engeller.
            
              
            
2. **CDN ve Altyapı Seviyesi Savunma:**
    
      
    - **Anycast & Edge Caching:** Trafiği dünya genelindeki binlerce edge sunucusunda önbellekten sunarak ana menşe sunucuya (Origin) yük binmesini önler.
        
          
        
    - **Load-Balancing (Yük Dengeleme):** Gelen istekleri sunucu çiftliklerine dengeli dağıtarak hiçbir sunucunun tek başına kilitlenmesine izin vermez.
        
          
        
3. **WAF ve Hız Sınırlandırması (Rate Limiting):**
    
      
    - IP başına belirli bir uç noktaya (örneğin `/login`) dakikada maksimum istek limiti getirmek (Örn: Dakikada en fazla 5 login isteği). Sınırı aşan IP'ye geçici blok veya CAPTCHA dayatmak.
        
          
        

> [!WARNING]
> 
> **Cache Bypass Açığına Dikkat:** Saldırganlar CDN önbelleğini delmek için URL sonuna dinamik ve rastgele parametreler (`/products?nocache=128736`) ekleyerek doğrudan arka plandaki Origin sunucuyu vurabilirler. CDN yapılandırmasında query-string önbellekleme kuralları sıkılaştırılmalıdır.
> 
>

## 🚦 7. Tekrar Kategorisi & 3 Dakikalık Pazar Tekrar Stratejisi

### 🟡 Sarı Sınıf: Kavramsal / Splunk Metrikleri & DDoS Savunma Prensipleri

Bu modül **Sarı Sınıf** (Kavramsal / Splunk SPL Analitiği & Katmanlı DDoS Savunması) kategorisindedir.

  

### ⏱️ Pazar Günü 3 Dakikalık Hızlı Tekrar Rutini

1. **Layer 7 DDoS İmzalarını Hatırla (1. Dakika):**
    
      
    - Saniyede yüzlerce istek (Burst rate) + Anormal User-Agent (`Java/x`, `curl`) + Belirli bir dinamik sayfa (`/login`, `/search`) = **Layer 7 HTTP Flood**.
        
          
        
    - Normal kullanıcılara dönen `503 Service Unavailable` = **Sunucu Kaynak Tükenmesi**.
        
          
        
2. **Splunk Tehdit Avcılığı SPL Kalıpları (2. Dakika):**
    
      
    - _Tepe Noktası / Hız Tespiti:_ `index="main" | timechart span=1s count by uri_path`
        
          
        
    - _Botnet Boyutu Hesaplama:_ `index="main" clientip="203.0.113.*" | stats dc(clientip)`
        
          
        
3. **Savunma Refleksini Özetle (3. Dakika):**
    
      
    - _WAF:_ Rate Limiting (Dakikada maks istek sınırı) + CAPTCHA / JS Challenge.
        
          
        
    - _CDN:_ Anycast Edge Caching + Load Balancing.
        
          
        
    - _Origin Koruması:_ Güvenli kodlama (karakter sınırlaması) + Cache-Bypass engelleme.
