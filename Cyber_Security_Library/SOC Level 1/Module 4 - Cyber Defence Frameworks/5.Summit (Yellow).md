Analist olarak göreviniz, saldırganın her hamlesini analiz edip güvenlik araçlarını (Hash Engelleme, Güvenlik Duvarı, DNS Filtresi, Sysmon/Sigma Kuralları) yapılandırarak saldırganı piramidin en altından (Hash) en tepesine (TTPs) doğru tırmandırmak ve operasyon maliyetini artırarak pes ettirmektir.

### Aşama Aşama Savunma Dinamikleri

1. **Hash Değerleri (Trivial - Önemsiz):** `sample1.exe` dosyasının SHA256 özeti alınarak blok listesine eklenir. Saldırgan kodu yeniden derleyerek (recompile) bu engeli anında aşar.
    
2. **IP Adresleri (Easy - Kolay):** `sample2.exe` analizinde tespit edilen C2 IP adresi için Güvenlik Duvarında (Firewall) giden trafik (Egress Deny) kuralı yazılır.
    
3. **Domain Adresleri (Simple - Basit):** `sample3.exe` analizinde tespit edilen zararlı alan adı DNS Filtresinde (DNS Filter Rule) engellenir.
    
4. **Host/Network Artifacts (Annoying - Can Sıkıcı):** `sample4.exe` dosyasının Windows Defender'ı devre dışı bırakmak için yaptığı Kayıt Defteri (Registry) manipülasyonu tespit edilir ve **Sysmon Registry Modification** tabanlı **Sigma Kuralı** yazılır (`TA0005: Defense Evasion`).
    
5. **Tools (Challenging - Zorlayıcı):** `sample5.exe` C2 aracının düzenli aralıklarla (30 dakikada bir, 97 bayt, port 443) yaptığı **Beaconing** trafiği analiz edilir ve **Sysmon Network Connection** tabanlı Sigma kuralı oluşturulur.
    
6. **TTPs - Tactics, Techniques & Procedures (Tough - Çetin):** Saldırganın doğrudan metodolojisi hedef alınır. `%temp%\exfiltr8.log` dosyası üzerinden veri kaçırma davranışı tespit edilip **Sysmon File Creation** tabanlı Sigma kuralı yazılarak saldırı tamamen durdurulur (`TA0010: Exfiltration`).
    

## 💻 Tüm Kural Yapılandırmaları, Parametreler ve Sigma Mantığı

### 1. Hash Engelleme (Sample 1)

- **Kullanılan Araç:** Hash Manager / Blocklist
    
- **Algoritma:** `SHA256`
    
- **İşlem:** Sandbox analiz raporundan elde edilen SHA256 karması doğrudan engelleme listesine eklenir.
    

### 2. Güvenlik Duvarı Egress Kuralı (Sample 2)

- **Kullanılan Araç:** Firewall Manager
    
- **Kural Tipi:** `Egress` (Kurum içinden dışarıya doğru çıkan / kaçan bağlantılar)
    
- **Kaynak IP (Source IP):** `Any` (Şirket içerisindeki tüm uç noktaları kapsayacak şekilde)
    
- **Hedef IP (Destination IP):** `154.35.10.113`
    
- **Eylem (Action):** `Deny` (Bağlantıyı reddet/kes)
    

### 3. DNS Filtreleme Kuralı (Sample 3)

- **Kullanılan Araç:** DNS Rule Manager
    
- **Kural Adı:** `Stop Malware download`
    
- **Kategori:** `Malware`
    
- **Domain Name:** `emudyn.bresonicz.info`
    
- **Eylem (Action):** `Deny` (Alan adına giden DNS çözümleme isteklerini engelle)
    

### 4. Windows Defender Kapatma Tespiti - Sigma Kuralı (Sample 4)

- **Kullanılan Araç:** Sigma Rule Builder
    
- **Log Kaynağı (Step 1):** `Sysmon Event Logs`
    
- **Olay Türü (Step 2):** `Registry Modifications` (Sysmon Event ID 12/13)
    
- **Kural Parametreleri (Step 3):**
    
    - `Registry Key`: `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows Defender\Real-Time Protection`
        
    - `Registry Name`: `DisableRealtimeMonitoring`
        
    - `Value`: `1` (1 = Devre Dışı Bırakıldı)
        
    - `MITRE ATT&CK Mapping`: `Defense Evasion (TA0005)`
        

YAML

```
# Sigma Kuralı Karşılığı (Mantıksal Temsil)
title: Windows Defender Real-Time Protection Disabled
logsource:
    category: registry_event
    product: windows
detection:
    selection:
        TargetObject: 'HKLM\SOFTWARE\Microsoft\Windows Defender\Real-Time Protection\DisableRealtimeMonitoring'
        Details: '1'
    condition: selection
level: high
tags:
    - attack.defense_evasion
    - attack.t1562.001
```

### 5. C2 Beaconing Trafiği Tespiti - Sigma Kuralı (Sample 5)

- **İncelenen Log:** `outgoing_connections.log`
    
- **Tespit Edilen Patern:**
    
    - Hedef IP: `51.102.10.19`
        
    - Periyot: Her 30 dakikada bir (Düzenli aralık = Beaconing)
        
    - Port: `443` (HTTPS)
        
    - Paket Boyutu: `97 bytes` (Sabit boyut)
        
- **Kullanılan Araç:** Sigma Rule Builder
    
- **Log Kaynağı (Step 1):** `Sysmon Event Logs`
    
- **Olay Türü (Step 2):** `Network Connections` (Sysmon Event ID 3)
    
- **MITRE ATT&CK Mapping:** `Command and Control (TA0011)`
    

### 6. Geçici Dosya ile Veri Sızdırma Tespiti - Sigma Kuralı (Sample 6)

- **İncelenen Log:** `commands.log`
    
- **Saldırgan Davranışı:** Komut satırından çıktıları `%temp%\exfiltr8.log` içerisine yazdırıp dışarı kaçırma hazırlığı yapma.
    
- **Kullanılan Araç:** Sigma Rule Builder
    
- **Log Kaynağı (Step 1):** `Sysmon Event Logs`
    
- **Olay Türü (Step 2):** `File Creation and Modification` (Sysmon Event ID 11)
    
- **Kural Parametreleri (Step 3):**
    
    - `File Path`: `%temp%`
        
    - `File Name`: `exfiltr8.log`
        
    - `MITRE ATT&CK Mapping`: `Exfiltration (TA0010)`
        

YAML

```
# Sigma Kuralı Karşılığı (Mantıksal Temsil)
title: Staging Data in Temp Directory for Exfiltration
logsource:
    category: file_event
    product: windows
detection:
    selection:
        TargetFilename|endswith: '\exfiltr8.log'
        TargetFilename|contains: '\Temp\'
    condition: selection
level: critical
tags:
    - attack.exfiltration
    - attack.t1074.001
```

## 🧠 Uzman Notları ve Kritik Uyarılar

> ⚠️ **MÜLAKAT HAPI - "NEDEN PYRAMID OF PAIN'DE YUKARI ÇIKMAK ZORUNDAYIZ?"** Mülakatlarda tespit mühendisliği (Detection Engineering) sorulduğunda şu ayrımı kesinlikle belirtin:
> 
> - **Hash / IP / Domain:** Saldırgan için değiştirmesi saniyeler sürer (Maliyeti sıfıra yakındır).
>     
> - **Host Artifacts / Tools / TTPs:** Saldırganın çalışma biçimini ve kod tabanını hedefler. TTP seviyesinde yazılan bir Sigma kuralı, saldırganı tüm operasyon altyapısını ve saldırı metodolojisini sıfırdan tasarlamaya zorlar (En yüksek operasyonel maliyet).
>     

> 🚨 **KRİTİK UYARI - FIREWALL KURALINDA EGRESS / INGRESS KARIŞIKLIĞI:** Kurban makinenin C2 sunucusuna veya zararlı bir IP adresine bağlanmasını engellemek için yazılacak kuralın yönü **kesinlikle `Egress` (Dışarı Çıkan)** olmalıdır. `Ingress` (İçeri Giren) seçilirse makinenin dışarıya açtığı bağlantı filtrelenmez ve zararlı yazılım C2 ile haberleşmeye devam eder.

> 💡 **SEKTÖREL İPUCU - BEACONING TESPİTİNDE SABİT PAKET BOYUTU & ZAMAN:** C2 zararlıları (Örn: Cobalt Strike, Mythic) varsayılan konfigürasyonlarında belirli aralıklarla (interval/sleep time) ve benzer bayt boyutlarında sinyal (beacon) gönderirler. Log analizinde port 443 üzerinden sürekli aynı boyutta (Örn: 97 bayt) ve düzenli aralıklarla giden paketler yakalandığında bu durum doğrudan C2 trafiğinin işaretidir.
