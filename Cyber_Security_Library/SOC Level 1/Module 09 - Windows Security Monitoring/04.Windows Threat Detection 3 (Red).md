## 🏛️ 1. Mimari Yapı ve Saldırı Yaşam Döngüsü (C2, Persistence & Impact Architecture)

İlk Erişim (**Initial Access**) sağlandıktan ve sistem keşfi (**Discovery**) tamamlandıktan sonra tehdit aktörleri iki temel yol ayrımına gelir: Ya hızlıca veri çalıp çıkmak (**Data Stealer**) ya da ağda kalıcı olup derinlemesine yayılmak (**APT & Ransomware Operasyonları**).

  

Bu aşamada saldırganın operasyonunu ayakta tutan üç kritik taktik devreye girer:

  

1. **Komuta ve Kontrol (Command and Control - C2 / TA0011):** Kurban makinenin saldırganın kontrol sunucusuyla 7/24 kesintisiz iletişim kurması ve verilen emirleri çalıştırması.
    
      
    
2. **Kalıcılık (Persistence / TA0003):** Sistem yeniden başlatılsa (**reboot**), kullanıcı oturumu kapatsa veya parolalar değişse bile kurban sisteme erişimin otomatik olarak devam etmesi.
    
      
    
3. **Etki (Impact / TA0040):** Saldırının nihai hedefi; verilerin şifrelenmesi (**Ransomware**), sistemlerin çökertilmesi ve fidye notlarının yazdırılması.

## 📡 2. Komuta ve Kontrol (Command & Control - C2) Mimarisi

Bir sistem RDP üzerinden doğrudan ele geçirilmişse saldırgan komutları konsola elle yazabilir; ancak RDP portu kapatıldığı an erişim kopar. Bu nedenle aktörler, güvenlik duvarlarını içeriden dışarıya doğru aşan ters bağlantılı (**Reverse Shell / C2 Beacon**) ajanlar yerleştirirler.

  

### 🔹 Basit vs. Gelişmiş C2 Ajan Mekaniği

- **Doğrudan C2 (Simplest C2):** Oltalama e-postasıyla indirilen dosya doğrudan C2 sunucusuna bağlanır (Cobalt Strike, Sliver, Havoc Beacon).
    
      
    
- **Aşamalı C2 (Staged C2):** Oltalama eki (`URGENT!.zip`) doğrudan bağlanmaz; arka planda ikinci bir ikili dosyayı (`update.exe`) kurbanın `AppData\Roaming\` veya `C:\Temp\` klasörüne yazar ve bağımsız bir süreç olarak başlatır. Orijinal ek silinse dahi C2 oturumu hayatta kalır.
    
      
    

> [!TIP]
> 
> **Cloudflare Workers & CDN İstismarı:**
> 
>   
> 
> Güncel saldırılarda tehdit aktörleri C2 alan adlarını doğrudan kendi IP'lerine yönlendirmek yerine `route.m365officesync.workers.dev` gibi Cloudflare Workers veya meşru bulut altyapılarının arkasına gizleyerek itibar (reputation) filtrelerini atlatırlar.
> 
>   

## 🔑 3. Kullanıcı Yönetimi ile Kalıcılık (Backdoored Users)

Saldırganlar sisteme RDP ile sızdıktan sonra yetkisiz erişimi kalıcı hale getirmek için yeni bir yerel hesap açar ve bu hesabı `Administrators` veya `Remote Desktop Users` grubuna eklerler (**MITRE: T1136 & T1098**).

  

### 🔹 Kullanıcı Ekleme ve Yetkilendirme Komutları

DOS

```
:: 1. YÖNTEM: Windows CMD ile Kullanıcı Oluşturma ve Gruba Ekleme
net user "support" "P@ssw0rd123!" /add
net localgroup Administrators "support" /add
```

- `net user "support" "..." /add`: Sistemde `support` adında yeni bir yerel kullanıcı hesabı tanımlar.
    
      
    
- `net localgroup Administrators "support" /add`: Yeni oluşturulan hesabı en yüksek yerel yetkilere sahip `Administrators` grubuna dahil eder.
    
      
    

PowerShell

```
# 2. YÖNTEM: PowerShell Cmdlet'leri ile Kullanıcı Yönetimi
New-LocalUser "support" -Password (ConvertTo-SecureString "P@ssw0rd123!" -AsPlainText -Force)
Add-LocalGroupMember -Group "Administrators" -Member "support"
```

- `New-LocalUser`: PowerShell ortamında yerel hesap oluşturan cmdlet.
    
      
    
- `Add-LocalGroupMember`: Belirtilen hesabı yerel güvenlik grubuna atayan cmdlet.
    
      
    

### 🔹 Adli Güvenlik Logları Korelasyonu

- **Event ID 4625 (Failed Logon):** Başarılı sızma öncesi gelen kaba kuvvet (Brute-force) denemeleri (Örn: 6 kez hatalı parola girilmesi).
    
      
    
- **Event ID 4624 (Successful Logon):** Saldırganın içeri girdiği oturum (`Logon Type 10` - RDP).
    
      
    
- **Event ID 4720 (User Created):** `support` adlı arka kapı kullanıcısının açıldığı an.
    
      
    
- **Event ID 4732 (Member Added to Group):** Kullanıcının `Administrators` grubuna eklendiği an.
    
      
    
- **Event ID 4724 (Password Reset):** Eski veya pasif bir hesabın şifresinin sıfırlanarak ele geçirilmesi.
    
      
    

## ⚙️ 4. Sistem Seviyesinde Kalıcılık: Windows Servisleri ve Zamanlanmış Görevler

Sistem yeniden başlatıldığında (reboot) zararlının tekrar ayağa kalkmasını sağlayan, makine genelinde (**system-wide**) çalışan yöntemlerdir. Yerel yönetici (**Local Administrator**) ayrıcalığı gerektirir.

  

### 🔹 Yöntemlerin Karşılaştırmalı Teknik Tablosu

|**Kalıcılık Yöntemi**|**Çalışma Zamanı**|**Saldırgan CLI Komut Örneği**|**Log Kaynağı & Event ID**|**Tipik Üst Süreç (Parent Image)**|
|---|---|---|---|---|
|**Windows Servisi** (_Service_)|Sistem açılışında (OS Boot) arka planda otomatik başlar.|`sc create "BadService" binpath= "C:\malware.exe" start= auto`|• Sysmon `Event ID 1` (sc.exe)<br><br>  <br>  <br><br>• Security `Event ID 4697`<br><br>  <br>  <br><br>• System `Event ID 7045`|`C:\Windows\System32\services.exe`|
|**Zamanlanmış Görev** (_Scheduled Task_)|Belirli aralıklarla veya sistem açılışında (`onstart`) tetiklenir.|`schtasks /create /tn "BadTask" /tr "C:\malware.exe" /sc onstart /ru System`|• Sysmon `Event ID 1` (schtasks.exe)<br><br>  <br>  <br><br>• Security `Event ID 4698`|`C:\Windows\System32\svchost.exe -k netsvcs -p -s Schedule`|

### 🔹 CLI Parametre Detayları

DOS

```
sc create "Data Protection Service" binpath= "C:\malware\nessie.exe" start= auto
```

- `sc create`: Yeni bir Windows servisi kaydeder.
    
      
    
- `"Data Protection Service"`: Hizmet listesinde dikkat çekmemesi için verilen meşru görünümlü servis adı.
    
      
    
- `binpath=`: Servisin başlatacağı çalıştırılabilir dosyanın yolu (Eşittir işaretinden sonra boşluk bırakılması sözdizimsel olarak zorunludur).
    
      
    
- `start= auto`: Servisin işletim sistemi açılışında otomatik başlamasını sağlar.
    
      
    

DOS

```
schtasks /create /tn "AmazonSync" /tr "C:\malware\troy.exe" /sc onstart /ru System
```

- `schtasks /create`: Yeni bir zamanlanmış görev tanımlar.
    
      
    
- `/tn "AmazonSync"`: Görev adı (Task Name).
    
      
    
- `/tr "C:\malware\troy.exe"`: Görev tetiklendiğinde çalıştırılacak program (Task Run).
    
      
    
- `/sc onstart`: Tetikleme zamanı (Schedule: Sistem açılışında).
    
      
    
- `/ru System`: Görevin en yüksek ayrıcalıklı `NT AUTHORITY\SYSTEM` yetkisiyle çalışacağını belirtir.
    
      
    

> [!WARNING]
> 
> **Parent Process Ayrımı (Soruşturma İpucu):**
> 
>   
> 
> Bir saldırgan şüpheli bir ikiliyi çalıştırdığında üst süreci incelemek kök nedeni anında ele verir:
> 
>   
> 
> - Üst süreç `services.exe` ise $\rightarrow$ Olay bir **Windows Servisi** kalıcılığıdır.
>     
>       
>     
> - Üst süreç `svchost.exe -k ... -s Schedule` ise $\rightarrow$ Olay bir **Zamanlanmış Görev** (Task Scheduler) kalıcılığıdır.
>     
>       
>     

## 📂 5. Kullanıcı Seviyesinde Kalıcılık: Başlangıç Klasörü ve Run Keys

Yönetici (Admin) yetkisi gerektirmeyen, sadece hedef kullanıcı sisteme giriş yaptığında (**User Logon**) tetiklenen yöntemlerdir.

  

### 🔹 Başlangıç Klasörü (Startup Folder)

- **Kullanıcıya Özel Dizin:**
    
      
    
    `C:\Users\<USER>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\`
    
      
    
- **Tüm Kullanıcılar İçin Dizin:**
    
      
    
    `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup\`
    
      
    
- **Çalışma Mantığı:** Bu klasöre bırakılan herhangi bir `.exe`, `.bat` veya `.url` kısayol dosyası kullanıcı masaüstüne ulaştığı an Windows Gezgini (`explorer.exe`) tarafından otomatik çalıştırılır.
    
      
    
- **Tespit:** Sysmon **Event ID 11** (_File Create_) ile Startup dizinine yazılan dosyalar izlenir. Başlatılan zararlının üst süreci `C:\Windows\explorer.exe` olur.
    
      
    

### 🔹 Kayıt Defteri Çalıştırma Anahtarları (Run Keys)

- **Kullanıcı Bazlı Yol:** `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
    
      
    
- **Makine Bazlı Yol:** `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`
    
      
    

DOS

```
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v "BadKey" /t REG_SZ /d "C:\malware.exe" /f
```

- `reg add`: Kayıt defterine yeni anahtar veya değer yazar.
    
      
    
- `/v "BadKey"`: Eklenen değerin adı (Value Name).
    
      
    
- `/t REG_SZ`: Değer veri türü (Dize/String metin).
    
      
    
- `/d "C:\malware.exe"`: Çalıştırılacak zararlının tam dosya yolu (Data).
    
      
    
- `/f`: Onay istemeden zorla üzerine yaz (`force`).
    
      
    
- **Tespit:** Sysmon **Event ID 13** (_Registry Value Set_) ile Run anahtarlarına yapılan müdahaleler filtrelenir.
    
      
    

## 💥 6. Nihai Hedef: Tehdit Aktörlerinin Kalıcılık Sebepleri ve Etki (Impact)

Saldırganlar ele geçirdikleri sistemde neden haftalarca veya aylarca kalırlar?

  

1. **Botnet Entegrasyonu:** Sistemi Kraken Botnet gibi kripto madenci, C2 rölesi ve DDoS zombisine dönüştürmek.
    
      
    
2. **Devlet Destekli Casusluk (APT):** _Volt Typhoon_ gibi tehdit aktörlerinin kritik altyapı şebekelerinde (enerji/su) 1 yıla yakın süre sessizce izleme yapması.
    
      
    
3. **Active Directory Yayılımı ve Ransomware:** Kurumsal ağa yanal hareketle (**Lateral Movement**) yayılarak tüm Domain Controller ve sunucuları rehin almak. (Örn: McLaren hastanelerindeki 743.000 hastayı etkileyen sağlık sistemi çöküşü).
    
      
    

> [!NOTE]
> 
> **Altın Kural:** Bir siber saldırıyı durdurmak ve zararı minimize etmek için en kritik müdahale anı **İlk Erişim (Initial Access)** aşamasıdır. Saldırı Etki (**Impact / Ransomware**) aşamasına ulaştığında geri dönüş maliyeti astronomik seviyelere çıkar.
> 
>

## 🚦 8. Tekrar Kategorisi & 3 Dakikalık Pazar Tekrar Stratejisi

### 🔴 Kırmızı Sınıf: Kalıcılık İmzaları, Event ID'ler & Kayıt Defteri Yolları

Bu modül **Kırmızı Sınıf** (Doğrudan Kalıcılık Mekanizmaları, Event ID Eşleştirmeleri ve Adli Kayıt Defteri Yolları) kategorisindedir.

  

### ⏱️ Pazar Günü 3 Dakikalık Hızlı Tekrar Rutini

1. **Kalıcılık Yöntemi ve Üst Süreç Ayrımı (1. Dakika):**
    
      
    - _Windows Servisi:_ `Event ID 4697 / 7045` $\rightarrow$ Üst Süreç: `services.exe`
        
          
        
    - _Zamanlanmış Görev:_ `Event ID 4698` $\rightarrow$ Üst Süreç: `svchost.exe -s Schedule`
        
          
        
    - _Startup / Run Keys:_ `Sysmon ID 11 / 13` $\rightarrow$ Üst Süreç: `explorer.exe`
        
          
        
2. **Kritik Dosya ve Kayıt Defteri Konumları (2. Dakika):**
    
      
    - _Startup Folder:_ `AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\`
        
          
        
    - _Run Key:_ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
        
          
        
    - _Hesap Ekleme:_ `4720` (Kullanıcı açıldı) $\rightarrow$ `4732` (Yetkili gruba eklendi).
        
          
        
3. **Mülakat Sorusu Canlandırması (3. Dakika):**
    
      
    - _Soru:_ "Bir saldırganın Windows makinede kalıcılık sağladığından şüpheleniyorsun. Hangi loglara ve hangi Registry anahtarlarına bakarsın?"
        
          
        
    - _Cevap:_ "Öncelikle sistem düzeyinde yeni bir servis veya görev oluşturulmuş mu diye Security `4697/4698` loglarına bakarım. Ardından kullanıcı düzeyinde kalıcılık için `HKCU\...\CurrentVersion\Run` anahtarını Sysmon `Event ID 13` ile, kullanıcı başlangıç klasörünü ise Sysmon `Event ID 11` ile denetlerim. Ayrıca yetkisiz bir hesap açılıp açılmadığını `4720` loglarından doğrularım."
