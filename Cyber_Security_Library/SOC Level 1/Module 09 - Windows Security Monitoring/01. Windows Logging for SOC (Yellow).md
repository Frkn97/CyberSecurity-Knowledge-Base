# 🛡️ Windows Logging for SOC 

## **Tags:** `#soc` `#dfir` `#windows-logging` `#event-viewer` `#sysmon` `#powershell` `#threat-hunting` `#tryhackme` **Platform:** TryHackMe

## 🏛️ Mimari Yapı ve Temel Mantık

Windows işletim sistemi olay günlükleri (Windows Event Logs), SIEM (Security Information and Event Management) sistemlerinin omurgasını oluşturur. Bir L1 SOC Analisti ve Tehdit Avcısı (Threat Hunter) için log analizi; alarm önceliklendirme (triage), adli bilişim (DFIR) ve kök neden analizinin merkezindedir.

  

```
[Kullanıcı / Saldırgan Eylemi]
          │
          ▼
[Windows Çekirdeği / Alt Sistemler]
          │
          ├──► Yerleşik Olay Kaydı (winevt) ──► EVTX Dosyaları (C:\Windows\System32\winevt\Logs)
          │                                            │
          │                                            ├──► Security.evtx (Kimlik Doğrulama / Kullanıcı Yönetimi)
          │                                            ├──► Application.evtx (Kullanıcı Modu Uygulamaları)
          │                                            └──► System.evtx (Sistem Bileşenleri)
          │
          ├──► Sysinternals Sysmon ─────────────► Microsoft-Windows-Sysmon/Operational
          │    (Gelişmiş Süreç, Ağ, DNS, Hash)         │
          │                                            └──► PID / ProcessGUID ile Korelasyon
          │
          └──► PowerShell Oturumu (PSReadLine) ──► ConsoleHost_history.txt (Düz Metin Komut Geçmişi)
```

### Temel Loglama Mekanizmaları ve Görevleri

- **Yerleşik Windows Logları (`.evtx`):** İkili (binary) XML formatında saklanır (`C:\Windows\System32\winevt\Logs`). Kullanıcı oturum açmaları, hesap yönetimi ve temel güvenlik olayları için varsayılan kaynaktır.
    
      
    
- **Microsoft Sysinternals Sysmon:** Çekirdek seviyesinde çalışan bir aygıt sürücüsü (device driver) ve arka plan servisidir. Standart Windows loglarının sağlayamadığı SHA256/MD5 süreç özetleri (hashes), işlem ağacı hiyerarşisi (Parent/Child PID), DNS sorguları ve ham ağ bağlantılarını yakalayarak L1 analistine uç nokta (endpoint) üzerinde tam görünürlük kazandırır.
    
      
    
- **PSReadLine / PowerShell Geçmişi:** PowerShell terminali üzerinden çalıştırılan komutları anlık olarak her kullanıcının profil dizini altına düz metin (`ConsoleHost_history.txt`) olarak yazar. Süreç oluşturma loglarının komut satırı argümanlarını yakalayamadığı durumlarda doğrudan dosya tabanlı kanıt sağlar.

## 🔐 Görev 3: Security Log - Kimlik Doğrulama Analizi (4624 & 4625)

Kimlik doğrulama olayları saldırı zincirinin ilk adımıdır. Saldırganın içeri nasıl girdiğini (Initial Access) ve parola denemelerini bu loglardan doğrularız.

  

### Temel Kimlik Doğrulama Olay Kimlikleri (Event IDs)

|**Event ID**|**Tanım**|**Amacı**|**SOC Analist Kısıtlaması / Tuzağı**|
|---|---|---|---|
|**4624**|Successful Logon|Şüpheli RDP/Ağ oturumlarını ve ilk sızma noktasını yakalamak.|**Gürültülüdür (Noisy):** Yüklü bir sunucuda dakikada yüzlerce oturum olayı üretilir. Doğru filtreleme şarttır.|
|**4625**|Failed Logon|Kaba kuvvet (Brute Force), Password Spraying veya servis taramalarını yakalamak.|**Tutarsızlıklar:** Çeşitli kimlik doğrulama parametreleri yanlış analize sevk edebilir; Logon Type kontrolü zorunludur.|

### Kritik Oturum Türleri (Logon Types)

|**Logon Type**|**Adı**|**Teknik Açıklama ve SOC İpuçları**|
|---|---|---|
|**2**|Interactive|Klavyeden doğrudan fiziksel olarak oturum açma (Local console).|
|**3**|Network|Ağ üzerinden paylaşıma veya servise erişim (SMB, RPC vb.). **Modern RDP (NLA aktifken)** kimlik doğrulaması da başlangıçta Tip 3 üretir.|
|**4**|Batch|Zamanlanmış görevler (Scheduled Tasks) tarafından açılan oturumlar.|
|**5**|Service|Windows servislerinin kendi hesaplarıyla başlattığı oturumlar.|
|**7**|Unlock|Kilitli ekranın açılması.|
|**10**|RemoteInteractive (RDP)|Uzak Masaüstü Bağlantısı (Terminal Services). Eski/NLA kapalı sistemlerde doğrudan, modern sistemlerde Tip 3'ten sonra tetiklenir.|

### 🛠️ Analiz Metodolojileri ve Tehdit Avı Playbook'u

> [!WARNING]
> 
> **NLA (Network Level Authentication) Mekanizması:**
> 
> Modern sistemlerde NLA varsayılan olarak açıktır. Bu nedenle bir RDP oturumu gerçekleştiğinde sistem **önce Logon Type 3 (Network)** ile kimlik doğrulaması yapar, ardından oturum başladığında **Logon Type 10 (RemoteInteractive)** üretir. Saldırganın gerçek `Workstation Name` bilgisini elde etmek için Logon Type 10'dan hemen önceki Logon Type 3 olayına bakılmalıdır.
> 
>   

#### RDP Kaba Kuvvet (Brute Force) & Password Spraying Tespiti

1. `Security.evtx` açılır ve Event ID `4625` filtrelenir.
    
      
    
2. `Logon Type` değerinin **3** veya **10** olduğu olaylar incelenir.
    
      
    
3. **Kırmızı Bayraklar (Red Flags):**
    
      
    - Tek bir hesaba (`Administrator`) yönelik çok sayıda başarısız deneme $\rightarrow$ **Brute Force**.
        
          
        
    - Birçok farklı kullanıcı adına (`admin`, `helpdesk`, `cctv`, `guest`) yönelik sıralı başarısız denemeler $\rightarrow$ **Password Spraying**.
        
          
        
    - Kurumsal adlandırma standardına uymayan iş istasyonu adları (Örn: `THM-PC-06` yerine `kali`).
        
          
        
    - Beklenmedik kaynak IP adresleri (Örn: bir ağ yazıcısının sunucuya oturum açmayı denemesi).
        
          
        

#### RDP Başarılı Giriş Analizi ve Oturum Takibi

1. `Security.evtx` açılır ve Event ID `4624` filtrelenir.
    
      
    
2. `Logon Type 10` olan olaylar tespit edilir.
    
      
    
3. Bu olaydan hemen önce gelen `Logon Type 3` olayı bulunarak saldırganın gerçek makine adı ve IP'si çıkarılır.
    
      
    
4. **Logon ID Değeri:** Başarılı her oturuma benzersiz bir oturum kimliği atanır (Örn: `0x183C36D`). Bu ID, saldırganın oturum boyunca yaptığı tüm eylemleri bağlamak için **altın değerindedir**.
    
      
    

## 👥 Görev 4: Security Log - Kullanıcı Yönetimi Olayları

Saldırganlar kalıcılık (Persistence) sağlamak veya tespit edilmekten kaçınmak için yeni hesap açar, pasif hesapları aktifleştirir veya mevcut hesapların yetkilerini yükseltir.

  

### Kullanıcı Yönetimi Olay Tablosu

|**Event ID**|**İşlem / Olay Açıklaması**|**Saldırganların İstismar Yöntemi**|
|---|---|---|
|**4720**|Bir kullanıcı hesabı oluşturuldu (_User account created_)|Sistemde kalıcılık (backdoor) hesabı oluşturma.|
|**4722**|Bir kullanıcı hesabı aktifleştirildi (_Account enabled_)|Eski/kullanılmayan hesapları aktif ederek şüphe çekmeden yetki alma.|
|**4738**|Bir kullanıcı hesabı değiştirildi (_User account changed_)|Hesap izinlerini veya niteliklerini manipüle etme.|
|**4725**|Bir kullanıcı hesabı devre dışı bırakıldı (_Account disabled_)|SOC veya güvenlik ekiplerinin hesaplarını kapatıp müdahaleyi geciktirme.|
|**4726**|Bir kullanıcı hesabı silindi (_Account deleted_)|Geride delil bırakmamak için oluşturulan geçici hesabı temizleme.|
|**4723**|Kullanıcı kendi şifresini değiştirmeyi denedi|Şifre ele geçirme sonrası kullanıcı hareketleri.|
|**4724**|Bir kullanıcının şifresi yetkili tarafından sıfırlandı|Hedef hesabı ele geçirmek için parolayı sıfırlama.|
|**4732**|Güvenlik grubuna üye eklendi (_Added to security group_)|Backdoor hesabını `Administrators`, `Backup Operators` gibi gruplara ekleme.|
|**4733**|Güvenlik grubundan üye çıkarıldı (_Removed from security group_)|İnceleme sonrası iz gizleme veya kısıtlama adımları.|

### Olay Kaydının Anatomik Yapısı

Kullanıcı yönetimi logları 3 temel bloktan oluşur:

  

1. **Subject (Özne):** Eylemi gerçekleştiren hesap. Buradaki **Logon ID**, Task 3'te tespit edilen başarılı `4624` olayındaki Logon ID ile eşleştirilerek oturum korelasyonu sağlanır.
    
      
    
2. **Object (Nesne):** Eylemin hedefi olan kullanıcı veya grup (Örn: `TargetUserName` / `MemberName`).
    
      
    
3. **Details (Ayrıntılar):** Yapılan değişikliklerin içeriği (Örn: eklenen grup adı, şifre geçerlilik ayarları).
    
      
    

> [!TIP]
> 
> **Arka Kapı (Backdoor) Hesap Avı Metodolojisi:**
> 
>   
> 
> - Event ID `4720` ve `4732` için filtre uygulayın.
>     
>       
>     
> - BT departmanının onayı olmayan, mesai saatleri dışında veya hafta sonu yapılan işlemleri sorgulayın.
>     
>       
>     
> - Şüpheli hesap adlandırmalarını tespit edin (Örn: standart dışı `svc_sysrestore` veya `backup`).
>     
>       
>     
> - Şüpheli olaydaki `Logon ID` değerini kopyalayarak `4624` loglarında aratın ve hangi IP'den sızıldığını kesinleştirin.
>

## ⚙️ Görev 5: Sysmon - Süreç İzleme (Process Monitoring)

Sadece kimlik doğrulamayı izlemek, saldırganın sistemde ne çalıştırdığını (How) anlamaya yetmez. Uç nokta tespiti için süreç logları gereklidir.

  

### 4688 vs. Sysmon Event ID 1 Karşılaştırması

|**Özellik**|**Security Log (Event ID 4688)**|**Sysmon (Event ID 1)**|
|---|---|---|
|**Durum**|Varsayılan olarak kapalıdır; GPO ile açılması gerekir.|Harici araçtır (Microsoft Sysinternals); kurulması gerekir.|
|**Gürültü Seviyesi**|Yüksektir ve filtrelemesi zordur.|Esnek XML konfigürasyonu ile gürültü tamamen bastırılabilir.|
|**Hash Desteği**|Yoktur.|**Var:** MD5, SHA256, IMPHASH gibi kriptografik özetler üretir.|
|**Süreç Hiyerarşisi**|Sınırlı Parent/Child takibi sunar.|**Gelişmiş:** ParentImage, ParentCommandLine, ParentProcessId tam dökülür.|
|**Kayıt Yolu**|`Security.evtx`|`Applications and Services Logs -> Microsoft -> Windows -> Sysmon -> Operational`|

### Sysmon Event ID 1 Alan Grupları

- **Process Info:** Başlatılan sürecin bağlamı (`ProcessId`, `Image` [yol], `CommandLine`).
    
      
    
- **Parent Info:** Süreci başlatan üst süreç bilgisi (`ParentProcessId`, `ParentImage`, `ParentCommandLine`). Süreç ağacı (Process Tree) çıkarmada kullanılır.
    
      
    
- **Binary Info:** Kriptografik hash değerleri (`Hashes`), dijital imza durumu (`Signed`), PE metadata bilgileri.
    
      
    
- **User Context:** Süreci çalıştıran kullanıcı ve oturum korelasyonunu sağlayan `LogonId`.
    
      
    

> [!WARNING]
> 
> **Süreç Avı (Process Hunting) Kırmızı Bayrakları:**
> 
>   
> 
> - **Şüpheli Dizinler:** `C:\Temp`, `C:\Users\Public`, `C:\ProgramData`, `AppData` altından çalışan çalıştırılabilir dosyalar (`.exe`).
>     
>       
>     
> - **Anormal İsimler:** Rastgele üretilmiş veya tek haneli isimler (`aa.exe`, `jqyvpqldou.exe`).
>     
>       
>     
> - **Anormal Ebeveyn-Çocuk İlişkisi:** `notepad.exe` veya `calc.exe` gibi uygulamaların `cmd.exe`, `powershell.exe` başlatması.
>     
>       
>     
> - **Hash Eşleşmesi:** Üretilen hash değerinin VirusTotal üzerinde zararlı olarak işaretlenmesi.
>     
>       
>     

## 🌐 Görev 6: Sysmon - Dosya, Ağ ve Kalıcılık Analizi

Saldırganın bıraktığı zararlıyı, yaptığı C2 (Command & Control) bağlantılarını ve kalıcılık mekanizmalarını ortaya çıkarmak için diğer Sysmon olayları incelenir.

  

### Sysmon İleri Düzey Olay Kimlikleri

|**Sysmon Event ID**|**Olay Tanımı**|**Security Log Alternatifi**|**Tehdit Avındaki Rolü**|
|---|---|---|---|
|**3**|Network Connection|Doğrudan alternatifi yoktur (Gelişmiş Güvenlikli Güvenlik Duvarı gerekir).|Süreçlerin dış IP'lere yaptığı TCP/UDP bağlantılarını, C2 trafiğini yakalar.|
|**11**|File Create|Event ID 4656 (Varsayılan olarak kapalıdır).|Diske bırakılan zararlı yazılımları (droppers, payloads) ve kalıcılık dosyalarını tespit eder.|
|**13**|Registry Value Set|Event ID 4657 (Varsayılan olarak kapalıdır).|Kayıt Defteri (Registry Run Keys) üzerinden sağlanan kalıcılık adımlarını yakalar.|
|**22**|DNS Query|Doğrudan alternatifi yoktur (DNS Analytical Logging gerekir).|Süreçlerin isim çözümleme yaptığı C2 alan adlarını (`QueryName`) tespit eder.|

### Süreç Merkezli Korelasyon Metodolojisi

Sysmon Event 3, 11, 13 ve 22 olaylarında bazen `ParentProcess` veya `Logon ID` alanları bulunmaz.

  

1. Şüpheli Event ID 1 (Süreç Oluşturma) kaydından `ProcessId` (PID) değeri kopyalanır.
    
      
    
2. Sysmon loglarında bu `ProcessId` filtre olarak aratılarak sürecin oluşturduğu dosyalar (ID 11), bağlandığı IP/Portlar (ID 3) ve sorguladığı DNS adresleri (ID 22) tek bir zaman çizelgesine dizilir.
    
      
    

> [!TIP]
> 
> **Ağ ve Kalıcılık Kırmızı Bayrakları:**
> 
>   
> 
> - `ProcessId` ile bağlanan ağ olaylarında standart dışı portlar (Örn: `4444`, `7777`, `8080`).
>     
>       
>     
> - Şüpheli TLD uzantıları (`.click`, `.top`, rastgele harf dizilimli alan adları).
>     
>       
>     
> - `Startup` klasörlerine eklenen kısayol ve dosyalar:
>     
>       
>     
>     `C:\Users\<USER>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\`
>     
>       
>     

## 💻 Görev 7: PowerShell Komut Loglama ve İnceleme

Saldırganlar Living-off-the-Land (LotL) teknikleri kapsamında yerleşik `powershell.exe`'yi kötüye kullanırlar. Sysmon Event ID 1 yalnızca `powershell.exe`'nin başladığını bildirir; terminal içerisinde interaktif olarak girilen alt komutları (`Get-ChildItem`, `Invoke-WebRequest` vb.) **gösteremez**.

  

### PowerShell İzleme Yaklaşımı: PSReadLine Geçmiş Dosyası

PowerShell 5.0 ile gelen PSReadLine modülü, kullanıcının terminale yazdığı her komutu oturum kapansa veya sistem yeniden başlasa dahi bir metin dosyasında saklar:

  

Plaintext

```
C:\Users\<USER>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadline\ConsoleHost_history.txt
```

### PSReadLine Özellikleri ve Kısıtlamaları

|**Özellik**|**Durum / Açıklama**|
|---|---|
|**Kullanıcı Başına Kayıt**|Her yerel kullanıcının kendi profil dizini altında ayrı bir `ConsoleHost_history.txt` dosyası bulunur. 5 kullanıcı varsa 5 dosya incelenmelidir.|
|**Kalıcılık**|Manuel olarak silinmediği sürece sistem yeniden başlatmalarından etkilenmez.|
|**Komut Çıktıları**|**Kaydedilmez.** Dosya yalnızca girilen komut metnini tutar, komutun ekrana bastığı sonucu kaydetmez.|
|**Script Blok İçerikleri**|Harici bir script çalıştırıldığında (`powershell.exe -File .\payload.ps1`), scriptin içindeki satırlar buraya yazılmaz (Bunun için Script Block Logging / Event ID 4104 gerekir).|

> [!NOTE]
> 
> **Adli Bilişim İpucu:**
> 
> Bir kullanıcının ilk PowerShell komutunu ne zaman çalıştırdığını bulmak için `ConsoleHost_history.txt` dosyasının dosya sistemindeki **Oluşturulma Tarihi (Creation Date)** dosya özelliklerinden (Properties) kontrol edilir.
> 
>

## 📌 Tekrar Kategorisi ve Stratejisi

### Renk Sınıfı

**🟡 Sarı Sınıf: Kavramsal / 3 Dakika Soru-Cevap Odası**

  

Bu oda yoğun payload ezberinden ziyade; Event ID'lerin zihinsel haritasına, alanlar arası korelasyona (Logon ID & PID takibi) ve log kaynaklarının mimari farklarına dayanır.

  

### ⏱️ Pazar Günü 3 Dakikalık Hızlı Tekrar Rutini

1. **Olay Kimlikleri Flash-Recall (60 sn):**
    
      
    - `4624` (Başarılı) vs `4625` (Başarısız)
        
          
        
    - `4720` (Kullanıcı açma) $\rightarrow$ `4732` (Gruba ekleme)
