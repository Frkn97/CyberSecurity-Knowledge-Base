## 🏛️ 1. Mimari Yapı ve Saldırı Zinciri (MITM Architecture & Chained Attack)

Ortadaki Adam (**Man-in-the-Middle - MITM**) saldırısı, saldırganın iki meşru iletişim noktası (örneğin bir istemci ile yerel ağ geçidi veya bir kullanıcı ile web sunucusu) arasına gizlice girerek trafiği dinlemesi (**eavesdropping**), değiştirmesi (**tampering**) veya sahte hedeflere yönlendirmesidir (**redirecting**).

  

Acme Corp vakasında saldırgan, birbirini besleyen **3 aşamalı zincirleme (chained) bir saldırı mimarisi** işletmiştir:

  

```
[ 1. AŞAMA: Ağ Düzeyinde Kesme ]
   Saldırgan (02:fe:fe:fe:55:55) ──── Unsolicited ARP is-at ────► Kurban (192.168.10.10)
   (Gateway IP'si 192.168.10.1, saldırganın MAC adresine yönlendirilir - ARP Poisoning)
                                      │
                                      ▼
[ 2. AŞAMA: Trafik Yönlendirme ]
   Kurban (corp-login DNS sorgusu) ──► Saldırgan Sahte Yanıtı (DNS Spoofing)
   (Meşru IP yerine Sahte Portal IP'si döner: 192.168.10.55)
                                      │
                                      ▼
[ 3. AŞAMA: Kriptografik Düşürme & Veri Hırsızlığı ]
   Kurban ◄────── Düz Metin HTTP (Port 80) ──────► Saldırgan (Proxy) ◄── HTTPS (Port 443) ──► Gerçek Sunucu
   (SSL Stripping ile oturum şifresizleştirilir; POST isteğindeki kullanıcı adı ve parola çalınır)
```

### 🔹 MITRE ATT&CK & Cyber Kill Chain Entegrasyonu

> [!NOTE]
> 
> **SOC Analistinin Perspektifi:** Bir MITM saldırısı tek başına izole bir olay değildir; Kill Chain üzerinde doğrudan **Exploitation (Sömürü)** ve **Installation (Kurulum/Yayılma)** aşamalarını temsil eder.
> 
>   
> 
> - **Sömürü Aracı Olarak MITM:** Ağ protokollerinin (ARP ve DNS) tasarım gereği kimlik doğrulamasız (stateless/unauthenticated) güven modelini kötüye kullanarak oturumu ele geçirir.
>     
>       
>     
> - **Kurulum / Teslimat Vektörü Olarak MITM:** Ortaya oturan saldırgan, giden/gelen trafiği manipüle edebildiği için kullanıcının indirdiği meşru şifresiz dosyaların içine zararlı yazılım (Trojan, RAT) veya tarayıcı exploitleri enjekte edebilir.
>     
>       
>

## 🔍 3. Adım Adım MITM Tespiti & Wireshark Paket Analizi

### 🔹 FAZ 1: ARP Spoofing (Zehirlenme ve Ağ Trafiğinin Ele Geçirilmesi)

ARP (Address Resolution Protocol), yerel ağda IPv4 adreslerini MAC adreslerine eşler. Doğrulaması yoktur; her cihaz ağa habersizce _"ben bu IP'ye sahibim"_ (`is-at`) diyebilir.

  

```
Normal Durum: 192.168.10.1 (Gateway) ──────► MAC: 02:aa:bb:cc:00:01
Zehirlenmiş : 192.168.10.1 (Gateway) ──────► MAC: 02:fe:fe:fe:55:55 (Saldırgan!)
```

#### Wireshark Filtreleri ve Parametre Anlamları

Kod snippet'i

```
# 1. Tüm ARP trafiğini izole etme
arp

# 2. Sadece ARP isteklerini (Who has?) listeleme
arp.opcode == 1

# 3. Sadece ARP yanıtlarını (is-at) listeleme (Zehirlenme burada aranır)
arp.opcode == 2

# 4. İstenmemiş / Talep edilmemiş (Gratuitous) sahte ARP paketlerini tespit etme
arp.isgratuitous

# 5. Meşru ağ geçidinden çıkan gerçek ARP paketlerini doğrulama
arp && arp.src.proto_ipv4 == 192.168.10.1 && eth.src == 02:aa:bb:cc:00:01

# 6. Gateway IP'sini anons eden tüm yanıtları dökme (Farklı MAC tespiti)
arp.opcode == 2 && arp.src.proto_ipv4 == 192.168.10.1

# 7. Bilgi sütununda "192.168.10.1 is at" geçen anonsları filtreleme
arp.opcode == 2 && _ws.col.info contains "192.168.10.1 is at"

# 8. Saldırgan MAC adresinin ağ geçidi adına yaydığı sahte paketleri sayma
arp.opcode == 2 && arp.src.proto_ipv4 == 192.168.10.1 && eth.src == 02:fe:fe:fe:55:55

# 9. Wireshark uzman analizcisinin (Expert Info) tespit ettiği IP-MAC çakışmaları
arp.duplicate-address-detected || arp.duplicate-address-frame
```

> [!WARNING]
> 
> **Gratuitous ARP Tuzağı:** Ağda bir IP adresi için istemci talepte bulunmadığı halde sürekli `is-at` yanıtı geliyorsa, saldırgan kurbanın ve router'ın ARP önbelleğini (cache) taze ve zehirli tutmaya çalışıyordur. Bir IP'ye iki farklı fiziksel MAC adresi yanıt veriyorsa ortada kesin bir ARP Spoofing vakası vardır.
> 
>   

### 🔹 FAZ 2: DNS Spoofing (Trafik Yönlendirme & Sahte Sunucu)

Kurban `corp-login.acme-corp.local` adresine gitmek istediğinde, ARP zehirlenmesi sayesinde araya giren saldırgan DNS sorgusunu yakalar ve yasal DNS'ten önce sahte yanıt döner.

  

```
Kurban Sorgusu: "corp-login.acme-corp.local IP'si nedir?"
Saldırgan Cevabı: "192.168.10.55 adresidir!" (Sahte DNS Yanıtı)
```

#### Wireshark Filtreleri ve İnceleme Mantığı

Kod snippet'i

```
# 1. DNS protokolünü izole etme
dns

# 2. Yasal DNS sunucusundan (8.8.8.8) gelen normal yanıtları listeleme
dns.flags.response == 1 && ip.src == 8.8.8.8

# 3. İlgili iç alan adına ait tüm DNS yanıtlarını sayma (Toplam: 211 adet)
dns.flags.response == 1 && dns.qry.name == "corp-login.acme-corp.local"

# 4. Yasal sunucu (8.8.8.8) DIŞINDAN gelen DNS yanıtlarını yakalama (Rogue DNS tespiti)
dns.flags.response == 1 && ip.src != 8.8.8.8 && dns.qry.name == "corp-login.acme-corp.local"

# 5. Saldırgan IP'sinin döndüğü sahte yanıtları izole etme
dns.flags.response == 1 && ip.src == 192.168.10.55 && dns.qry.name == "corp-login.acme-corp.local"
```

> [!TIP]
> 
> **DNS Spoofing İmzaları:**
> 
>   
> 
> 1. **Multiple Conflicting Responses:** Aynı sorguya iki farklı kaynaktan çelişkili yanıt gelmesi (Biri meşru sunucudan, diğeri yerel saldırgandan).
>     
>       
>     
> 2. **Düşük TTL (Time-To-Live):** Saldırganlar kurbanın önbelleğinde sahte kaydı kontrol altında tutabilmek için TTL değerini genellikle 1–30 saniye gibi çok düşük tutarlar.
>     
>       
>     
> 3. **Unexpected Source:** Yapılandırılmış DNS resolvers (örneğin 8.8.8.8 veya iç DC) dışındaki yerel bir IP'nin DNS cevabı üretmesi.
>     
>       
>     

### 🔹 FAZ 3: SSL Stripping (HTTPS Downgrade & Açık Metin Parola Hırsızlığı)

SSL Stripping tekniğinde saldırgan, kurbanın tarayıcısı ile HTTPS bağlantısı kurmasına izin vermez. Kurbana sitenin **düz metin HTTP (Port 80)** sürümünü sunar; kendisi ise arka planda gerçek sunucuyla HTTPS (Port 443) üzerinden konuşur.

  

```
Kurban (Tarayıcı)  ◄────── Şifresiz HTTP (Port 80) ──────►  Saldırgan (Mitmproxy / sslstrip)
                                                                    │
                                                           Şifreli HTTPS (Port 443)
                                                                    │
                                                                    ▼
                                                            Gerçek Web Portalı
```

#### Wireshark Filtreleri ve İnceleme

Kod snippet'i

```
# 1. Normal TLS trafiğini doğrulama (Sitenin normalde TLS kullandığını kanıtlama)
tls.handshake.type == 1 && tls.handshake.extensions_server_name == "corp-login.acme-corp.local"

# 2. Kurban ile Saldırgan arasındaki düz metin HTTP trafiğini izole etme
http && ip.src == 192.168.10.10 && ip.dst == 192.168.10.55

# 3. Kurbanın gönderdiği kimlik doğrulama (POST) isteklerini filtreleme
http.request.method == "POST" && ip.dst == 192.168.10.55
```

- **Adli Bulgu:** Wireshark'ta yakalanan HTTP POST paketine sağ tıklayıp **Follow $\rightarrow$ HTTP Stream** (veya TCP Stream) seçildiğinde kurbanın girdiği hassas parola açık metin olarak yakalanır:
    
      
    - **Kullanıcı Adı / Parametre:** Oturum açma form verisi
        
          
        
    - **Açık Metin Parola:** `Secret123!`

## 🛡️ 5. Mavi Takım Savunma Stratejileri (Mitigation)

Mülakatlarda _"MITM saldırılarını ağ seviyesinde nasıl engellersiniz?"_ sorusunun kurumsal yanıtları:

  

1. **DAI (Dynamic ARP Inspection):** Switch'ler üzerinde DHCP Snooping veritabanı kullanılarak sahte veya eşleşmeyen ARP paketleri port seviyesinde düşürülür.
    
      
    
2. **HSTS (HTTP Strict Transport Security):** Web sunucularında tarayıcılara sadece HTTPS üzerinden bağlanma zorunluluğu getirilir; SSL Stripping saldırılarını tamamen engeller.
    
      
    
3. **DNSSEC:** DNS yanıtlarının kriptografik olarak imzalanmasını sağlayarak DNS Cache Poisoning saldırılarını etkisiz hale getirir.
    
      
    
4. **Statik ARP Tablosu:** Kritik sunucularda ve varsayılan ağ geçitlerinde kritik IP-MAC eşleşmeleri statik olarak tanımlanır.
    
      
    

## 🚦 Tekrar Kategorisi & 3 Dakikalık Pazar Tekrar Stratejisi

### 🔴 Kırmızı Sınıf: Protokol Paket Filtreleri & Wireshark Opcode Ezberi

Bu oda **Kırmızı Sınıf**'tadır. ARP opcode değerlerini (`1: Request`, `2: Reply`), DNS response bayraklarını (`dns.flags.response == 1`) ve HTTP/TLS akış filtrelerini doğrudan hatırlamayı gerektirir.

  

### ⏱️ Pazar Günü 3 Dakikalık Hızlı Tekrar Rutini

1. **Opcode ve Bayrak Refleksi (1. Dakika):**
    
      
    - _ARP İsteği (Who has):_ `arp.opcode == 1`
        
          
        
    - _ARP Yanıtı (is at):_ `arp.opcode == 2`
        
          
        
    - _DNS Yanıtı:_ `dns.flags.response == 1`
        
          
        
    - _DNS İsmi Sorgulama:_ `dns.qry.name == "domain"`
        
          
        
2. **3'lü Saldırı Zincirini Sırala (2. Dakika):**
    
      
    - $\text{ARP Spoofing}$ (Ağ geçidini taklit et, araya gir) $\rightarrow$ $\text{DNS Spoofing}$ (Trafiği kendi sahte sunucuna çek) $\rightarrow$ $\text{SSL Stripping}$ (HTTPS'i HTTP'ye düşür, kimlik bilgilerini düz metin çal).
        
          
        
3. **Önleme Mekanizmalarını Zihninde Canlandır (3. Dakika):**
    
      
    - ARP Spoofing'e karşı $\rightarrow$ **Dynamic ARP Inspection (DAI)**
        
          
        
    - DNS Spoofing'e karşı $\rightarrow$ **DNSSEC**
        
          
        
    - SSL Stripping'e karşı $\rightarrow$ **HSTS (HTTP Strict Transport Security)**
