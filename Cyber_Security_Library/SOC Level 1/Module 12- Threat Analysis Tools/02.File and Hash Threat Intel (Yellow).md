## 1. Mimari Yapı ve Uç Nokta Triage Hattı (File & Hash Enrichment Pipeline)

Güvenlik Operasyon Merkezlerinde (SOC) analistin zamanının büyük bölümü alarm kuyruklarını eritmekle geçer. Birinci Seviye (L1) analist için her inceleme değişmez üç adımlı bir hatta oturur:

  

```
┌────────────────────────────────────────────────────────────────────────┐
│                        SOC ALARM TRİAJ DÖNGÜSÜ                         │
├──────────────────────────┬─────────────────────────────┬───────────────┤
│    1. VERIFY (Doğrula)   │    2. ENRICH (Zenginleştir) │3. DECIDE (Karar)│
│  Alarm gerçek mi?        │  İstihbarat platformları    │  Escalate     │
│  Yanlış pozitif (FP) mi? │  ve bağlamsal telemetri ile │  Remediate    │
│  Artefaktı yakala.       │  dosyayı/hash'i zenginleştir│  Suppress     │
└──────────────────────────┴─────────────────────────────┴───────────────┘
```

**File and Hash Threat Intel**, tam olarak bu **Enrich (Zenginleştirme)** aşamasında devreye girer. Tek başına hiçbir anlam ifade etmeyen bir dosya yolunu (`C:\Users\Public\payload.exe`) veya 64 karakterlik bir özet dizisini (SHA-256), kurum içi savunma kararlarına yön veren operasyonel istihbarata dönüştürür.

  

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                      DOSYA VE ÖZET (HASH) İSTİHBARAT ENTEGRASYONU                      │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ GİRDİ: Şüpheli Dosya / Yol / İsim / Hash Değeri                                        │
│  │                                                                                     │
│  ├── 1. Katman: Sezgisel (Heuristic) Dosya Analizi                                      │
│  │   ├── Yol Şüphesi: C:\Users\Public, C:\Windows\Temp, C:\ProgramData                 │
│  │   └── Adlandırma Hilesi: Çift Uzantı (.pdf.exe), Masquerading, Yüksek Entropi       │
│  │                                                                                     │
│  ├── 2. Katman: Kriptografik Parmak İzi (Hash Sabitleme)                                │
│  │   └── certutil / Get-FileHash / sha256sum ──► Değiştirilemez Kimlik Çıkarımı        │
│  │                                                                                     │
│  ├── 3. Katman: Tehdit İstihbarat Platformları ile Zenginleştirme                      │
```

## 2. Sezgisel (Heuristic) Yol ve Dosya Adı Analizi

İkili dosyanın içi açılmadan veya hash hesaplanmadan önce bir analistin elindeki ilk veri **dosya yolu (filepath)** ve **dosya adıdır (filename)**. Bu göstergeler tek başına saldırıyı kesinleştirmese de saldırganın işletim sisteminde nasıl saklanmaya çalıştığına dair doğrudan ipucu verir.

  

### A. Şüpheli Dizin Tercihleri (Staging Directory Patterns)

|**Dizin Yolu**|**Saldırgan Tercih Nedeni**|**SOC Analist Değerlendirmesi**|
|---|---|---|
|`C:\` (Kök Dizin)|Kalıcılık mekanizmaları (Persistence) için sık hedeflenir.|Normal kullanıcı veya standart yazılımlar buraya dosya bırakmamalıdır.|
|`C:\Users\Public\`|Standart kullanıcılar tarafından yazılabilir; oturum açan tüm kullanıcılar erişebilir.|Farklı kullanıcı bağlamlarında yatay hareket ve ortak yürütme için kullanılır.|
|`C:\Users\Public\Public Downloads\`|Yoğun dosya trafiğine sahip, sıkı denetimden kaçması kolay klasör.|İndirici (stager/downloader) zararlılarının ilk sıçrama noktasıdır.|
|`C:\Windows\Temp\`|Geçici, silinebilir (ephemeral) yükleri barındırmak için kullanılır.|Otomasyon araçları tarafından sıklıkla temizlendiği için saldırgan geçici yükler atar.|
|`C:\ProgramData\`|Gizli kalıcılık (Stealth Persistence) sağlamak için meşru yazılım gibi yerleşilir.|Yazma yetkisi bulunan alt dizinlerde meşru servis isimleri taklit edilir.|

### B. Dosya Adı Sezgisel Göstergeleri (Filename Heuristics)

- **Çift Uzantı (Double Extensions):** `payroll.pdf.exe` veya `invoice.pdf.vbs`. Windows'un bilinen dosya uzantılarını varsayılan olarak gizleme özelliğini suistimal eder. Kullanıcı dosyayı salt okunur PDF zannederken işletim sistemi arka planda çalıştırılabilir PE dosyasını yürütür.
    
      
    
- **Sistem İkilisi Kimliğine Bürünme (System Binary Impersonation):** `scvhost.exe` (harf yer değiştirme / typosquatting). Kullanıcının ve analistin `svchost.exe` işlemine olan aşinalığı suistimal edilir.
    
      
    
- **Yüksek Entropili Rastgele İsimler (High-Entropy Strings):** `jh8F21.exe`. Otomatik paketleme (packing) veya polimorfik üretim kalıbıdır; özellikle phishing kampanyalarında sık görülür.
    
      
    
- **Kılık Değiştirme (Masquerading - MITRE T1036):** `backup-2300.exe`. Rutin sistem dosyaları arasına karışarak şüpheyi en aza indirmeyi hedefler.
    
      
    

> [!WARNING]
> 
> **Kritik Kural: Yalnızca Dosya Adı ile Beyaz Liste (Allowlist) Yapılmaz!**
> 
>   
> 
> Meşru sistem süreçleri (örn. `svchost.exe`, `explorer.exe`) mutlaka **tam dosya yolu** ile doğrulanmalıdır (`C:\Windows\System32\svchost.exe`). `C:\Users\Public\svchost.exe` veya `C:\Windows\Temp\scvhost.exe` konumunda görülen her `svchost` açık bir uzlaşma (compromise) göstergesidir.
> 
>   

## 3. Kriptografik Parmak İzi (Hash Analitiği) ve Platform Zenginleştirmesi

Saldırganlar dosya adını veya uzantısını diledikleri gibi değiştirebilir. Ancak **kriptografik özet (Hash)** dosyanın içeriği değişmediği sürece değişmeyen tekil kimlik kartıdır (parmak izi).

  

```
┌────────────────────────────────────────────────────────┐
│              ANALİST HASH YÖNETİM REHBERİ              │
├────────────────────────────────────────────────────────┤
│ • Küçük Harf Zorunluluğu: Hash değerlerini her zaman   │
│   küçük harfle (lowercase) saklayın.                   │
│ • Doğru Nesneyi Özetleyin: Zararlı bir ZIP içindeyse,  │
│   hem arşivin hem çıkarılan ikilinin hash'ini alın.   │
│ • Tek Bit Kuralı: Dosya içindeki tek bir baytın dahi   │
│   değişmesi (Avalanche Effect) hash'i tamamen bozar.   │
└────────────────────────────────────────────────────────┘
```

### A. VirusTotal Üzerinde 6 Aşamalı Taktik Triaj Rehberi

|**Bölüm / Başlık**|**Analistin Yanıt Araması Gereken Soru**|**Şüpheli Göstergeler (Red Flags)**|**Analist Değerlendirmesi**|
|---|---|---|---|
|**Detection Score & Labels**|Kaç antivirüs motoru dosyayı zararlı olarak işaretlemiş?|5 veya daha fazla güvenilir motorun zararlı demesi; ilk 3 büyük üretici arasında uzlaşı olmaması; çelişkili etiketler ("Trojan" vs "PUA").|Yepyeni zararlılarda ilk saatlerde tespit skoru düşük çıkabilir. Tehdit ailesi (`trojan.graftor`) ve yetenek adına odaklanın; 24-48 saat sonra yeniden sorgulayın.|
|**Upload Time**|Dosya platforma ilk ne zaman gönderilmiş?|7 gün önce yüklenmiş olmasına rağmen 10'dan fazla tespit alması; günler/haftalar sonra aniden tespit patlaması yaşanması.|Üreticilerin analizi tamamlaması 48-72 saat alabilir. Tarihsel tespit artışı zararlının yaşlandığını gösterir.|
|**Signatures**|Dosya geçerli bir dijital sertifika ile imzalanmış mı?|Geçersiz, süresi dolmuş veya eksik sertifika; alakasız bir kurum adına düzenlenmiş sertifika.|Geçerli sertifikalar dahi çalınmış olabilir. Sertifika zincirinin geçerlilik tarihlerini doğrulayın.|
|**Properties**|Dosya üstverisinde yapısal anomaliler var mı?|Gece yarısı derleme zaman damgası (örn. 03:00); medya harici dosyalarda yüksek entropi (>7.5).|UPX gibi meşru paketleyiciler de entropiyi artırır. Bilinen temiz sürümlerle boyut ve bölüm kıyaslaması yapın.|
|**Relations**|Zararlı hangi ağ altyapısıyla bağlantı kuruyor?|Bilinen kötü IP/domain ilişkileri; DGA (Domain Generation Algorithm) benzeri alan adları (`xk8f92.xyz`).|Meşru CDN'ler de zararlı barındırabilir. Dış IP'leri Shodan üzerinden açık portlar açısından sorgulayın.|
|**Behavioral**|Yürütme sonrası sistemde hangi eylemler gerçekleşti?|Kritik Registry anahtarlarının değiştirilmesi; süreç enjeksiyonu denemeleri; VSS silme komutları.|Bazı yönetim araçları meşru olarak kayıt defterini düzenler; uç nokta logları (Sysmon/EDR) ile korelasyon yapın.|

### B. MalwareBazaar Tehdit Avcılığı Entegrasyonu

[MalwareBazaar](https://bazaar.abuse.ch/), tehdit istihbaratını teyit etmek için kullanılan açık kaynaklı bir zararlı yazılım havuzudur:

  

- **Tehdit Ailesi Etiketleri (#MalwareFamily):** VirusTotal'de yalnızca 5/70 tespit almış bir dosya, MalwareBazaar üzerinde `#IcedID` veya `#AgentTesla` olarak etiketlenmişse **kesinlikle zararlı** kabul edilmelidir.
    
      
    
- **YARA Kuralı Entegrasyonu:** Gönderilen örnekler analiz edilerek YARA kuralları ile eşleştirilir; analist bu kuralları EDR/SIEM sistemine anında kural olarak ekleyebilir.
    
      
    
- **Tehdit Aktörü / Kampanya Eşlemesi (#TA551):** Örneklerin arkasındaki organize saldırgan grubunu tespit ederek kurum içi hedefli saldırı riskini aydınlatır.
    
      
    
- **Sorgu Sözdizimi:** `sha256:<file_hash>` formatında arama yapılır.
    
      
    

## 4. SOC Analistleri İçin Dinamik Sandbox Analizi

Statik analiz dosyanın **kimliğini**, dinamik sandbox analizi ise dosyanın **niyetini ve davranışını (impact)** ortaya çıkarır.

  

```
┌────────────────────────────────────────────────────────────────────────┐
│                        SANDBOX'IN 3 ANA GÖREVİ                         │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Yürütmeyi Doğrula: Dosya gerçekten çalışıyor mu yoksa yanıltıcı bir │
│    yem (decoy) mi?                                                     │
│ 2. Çalışma Zamanı IOC'lerini Çıkar: Mutex'ler, C2 IP/URL'leri,         │
│    bırakılan (dropped) ikincil yükler.                                 │
│ 3. MITRE ATT&CK Eşlemesi: Gözlemlenen davranışları taktik/teknik       │
│    kimliklerine (T1490, T1036 vb.) dönüştürmek.                       │
└────────────────────────────────────────────────────────────────────────┘
```

### A. Araç Kıyaslaması: Hybrid Analysis vs. Joe Sandbox

- **Hybrid Analysis (Falcon Sandbox):** Süreç davranış ağaçlarına, hızlı özetlere ve temiz MITRE ATT&CK ısı haritalarına odaklanır. Yönetimsel ve hızlı L1 olay müdahalesi için idealdir.
    
      
    
- **Joe Sandbox:** Derinlemesine sistem çağrıları (syscalls), bellek dökümleri (memory dumps) ve tersine mühendislik telemetrisi sunar. Güvenlik ve algılama mühendisleri için uygundur.
    
      
    

### B. Sandbox Kısıtlamaları ve Saldırgan Atlatma (Evasion) Yöntemleri

> [!WARNING]
> 
> **Sandbox Sonuçlarına Asla Körü Körüne Güvenilmez!**
> 
>   
> 
> Saldırganlar sanal analiz ortamlarını tespit etmek için özel savunma mekanizmaları geliştirmiştir. Bir sandbox'ın "temiz" rapor vermesi dosyanın masum olduğunu kanıtlamaz.
> 
>   

1. **Ortam Farkındalığı ve Anti-Sandboxing:** Zararlı kod; hipervizör sürücülerini, donanım kimliklerini veya hata ayıklayıcıları (debuggers) denetler; sanal makinede olduğunu anlarsa zararlı dalı çalıştırmayıp kendini kapatır.
    
      
    
2. **Sınırlı Yürütme Süresi (Execution Timeout):** Sandbox'lar çoğunlukla 2-5 dakika çalışır. Zararlı yazılım `Sleep` çağrıları ile analizin bitmesini bekler (Time-delayed execution).
    
      
    
3. **Şifreli Trafik Kör Noktaları:** Birçok sandbox giden HTTPS/TLS trafiğini çözemez. C2 haberleşmesi veya DNS tünelleme şifreli tüneller arkasında kör noktada kalabilir.
    
      
    
4. **Dosyasız (Fileless) ve Living-off-the-Land (LotL) Saldırılar:** Bellekte doğrudan çalışan, PowerShell ve WMI olay abonelikleri üzerinden yürütülen tehditler diske dosya bırakmadığı için standart dosya sandbox'larından kaçabilir.

## 6. Tüm Terminal Komutları, Kod Parçacıkları ve Parametre Referansı

### A. Windows Komut Satırı ve PowerShell ile Hash Hesaplama

DOS

```
:: Windows Komut İstemi (CMD) ile SHA256 özetini hesaplama
certutil -hashfile bl0gger.exe SHA256
certutil -hashfile Morse-Code-Analyzer SHA256
certutil -hashfile Challenge.bin.sample SHA256
```

PowerShell

```
# PowerShell ile dosyanın SHA256 özetini hesaplama
Get-FileHash -Algorithm SHA256 bl0gger.exe
Get-FileHash -Algorithm SHA256 Challenge.bin.sample
```

### B. Linux Ortamında Hash Hesaplama

Bash

```
# Linux terminalinde SHA256 özetini hesaplama
sha256sum bl0gger.exe
```

### C. Saldırganın Çalıştırdığı Komut Kalıpları ve Analizi

DOS

```
:: Sessiz modda ActiveX kontrol kütüphanesi kaydetme (bl0gger.exe tarafından tetiklenen)
:: %WINDIR%: C:\Windows ortam değişkeni
:: /s: Sessiz mod (silent) - kullanıcıya hiçbir uyarı veya pencere göstermez
regsvr32 %WINDIR%\Media\ActiveX.ocx /s
```

PowerShell

```
# Akira fidye yazılımının gölge kopyaları (Volume Shadow Copies) silme komutu
# Amaç: Kurbanın sistem geri yükleme ile şifrelenen dosyaları kurtarmasını engellemek (MITRE T1490)
Get-WmiObject Win32_Shadowcopy | Remove-WmiObject
```

## 8. Tekrar Kategorisi ve Pazar Stratejisi

- **Kategori Sınıfı:** 🟡 **Sarı (Kavramsal Triaj & Tehdit İstihbaratı / 3 Dakika)**
    
      
    
- **Gerekçe:** Dosya yolu tuzakları (`C:\Users\Public`), çift uzantı riskleri, VirusTotal'de 5+ kuralı, MalwareBazaar etiketlerinin önemi ve fidye yazılımlarının VSS silme komutları (`T1490`) doğrudan mülakatlarda sorulan klasik birinci hat (L1) sorularıdır.
    
      
    
- **Pazar Günü 3 Dakikalık Tekrar Stratejisi:**
    
      
    1. **1. Dakika:** Saldırganların en çok tercih ettiği 3 şüpheli dizini ve gerekçesini say: `C:\Users\Public` (herkes yazar, oturumlar arası geçiş), `C:\Windows\Temp` (geçici/silinebilir yükler), `C:\ProgramData` (gizli kalıcılık).
        
          
        
    2. **2. Dakika:** VirusTotal vs MalwareBazaar kıyasını açıkla: VirusTotal genel antivirüs tespit skoru verirken, MalwareBazaar topluluk tarafından doğrulanmış tehdit ailesi (#IcedID, #Akira) ve doğrudan uygulanabilir YARA imzaları sağlar.
        
          
        
    3. **3. Dakika:** Şu komutu görsen ne düşünürsün: `Get-WmiObject Win32_Shadowcopy | Remove-WmiObject` $\rightarrow$ Fidye yazılımı (Akira vb.) sistem geri yükleme kopyalarını siliyor, **MITRE T1490 (Inhibit System Recovery)**, acil P1 müdahale gerektirir.
