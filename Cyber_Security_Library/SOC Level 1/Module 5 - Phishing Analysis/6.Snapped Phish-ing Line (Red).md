## 1. Mimari Yapı ve Analiz Metodolojisi

Bu senaryoda, **SwiftSpend Financial** bünyesinde çalışan kullanıcılara yönelik organize bir kimlik avı (phishing) saldırısının uçtan uca adli bilişim ve tehdit istihbaratı (CTI) analizi gerçekleştirilmektedir.

  

```
[ Gelen Sahte E-posta ] 
          │
          ├──> [ Ek Dosya: HTML / PDF ] 
          │          │
          │          └──> [ Yönlendirme URL'i: kennaroads.buzz ]
          │                     │
          │                     └──> [ Phishing Landing Page (Microsoft Login Impersonation) ]
          │                                │
          │                                ├──> [ Açık Dizinler: /data/ ve /data/Update365/ ]
          │                                │          ├──> [ log.txt: Ele geçirilen kimlik bilgileri ]
          │                                │          ├──> [ Update365.zip: Phishing Kit Kaynak Kodları ]
          │                                │          └──> [ flag.txt: Gizli Bayrak (Base64 + Reverse) ]
          │                                │
          └──> [ Adli & CTI İnceleme: Hash (VirusTotal), submit.php (Arka Kapı / E-posta Tespiti) ]
```

### 🛠️ Kullanılan Araçlar ve İşlevleri:

- **Thunderbird:** E-posta dosyalarını (`.eml`, raw text) grafik arayüzde açarak başlık (header), gönderici, alıcı ve ek dosyaları (attachment) izole etmek.
    
      
    
- **GNU Coreutils (`grep`, `sort`, `uniq`, `sha256sum`, `wget`, `unzip`):** Ham logları ve kit dosyalarını komut satırından hızla filtrelemek, özetlemek ve bütünlük doğrulaması yapmak.
    
      
    
- **VirusTotal:** Elde edilen ZIP arşivinin hash değerini sorgulayarak CTI istihbaratı (ilk yükleme tarihi, tehdit sınıflandırması, dosya içeriği) toplamak.
    
      
    
- **CyberChef:** Zararlı URL'leri zararsızlaştırmak (defang) ve Base64/Reverse kodlanmış payload'ları deşifre etmek.
    
      
    

## 2. Komutlar, Parametreler ve Canlı Terminal Analizi

### 🔹 Adım 1: E-posta Dizininde PDF Eki İçeren Dosyayı Bulma

E-posta gövdelerinde veya başlıklarında `.pdf` uzantılı eki aramak:

  

Bash

```
grep -rn "\.pdf" ./phish_emails/*
```

- `grep`: Dosyalar içinde metin deseni arayan araç.
    
      
    
- `-r` (recursive): Belirtilen dizin altındaki tüm alt dosyaları tarar.
    
      
    
- `-n` (line-number): Eşleşen satırın dosya içindeki satır numarasını gösterir.
    
      
    
- `"\.pdf"`: Nokta (`.`) karakterini regex kaçışıyla (escape) aratarak `.pdf` uzantısını hedefler.
    
      
    

### 🔹 Adım 2: Phishing Kiti Arşivini İndirme ve SHA256 Hash Doğrulama

Web sunucusundaki açık dizinden kiti indirmek ve hash değerini üretmek:

  

Bash

```
wget http://kennaroads.buzz/data/Update365.zip
sha256sum Update365.zip
```

- `wget`: Belirtilen URL'den doğrudan dosya indiren HTTP istemcisi.
    
      
    
- `sha256sum`: İndirilen arşivin 256-bit SHA özetini hesaplar (VirusTotal sorguları için benzersiz dijital parmak izi).
    
      
    

### 🔹 Adım 3: Sızdırılan Kimlik Bilgileri Logunu İnceleme (Frekans Analizi)

Saldırganın `/data/Update365/log.txt` dosyasını çekip kimlik bilgilerini birden fazla kez giren kurbanı tespit etme:

  

Bash

```
# Log dosyasını indirme
wget http://kennaroads.buzz/data/Update365/log.txt

# Email alanlarını filtreleyip frekans sayımı yapma
grep -i "Email" log.txt | sort | uniq -c

# Şifre alanlarıyla birlikte bağlamı (Context) görme
grep -i "Email" log.txt -A 1
```

- `grep -i "Email"`: Büyük/küçük harf duyarsız olarak "Email" geçen satırları yakalar.
    
      
    
- `sort`: Çıktıyı alfabetik olarak sıralar (`uniq` komutunun doğru çalışması için zorunludur).
    
      
    
- `uniq -c`: Tekrarlayan satırları gruplayıp başlarına tekrar sayısını ekler.
    
      
    
- `-A 1` (After Context): Eşleşen satırın hemen ardından gelen 1 satırı daha ekrana basar (girilen şifreyi doğrulamak için).
    
      
    

### 🔹 Adım 4: Phishing Kitini Çıkarma ve Arka Kapı / E-posta Avı

Arşivi açıp çalınan verilerin iletildiği saldırgan e-posta adreslerini (`submit.php` ve diğer kaynak kodlar) arama:

  

Bash

```
# Arşivi açma
unzip Update365.zip

# submit.php içindeki veri aktarım fonksiyonunu inceleme
cat Update365/office365/Validation/submit.php | grep -E "mail\(|\$to"

# Tüm kit içerisinde Gmail adreslerini tarama
grep -rEi "[a-zA-Z0-9._%+-]+@gmail\.com" ./Update365/
```

- `unzip`: `.zip` arşivini geçerli dizine çıkarır.
    
      
    
- `grep -E`: Genişletilmiş düzenli ifadeleri (Extended Regex) çalıştırır.
    
      
    
- `grep -rEi`: Dizin genelinde büyük/küçük harf duyarsız regex ile spesifik desenleri (Gmail regexi) arar.

## 4. Uzman Notları ve Kritik Uyarılar  

> [!WARNING]
> 
>   
> 
> ### ⚠️ URL Zararsızlaştırma (Defanging) Zorunluluğu
> 
> SOC analiz raporlarında veya biletleme sistemlerinde canlı zararlı URL'ler asla `http://` veya açık nokta `.` ile paylaşılmaz. Analistin veya müşterinin kazara tıklamasını önlemek için `http -> hxxp` ve `. -> [.]` formatına dönüştürülmelidir. CyberChef üzerinde **"Defang URL"** işlemi bu standardı sağlar.
> 
>   

> [!TIP]
> 
>   
> 
> ### 💡 Web Dizin Gezinimi (Directory Listing) Tespiti
> 
> Saldırganlar oltalama sayfalarını yüklerken web sunucusu (Apache/Nginx) yapılandırmasında `Indexes` özelliğini kapatmayı unuttuklarında, `/data/` gibi üst dizinlere gidilerek kaynak kodlar (`.zip`), log dosyaları (`log.txt`) ve saldırganın operasyonel izleri doğrudan ele geçirilebilir.
> 
>   

> [!NOTE]
> 
>   
> 
> ### 🧠 `sort` Olmadan `uniq` Kullanma Hatası
> 
> Linux kabuk ortamında `uniq` komutu yalnızca **ardışık** yinelenen satırları gruplar. Dosya içerisindeki mükerrer kayıtları tam olarak yakalamak için komut her zaman `sort | uniq -c` zinciriyle çalıştırılmalıdır.
> 
>

## 6. Tekrar Kategorisi ve Pazar Günü Çalışma Stratejisi

### 🔴 Renk Sınıfı: Kırmızı (Pratik / Komut & Analiz Zinciri)

Bu oda; statik e-posta analizi, Linux komut satırı filtreleme zincirleri (`grep | sort | uniq`), web açık dizin keşfi ve CTI hash araştırmasını uçtan uca birleştiren pratik bir senaryodur.

  

### ⏱️ Pazar Günü 3 Dakikalık Tekrar Rutini:

1. **1. Dakika (Log & Filtreleme):** `grep -i "email" log.txt | sort | uniq -c` mantığını ve `grep -rn "\.pdf"` kalıbını zihinden tekrar et.
    
      
    
2. **2. Dakika (Phishing Kit İncelemesi):** Phishing kitlerinde form post mekanizmasını kontrol etmek için bakılması gereken dosyanın neden `submit.php` / form action dosyası olduğunu ve saldırgan e-postasının `$to` değişkeninde nasıl saklandığını hatırla.
    
      
    
3. **3. Dakika (CTI & Defanging):** Hash tabanlı VT aramasında hangi sekmelere (Details -> History, Bundled Files) bakıldığını ve IoC defanging (`hxxp`, `[.]`) kurallarını gözden geçir.
