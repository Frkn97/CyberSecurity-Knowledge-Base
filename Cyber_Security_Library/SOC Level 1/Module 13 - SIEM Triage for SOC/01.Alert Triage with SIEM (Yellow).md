# 📊 Log Analysis with SIEM

## 1. Mimari Yapı ve SIEM Analiz Temelleri

Güvenlik Bilgisi ve Olay Yönetimi (**Security Information and Event Management - SIEM**), bir kurumun tüm bilişim altyapısından gelen telemetriyi tek bir çatı altında toplayan merkezi güvenlik motorudur. Bir SOC analistinin operasyonel başarısı, logları yalnızca görüntülemesinde değil; farklı veri kaynaklarını birleştirip birbiriyle bağlayabilmesinde (**Korelasyon**) yatar.

  

SIEM mimarisi üç temel taşıyıcı sütun üzerine kuruludur:

  

1. **Merkezileştirme (Centralisation - Single Pane of Glass):** EDR, IPS, Güvenlik Duvarı, Bulut ve Kimlik sağlayıcıları arasında konsol yorgunluğu (console fatigue) yaşamadan tüm kanıtlara tek bir arama çubuğundan erişim sağlar.
    
      
    
2. **Korelasyon (Correlation):** Görünüşte bağımsız iki olayı (Örn: Ağdaki bir IDS port tarama alarmı ile uç noktadaki şüpheli bir PowerShell oturumu) zaman, IP ve kullanıcı ekseninde bağlayarak saldırı hikayesini tamamlar.
    
      
    
3. **Tarihsel Analiz (Historical Analysis / Look-back):** Geriye dönük sorgularla kullanıcının normal davranış profilini (baseline) çıkarır; haftalar önce başlamış sinsi sızmaları açığa çıkarır.
    
      
    

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                          SIEM GÖRÜNÜRLÜK AĞACI (LOG SOURCES)                           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                          [ SIEM PLATFORMU (Splunk / Elastic) ]                         │
│                                           ▲                                            │
│            ┌──────────────────────────────┼──────────────────────────────┐             │
│            │                              │                              │             │
│  [ Host-Based Logs ]            [ Network-Based Logs ]         [ Web-Based Logs ]      │
│  • Workstation & Sunucular      • Firewall, Router             • Apache, Nginx, IIS    │
│  • Sysmon (EID 1, 3, 7)         • IDS / IPS (Suricata, Snort)  • access.log (200, 500) │
│  • WinEvent (Security/System)   • NetFlow, VPN Gateway         • error.log (403, 503)  │
│  • Linux auth.log & syslog      • DNS Telemetrisi              • Web Shell / Brute     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. Teknik Analiz Zorlukları: Zaman Tuzakları ve Normalizasyon

### A. Zaman Tuzakları (Time Pitfalls & Synchronization Gap)

Farklı coğrafi bölgelerdeki uç noktalar UTC veya yerel saat dilimlerinde log basabilir. Analistin çalıştığı yerel saat dilimi ile SIEM sunucusunun normalizasyon saat dilimi farklı olabilir.

  

- **Tuzak:** Analist UTC-2 bölgesindeyken, Splunk logları UTC+2 formatında indeksliyorsa arada **4 saatlik bir kayma** oluşur. Saat 17:00'da görülen bir olay Splunk'ta 21:00 olarak listelenebilir.
    
      
    
- **Analist Refleksi:** Her zaman **Kaynak Zamanı (Source Time / Event Time)** ile **İndeksleme Zamanı (Index / Ingestion Time)** karşılaştırılmalı; UTC standardı esas alınmalıdır.
    
      
    

### B. Log Normalizasyonu (Log Normalisation & Ortak Bilgi Modeli)

Ham loglar sisteme XML, JSON, Syslog veya düz metin (plain text) olarak akar.

  

- **Normalizasyon Yoksa:** Windows logunda `ClientIP`, Linux'ta `src_ip`, web logunda `c_ip` alan adlarını ayrı ayrı aramak gerekir.
    
      
    
- **Normalizasyon Varsa (CIM - Common Information Model):** Farklı kaynaklardan gelen tüm kaynak IP alanları ortak bir standarda (`src` veya `src_ip`) dönüştürülür; tek bir sorguyla tüm ekosistem taranabilir.
    
      
    

## 3. Platform Bazlı Veri Kaynakları ve Kritik Olay Kodları (Event IDs)

### A. Windows Veri Kaynakları: Sysmon vs. WinEventLogs

> [!WARNING]
> 
> **Planlanmış Görevlerde (Scheduled Tasks) Sahte İsim Tuzağı:**
> 
>   
> 
> Saldırganlar kalıcılık sağlamak için `schtasks.exe` kullandıklarında analistin dikkatinden kaçmak amacıyla göreve `Office365 Install` veya `WindowsUpdate` gibi güvenilir sistem adları verirler. Bir SOC analisti görevin **görünen adına asla güvenmemeli**, görevin çalıştırdığı ikili dosyanın disk yolunu (`ImagePath`) ve hash değerini incelemelidir.
> 
>   

### B. Linux Veri Kaynakları: `auth.log` vs. `syslog`

- **`auth.log` (Kimlik Doğrulama):** Başarısız oturum denemeleri (`Failed password`), başarılı girişler (`Accepted password`), `sudo` ve `su root` yetki yükseltme hareketleri, `useradd` hesap oluşturma olayları.
    
      
    
- **`syslog` (Sistem Olayları):** Servis yeniden başlatmaları, arka plan süreçleri ve zamanlanmış görevler (`cron` / `CRON`). Saldırganların `/etc/cron*` dizinlerine attığı zararlı betikler (`.sh`, `python`, `perl`) buradan izlenir.
    
      
    

### C. Web Erişim Logları: Saldırı İmzaları ve HTTP Durum Kodları

- **Web Brute Force (Kaba Kuvvet):** `/wp-login.php` veya `/login` uç noktalarına kısa sürede (örn. 5 dakikada >25 istek) gelen yoğun `POST` istekleri. `User-Agent` alanında `Hydra` veya `WPScan` gibi araç imzaları aranır.
    
      
    
- **Web Shell Tespiti:** Doğrudan kod çalıştırabilen uzantılara (`.php`, `.jsp`, `.aspx`, `.phtm`) yapılan `POST`/`GET` istekleri ve dönen **HTTP 200 (OK)** yanıtları.
    
      
    
- **DDoS Saldırıları:** Sunucunun aşırı yüklenme sonucu kaynak yetersizliğine düştüğünü gösteren **HTTP 503 (Service Unavailable)** yanıt patlamaları (örn. 10 dakikada >100.000 istek).
    
      
    

## 4. Tüm Splunk SPL Komutları, Parametreleri ve Analiz Sorguları

### A. Windows ve Sysmon SPL Sorguları

SQL

```
-- 1. Sysmon EID 1: EncodedCommand argümanı içeren şüpheli PowerShell süreçlerini yakalama
index=winenv EventCode=1 *powershell* AND *EncodedCommand*
| table _time ComputerName ParentUser ParentImage ParentCommandLine Image CommandLine

-- 2. Sysmon EID 3: Belirli bir uç noktadaki giden ağ bağlantılarını dökme
index=winenv EventCode=3 ComputerName=WINHOST05
| table _time ComputerName Image SourceIp SourcePort DestinationIp DestinationPort Protocol

-- 3. Security Log (EID 4720/4722): Yeni kullanıcı hesabı oluşturma ve etkinleştirme olayları
index=winenv EventCode=4720 OR EventCode=4722
| table _time EventCode ComputerName Subject_Account_Name Target_Account_Name New_Account_Account_Name Keywords

-- 4. System Log (EID 7045/7036): Servis seviyesinde yetki yükseltme ve kalıcılık tespiti
index=winenv EventCode=7045 OR EventCode=7036 ComputerName=WINHOST05
| table _time EventCode ComputerName Service_Name Service_Account Service_File_Name Message

-- 5. Task 4 Pratiği: 5678 portuna giden şüpheli bağlantı ve başlatan süreci bulma
index="task4" EventCode=3 DestinationPort=5678
| table UtcTime ComputerName Image SourceIp SourcePort DestinationIp DestinationPort

-- 6. Task 4 Pratiği: Sürecin MD5 hash değerini çekme
index="task4" EventCode=1 Image=*SharePoInt.exe*
| table ComputerName ParentImage ParentProcessId Image Hashes

-- 7. Task 4 Pratiği: Oluşturulan şüpheli Scheduled Task adını çıkarma
index="task4" EventCode=1 CommandLine=*schtasks*
| table UtcTime ComputerName ParentImage Image CommandLine Description
```

### B. Linux SPL Sorguları

SQL

```
-- 1. auth.log: SSH kaba kuvvet (brute-force) analizi (Başarısız ve başarılı denemeler)
index=linux source="auth.log" *ubuntu* process=sshd
| search "Accepted password" OR "Failed password"

-- 2. auth.log: su ile root kullanıcısına yetki yükseltme denemeleri
index=linux source="auth.log" *su*
| sort + _time

-- 3. syslog: Cron görevleri üzerinden başlatılan ters kabuk (Reverse Shell) avı
index=linux sourcetype=syslog ("CRON" OR "cron")
| search ("python" OR "perl" OR "ruby" OR ".sh" OR "bash" OR "nc")

-- 4. Task 5 Pratiği: remote-ssh kullanıcısının eklenme zaman damgasını çıkarma
index="task5" "remote-ssh" command=useradd
| table _time command user_name eventtype

-- 5. Task 5 Pratiği: jack-brown kullanıcısının başarılı giriş yaptığı IP adresini bulma
index="task5" "jack-brown"
| search "Failed Password" OR "Accepted Password"
| sort + _time

-- 6. Task 5 Pratiği: Cron üzerinden dinlenen ters kabuk portunu tespit etme
index="task5" sourcetype=syslog (*CRON* OR *cron*)
```

### C. Web Erişim ve Anomali SPL Sorguları

SQL

```
-- 1. Web Brute Force: wp-login.php sayfasına 5 dakikada 25'ten fazla gelen POST istekleri
index=* method=POST uri_path="/wp-login.php"
| bin _time span=5m
| stats values(referer_domain) as referer_domain values(status) as status values(useragent) as UserAgent values(uri_path) as uri_path count by clientip _time
| where count > 25
| table referer_domain clientip UserAgent uri_path count status

-- 2. Web Shell Tespiti: Betik uzantılarına gelen ve HTTP 200 dönen şüpheli istekler
index=*
| search status=200 AND uri_path IN(*.php, *.phtm, *.asp, *.aspx, *.jsp, *.exe) AND (method=POST AND method=GET)
| stats values(status) as status values(useragent) as UserAgent values(method) as method values(uri) as uri values(clientip) as clientip count by referer_domain
| where count > 2
| table referer_domain count method status clientip UserAgent uri

-- 3. DDoS Tespiti: HTTP 503 dönen ve 10 dakikada 100.000'i aşan istek patlamaları
index=* status=503
| bin _time span=10m
| stats values(referer_domain) as referer_domain values(status) as status values(useragent) as UserAgent values(uri_path) as uri_path count by clientip _time
| where count > 100000
| table _time referer_domain clientip UserAgent uri_path count status

-- 4. Task 6 Pratiği: En yüksek istek alan URI yolunu bulma
index="task6"
| stats count by uri
| sort - count

-- 5. Task 6 Pratiği: Saldırgan IP'yi ve User-Agent aracını (WPScan) tespit etme
index="task6" uri="*wp-login.php*"
| stats count values(useragent) as UserAgent by clientip
```

## 6. Tekrar Kategorisi ve Pazar Stratejisi

- **Kategori Sınıfı:** 🟡 **Sarı (Kavramsal Analiz & SPL Sorgu Mantığı / 3 Dakika)**
    
      
    
- **Gerekçe:** SIEM mimarisinin 3 sütunu (Centralisation, Correlation, Historical Analysis), normalizasyonun amacı, Sysmon EID 1/3 ayrımı, Windows EID 4720/7045 kullanım senaryoları ve web erişim loglarında Brute Force / DDoS tespit kalıpları mülakatlarda canlı sorgu ve vaka senaryosu olarak sorulur.
    
      
    
- **Pazar Günü 3 Dakikalık Tekrar Stratejisi:**
    
      
    1. **1. Dakika:** SIEM'in temel farkını açıkla: _"Merkezileştirme konsol yorgunluğunu bitirir; Korelasyon ise IDS alarmı ile uç noktadaki Sysmon EID 1 sürecini bağlayarak saldırı hikayesini tamamlar."_
        
          
        
    2. **2. Dakika:** Şu 4 kritik Event ID'yi eşleştir:
        
          
        - **Sysmon EID 1:** Süreç oluşturma (`CommandLine`, Hash).
            
              
            
        - **Sysmon EID 3:** Ağ bağlantısı (`DestinationIp:Port`).
            
              
            
        - **WinEvent EID 4720:** Yeni kullanıcı oluşturuldu (Persistence).
            
              
            
        - **WinEvent EID 7045:** Yeni servis kuruldu (Privilege Escalation / Persistence).
            
              
            
    3. **3. Dakika:** Web loglarında Brute Force ve Web Shell tespit formülünü hatırla:
        
          
        - _Brute Force:_ `/wp-login.php` + `POST` + kısa sürede yüksek sayı (`count > 25`) + `User-Agent: Hydra/WPScan`.
            
              
            
        - _Web Shell:_ `.php/.jsp` + `GET/POST` + `status=200` + az sayıda şüpheli dosya adı (`505.php`).
