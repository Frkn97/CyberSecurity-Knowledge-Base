# 🌐 TryHackMe: Network Traffic Basics (SOC Level 1)

## 🏗️ Mimari Yapı ve Ağ Trafiği Analizi (NTA) Mekanizması

**Ağ Trafiği Analizi (Network Traffic Analysis - NTA)**; bir ağ içerisinde akan verilerin yakalanması, incelenmesi ve anomali tespiti amacıyla analiz edilmesi sürecidir. NTA yalnızca Wireshark aracını kullanmaktan ibaret değildir; log korelasyonu, derin paket denetimi (Deep Packet Inspection - DPI) ve akış telemetrisi (Flow Statistics) bileşenlerinin entegre çalışmasıdır.

## 🧩 1. TCP/IP Katmanları ve İncelenebilir Ağ Verileri

Standart güvenlik duvarları ve proxy'ler paket başlıklarının yalnızca belirli kısımlarını loglar. Tam paket incelemesi (PCAP), başlıkların arkasındaki gizli saldırı imzalarını ve veri yüklerini (payload) açığa çıkarır.

  

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. Uygulama Katmanı (Application): HTTP, DNS, SMB, TLS                 │
│    -> Header bilgisi + Ham Yük / Payload (Zararlı dosya, C2 komutları) │
├────────────────────────────────────────────────────────────────────────┤
│ 2. İletim Katmanı (Transport): TCP, UDP                                │
│    -> Portlar, Flag'ler (SYN, ACK), Sequence & Acknowledgment Numaraları│
├────────────────────────────────────────────────────────────────────────┤
│ 3. İnternet Katmanı (Internet): IP, ICMP                               │
│    -> Kaynak/Hedef IP, TTL, Fragment Offset, Paket Uzunluğu            │
├────────────────────────────────────────────────────────────────────────┤
│ 4. Bağlantı Katmanı (Link): Ethernet, ARP                              │
│    -> Kaynak/Hedef MAC Adresleri, Ağ Arayüzleri                         │
└────────────────────────────────────────────────────────────────────────┘
```

### A. Uygulama Katmanı (Application Layer)

- **Loglanan Kısım:** HTTP GET istek başlıkları, hedef Host adı, User-Agent, durum kodları (200 OK).
    
      
    
- **Gizlenen / Loglanmayan Kısım:** İndirilen ikili (binary) dosya içeriği veya DNS yanıt gövdesi.
    
      
    
- **Örnek İnceleme:**
    
      
    
    HTTP
    
    ```
    GET /downloads/suspicious_package.zip HTTP/1.1
    Host: www.tryhackrne.thn
    User-Agent: curl/7.85.0
    Connection: close
    
    HTTP/1.1 200 OK
    Content-Type: application/zip
    Content-Length: 10485760
    Content-Disposition: attachment; filename="suspicious_package.zip"
    [binary ZIP file bytes follow — 10,485,760 bytes]
    ```
    

### B. İletim Katmanı (Transport Layer) & Oturum Gaspı (Session Hijacking)

- **Tespit Mekanizması:** TCP sıra numaralarının (**Sequence Numbers - Seq**) takibiyle yapılır.
    
      
    
- **Saldırı İmzası:** Beklenmeyen bir IP'den aniden çok yüksek veya uyumsuz bir sıra numarasıyla (`Seq=34567232`) oturuma paket enjekte edilmeye çalışılması oturum gaspı göstergesidir.
    
      
    

Plaintext

```
No.  Source          Destination    Protocol  Info
1    192.168.1.45    172.217.22.14  TCP       51432 → 80 [SYN] Seq=0 Win=64240 Len=0
2    172.217.22.14   192.168.1.45   TCP       80 → 51432 [SYN, ACK] Seq=0 Ack=1 Win=65535 Len=0
3    192.168.1.45    172.217.22.14  TCP       51432 → 80 [ACK] Seq=1 Ack=1 Win=64240 Len=0
4    192.168.1.45    172.217.22.14  TCP       51432 → 80 [PSH, ACK] Seq=1 Ack=1 Len=1460
5    172.217.22.14   192.168.1.45   TCP       80 → 51432 [ACK] Seq=1 Ack=1461 Len=0
6    192.168.99.200  172.217.22.14  TCP       51432 → 80 [PSH, ACK] Seq=34567232 Ack=1 Len=20  <-- Enjeksiyon Girişimi
```

### C. İnternet Katmanı (Internet Layer) & Parçalama Saldırıları (Fragmentation Evasion)

- **Tespit Mekanizması:** `Fragment Offset` ve `Total Length` alanlarının analizi.
    
      
    
- **IDS Atlama (Evasion):** Saldırganlar IDS imzalarından kaçmak için yükü kasıtlı olarak çakışan bayt aralıklarıyla (**Overlapping Offset**) parçalara böler.
    
      
    

Plaintext

```
No.  Source        Destination   Protocol  Info
1    203.0.113.45  192.168.1.10  UDP       Fragmented IP (id=0x1a2b) [MF] Offset=0, Len=1480
2    203.0.113.45  192.168.1.10  UDP       Fragmented IP (id=0x1a2b) [MF] Offset=1480, Len=1480
3    203.0.113.45  192.168.1.10  UDP       Fragmented IP (id=0x1a2b) Offset=1480, Len=64   <-- Çakışma / Overlap
4    192.168.1.10  203.0.113.45  ICMP      Destination unreachable (Fragment reassembly time exceeded)
```

### D. Bağlantı Katmanı (Link Layer) & ARP Zehirleme (ARP Poisoning / Spoofing)

- **Tespit Mekanizması:** Aynı IP adresine karşı ağda aniden farklı ve çakışan MAC adresleri anons edilmesi (**Gratuitous ARP**).
    
      
    

Plaintext

```
No.  Source           Destination   Protocol  Info
1    192.168.1.1      Broadcast     ARP       Who has 192.168.1.10? Tell 192.168.1.1
2    192.168.1.10     192.168.1.1   ARP       192.168.1.10 is at 00:11:22:33:44:55
3    192.168.1.200    192.168.1.1   ARP       192.168.1.10 is at aa:bb:cc:dd:ee:ff  <-- Saldırgan Sahte Yanıtı
4    192.168.1.200    192.168.1.10  ARP       192.168.1.1 is at aa:bb:cc:dd:ee:ff   <-- Ağ Geçidi Sahte Yanıtı
5    192.168.1.10     172.217.22.14 TCP       54433 → 80 [SYN] Seq=0
6    192.168.1.200    172.217.22.14 TCP       54433 → 80 [SYN] Seq=0                 <-- Saldırgan Üzerinden İletim
```

## 🧭 2. Ağ Kaynakları ve Trafik Akış Tipleri

### A. Trafik Kaynakları (Sources)

1. **Uç Nokta Kaynakları (Endpoint Sources):** Ağdaki bant genişliğinin ezici çoğunluğunu oluşturan istemciler, sunucular, mobil cihazlar ve IoT sistemleridir.
    
      
    
2. **Aracı Kaynaklar (Intermediary Sources):** Güvenlik duvarları, anahtarlar (switch), yönlendiriciler (router), web proxy'leri ve IDS/IPS cihazlarıdır. Ürettikleri trafik yönlendirme (OSPF, BGP), yönetim (SNMP, PING) ve log (Syslog) protokolleriyle sınırlıdır.
    
      
    

### B. Trafik Akış Yönleri (Flows)

|**Akış Yönü**|**Tanım**|**Geçtiği Kritik Varlıklar**|**Tipik Protokoller ve Hizmetler**|
|---|---|---|---|
|**North-South (Kuzey-Güney)**|Yerel ağ (LAN) ile dış dünya (WAN/İnternet) arasındaki giriş (**Ingress**) ve çıkış (**Egress**) trafiğidir.|Güvenlik Duvarı (Firewall), Edge Router, Web Proxy|HTTPS, Dış DNS, SSH, VPN, SMTP, RDP|
|**East-West (Doğu-Batı)**|Kurumsal yerel ağ içerisinde kalan (veya yerel ağdan şirket bulutuna uzanan) yatay trafiktir. Saldırganların **Yanal Yayılma (Lateral Movement)** alanıdır.|Dahili Anahtarlar (Switch), VLAN Yönlendirme|Kerberos, LDAP, SMB/CIFS, Dahili DNS, DHCP, RPC, SQL, SNMP|

> [!WARNING]
> 
> **Doğu-Batı (East-West) Trafiğinde Kör Noktalar:**
> 
> Güvenlik ekipleri genellikle dış giriş/çıkış noktalarına (North-South) odaklanır; ancak ağ içi ihlallerde saldırganlar SMB, Kerberos veya yerel RPC çağrıları üzerinden yatayda hareket eder. Kurum içi segmentasyon ve Doğu-Batı görünürlüğü şarttır.
> 
>   

### C. Kritik Kurumsal Akış Senaryoları

- **TLS İncelemeli HTTPS Akışı:** İstemci $\rightarrow$ NGFW/Web Proxy (Oturumu çözer, inceler) $\rightarrow$ Hedef Web Sunucusu. (İstemci ile proxy arasında ayrı, proxy ile sunucu arasında ayrı birer TCP/TLS oturumu kurulur).
    
      
    
- **Dahili DNS Çözümleme:** İstemci $\rightarrow$ Dahili DNS Sunucusu (Port 53) $\rightarrow$ Önbellek yoksa $\rightarrow$ Güvenlik Duvarı $\rightarrow$ Dış DNS Sunucusu.
    
      
    
- **Kerberos ile SMB Erişimi:** İstemci önce Domain Controller (KDC) ile görüşüp **Ticket Granting Ticket (TGT)** ve ardından servis bileti alır; bu bilet ile hedef dosya sunucusuna (`\\FILESERVER\...`) SMB oturumu açar.
    
      
    

## 📡 3. Trafik Toplama ve İzleme Yöntemleri

Plaintext

```
                                [ Trafik Yakalama Karşılaştırması ]
                                                │
                ┌───────────────────────────────┴───────────────────────────────┐
                ▼                                                               ▼
       [ Donanımsal Ağ TAP ]                                          [ Port Mirroring / SPAN ]
  - Fiziksel hatta doğrudan inline takılır                       - Anahtar yazılımı üzerinden port kopyalama
  - Link katmanında çalışır (MAC/IP gereksiz)                    - Ağ cihazının işlemci gücünü kullanır
  - Ağ performansına 0 gecikme / etki                            - Yüksek trafikte paket düşürme (drop) riski
```

### A. Cisco Switch Üzerinde SPAN (Port Mirroring) Yapılandırması

Ağ anahtarındaki bir porttan geçen trafiği analiz makinesine klonlamak için kullanılan standart komut seti:

  

Plaintext

```
# 1. Konfigürasyon moduna geçiş
Switch# configure terminal

# 2. Kaynak arayüzü (izlenecek port) belirleme
Switch(config)# monitor session 1 source interface fastEthernet0/1

# 3. Hedef arayüzü (analiz/IDS makinesinin bağlı olduğu port) belirleme
Switch(config)# monitor session 1 destination interface fastEthernet0/2
```

- `monitor session 1`: SPAN oturum numarasını tanımlar.
    
      
    
- `source interface fastEthernet0/1`: Trafiği kopyalanacak hedef portu belirtir.
    
      
    
- `destination interface fastEthernet0/2`: Klonlanan trafiğin aktarılacağı IDS veya analiz makinesi portunu belirler.
    
      
    

### B. Akış Telemetrisi: NetFlow vs. IPFIX

Paket yükünün tamamını saklamak yüksek hatlarda (10-40 Gbps) devasa depolama gerektirir (1 Gbps hat 24 saatte ortalama **10.8 TB** veri üretir). Bu nedenle akış istatistikleri kullanılır:

  

- **NetFlow:** Cisco tarafından geliştirilen, kaynak/hedef IP, portlar ve bayt miktarlarını toplayan protokol.
    
      
    
- **IPFIX (Internet Protocol Flow Information Export):** IETF tarafından standartlaştırılan, NetFlow v9 tabanlı, üretici bağımsız (vendor-neutral) akış telemetrisi standardıdır.
    
      
    

## 🧪 4. DNS Tünelleme ve Gizli Kanal Analizi (DNS Tunneling)

Saldırganlar güvenlik duvarı kısıtlamalarını aşmak için komuta kontrol (C2) talimatlarını veya sızdırılan verileri DNS TXT/A kayıtlarına gömer.

  

Plaintext

```
Domain Name System (response)
    Transaction ID: 0x4a2b
    Flags: 0x8180 Standard query response, No error
    Queries
        cmd1.evilc2.com: type TXT, class IN
    Answers
        cmd1.evilc2.com: type TXT, class IN, TTL 60, TXT length: 20
            TXT: "SSBsb3ZlIHlvdXIgY3VyaW91c2l0eQ=="  <-- Base64 Kodlanmış C2 Komutu
```

> [!NOTE]
> 
> **DNS Logu vs. Ham Paket Ayrımı:**
> 
> SIEM DNS loglarında yalnızca sorgulanan etki alanı (`cmd1.evilc2.com`) görünürken, tam paket analizinde (PCAP) TXT kaydının içindeki Base64 gömülü komut dizesi (`TXT: "..."`) doğrudan okunabilir.
> 
>
