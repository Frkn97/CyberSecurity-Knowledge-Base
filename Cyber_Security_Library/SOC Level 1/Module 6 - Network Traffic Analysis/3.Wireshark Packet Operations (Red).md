# 🦈 TryHackMe: Wireshark: Packet Operations (SOC Level 1)

## 🏗️ Mimari Yapı ve Paket Operasyonları Mekanizması

Wireshark ile ağ trafiği analizi yaparken on binlerce paket arasında kaybolmamak için iki temel sütun kullanılır: **İstatistiksel Ön Analiz (Triage & Hypothesis Generation)** ve **Granüler Filtreleme Motoru (Packet Filtering Engine)**.

  

Bir analist, ham PCAP dosyasını açtığında doğrudan paketleri tek tek okumaz; önce `Statistics` menüsü ile genel protokol dağılımını, en çok konuşan uç noktaları (Endpoints) ve çözümlenmiş DNS/IP adreslerini çıkararak bir analiz hipotezi kurar. Ardından **Display Filter** sorguları ve gelişmiş fonksiyonlar (`contains`, `matches`, `in`, `regex`) ile doğrudan hedef olaya odaklanır.

  

```
                         [ Ham PCAP / PCAPNG Dosyası ]
                                       │
            ┌──────────────────────────┴──────────────────────────┐
            ▼                                                     ▼
  [ İstatistiksel Triyaj (Statistics) ]                 [ Filtreleme Motoru ]
  ├─► Protocol Hierarchy (Protokol Dağılımı)            ├─► Capture Filters (BPF - Ham Yakalama)
  ├─► Endpoints (Benzersiz IP/MAC/Portlar)              └─► Display Filters (Ekran Filtreleri)
  ├─► Conversations (İki Nokta Arası Akışlar)                 ├─► Temel: Karşılaştırma & Mantıksal
  ├─► Resolved Addresses (DNS / Hostname Eşleşmesi)           ├─► Gelişmiş: contains, matches (Regex)
  └─► Protocol Specific (DNS, HTTP Dağılımı)                  └─► Fonksiyonlar: upper, lower, string
                                       │
                                       ▼
                       [ Odaklanmış Olay Analizi & IoC ]
                       (Zararlı IP/Port Tespiti, Web Sunucu
                        Versiyon Analizi, Bozuk Checksum İncelemesi)
```

## 🧰 Wireshark İstatistik ve Çözümleme Menüleri

|**Menü Yolu**|**İşlev ve Analizdeki Amacı**|**SOC Analistine Sağladığı Görünürlük**|
|---|---|---|
|**`Statistics -> Resolved Addresses`**|DNS yanıtlarından toplanan IP ve Hostname eşleşmelerini listeler.|Erişilen harici alan adlarını (`bbc...`, `rad.msn.com`) hızlıca tespit etmeyi sağlar.|
|**`Statistics -> Protocol Hierarchy`**|Paketteki tüm protokolleri ağaç (tree) yapısında yüzde ve sayaçlarla döker.|Ağdaki anormal protokolleri (Örn: HTTP içinde beklenmeyen IRC veya DNS içinde aşırı TXT) gösterir.|
|**`Statistics -> Conversations`**|İki uç nokta arasındaki tüm trafiği 5 formatta (Ethernet, IPv4, IPv6, TCP, UDP) özetler.|En çok veri aktaran (Top Talkers) istemci-sunucu çiftlerini belirler.|
|**`Statistics -> Endpoints`**|Ağdaki tekil cihazları (IP/MAC) ve aktardıkları bayt/paket miktarlarını listeler.|Saldırgan veya kurban IP adreslerini ve cihaz üreticilerini (OUI / MAC) çıkarır.|
|**`Statistics -> DNS`**|DNS sorgu/yanıt kodlarını (rcode, opcode) ve yanıt sürelerini ağaç yapısında sunar.|DNS Tünelleme anomalilerini ve maksimum istek-yanıt gecikmelerini (Request-Response Time) tespit eder.|
|**`Statistics -> HTTP`**|HTTP istek/yanıt kodlarını ve yük dağılımını (Load Distribution) listeler.|Web sunucularına yapılan istek sayılarını ve erişilen domainleri dökümler.|
|**`Edit -> Preferences -> Name Resolution`**|MAC, IP ve Taşıma Katmanı Port isim çözümleme ayarlarını yönetir.|IP adreslerini harici **MaxMind GeoIP** veritabanı yolu göstererek coğrafi konumlara (Şehir, Ülke, AS Org) eşler.|

## ⚖️ 1. Capture Filters vs. Display Filters Ayrımı

Wireshark iki farklı filtreleme motoruna sahiptir. Bu iki yapının sözdizimi ve kullanım amacı birbirinden tamamen farklıdır:

  

```
┌──────────────────────────────────────┬──────────────────────────────────────┐
│ Capture Filters (Yakalama Filtresi)  │ Display Filters (Görüntüleme Filtresi)│
├──────────────────────────────────────┼──────────────────────────────────────┤
│ - Yakalama başlamadan önce ayarlanır. │ - Yakalama sırasında veya sonrasında  │
│ - Yakalama esnasında DEĞİŞTİRİLEMEZ.  │   istenildiği an DEĞİŞTİRİLEBİLİR.   │
│ - Diske sadece filtreye uyan paketler│ - Diske tüm paketler yazılır; sadece │
│   kaydedilir (Depolama tasarrufu).   │   ekrandaki görünüm daraltılır.      │
│ - Berkeley Packet Filter (BPF) kullanır│ - Wireshark Display Filter Engine   │
│ - Örnek: `tcp port 80`               │ - Örnek: `tcp.port == 80`            │
└──────────────────────────────────────┴──────────────────────────────────────┘
```

> [!WARNING]
> 
> **Filtre Sözdizimi Çakışması:**
> 
> Yakalama filtresi (Capture Filter) alanına `tcp.port == 80` yazılamaz; aynı şekilde Görüntüleme filtresi (Display Filter) alanına `tcp port 80` yazılamaz. Capture filtreleri BPF sözdizimini (`host`, `net`, `port`, `src`, `dst`), Display filtreleri ise nokta notasyonlu protokol ağacını (`ip.addr`, `tcp.srcport`) kullanır.
> 
>   

## 🔍 2. Display Filter Sözdizimi, Operatörler ve Toolbar

Display Filter çubuğu analiste anlık geri bildirim veren akıllı bir renk kodlamasına sahiptir:

  

- 🟢 **Yeşil:** Geçerli ve çalışan filtre sözdizimi.
    
      
    
- 🔴 **Kırmızı:** Hatalı / geçersiz filtre sözdizimi.
    
      
    
- 🟡 **Sarı:** Çalışan ancak güvenilir olmayan / uyarılı filtre (Örn: eskimiş sözdizimi kullanımı).
    
      
    

### A. Karşılaştırma Operatörleri (Comparison Operators)

|**İngilizce Sözdizimi**|**C-Tipi Karşılığı**|**Türkçe Anlamı**|**Canlı Kullanım Örneği**|
|---|---|---|---|
|`eq`|`==`|Eşittir|`ip.src == 10.10.10.100`|
|`ne`|`!=`|Eşit değildir|`ip.src != 10.10.10.100` _(Öneri: `!(ip.src == 10.10.10.100)`)_|
|`gt`|`>`|Büyüktür|`ip.ttl > 250`|
|`lt`|`<`|Küçüktür|`ip.ttl < 10`|
|`ge`|`>=`|Büyük veya eşittir|`ip.ttl >= 0xFA`|
|`le`|`<=`|Küçük veya eşittir|`ip.ttl <= 0xA`|

> [!TIP]
> 
> **`!=` Operatörü Tuzağı:**
> 
> `ip.addr != 10.1.1.1` filtresi, analistin düşündüğü gibi "bu IP'nin olmadığı paketleri" değil; "içinde 10.1.1.1 dışındaki herhangi bir IP'nin de geçtiği paketleri" getirebilir. Tutarlı ve kesin sonuç için her zaman mantıksal **`!(ip.addr == 10.1.1.1)`** yapısı kullanılmalıdır.
> 
>   

### B. Mantıksal Operatörler (Logical Expressions)

|**Operatör**|**C-Tipi**|**Anlamı**|**Örnek Filtre**|
|---|---|---|---|
|`and`|`&&`|Mantıksal VE (Her iki koşul da doğru olmalı)|`(http.request.method == "GET") && (tcp.port == 80)`|
|`or`|`\|`|Mantıksal VEYA (Koşullardan biri doğru olmalı)|`tcp.port == 3333 or tcp.port == 4444 or tcp.port == 9999`|
|`not`|`!`|Mantıksal DEĞİL (Koşulun tersi)|`!(ip.addr == 192.168.1.1)`|

## 🧪 3. Temel Protokol Filtreleri (IP, TCP/UDP, DNS, HTTP)

### A. IP Seviyesi Filtreler (Network Layer)

- `ip`: Tüm IPv4 paketlerini listeler.
    
      
    
- `ip.addr == 10.10.10.111`: Kaynak veya hedef fark etmeksizin ilgili IP'yi içeren paketler.
    
      
    
- `ip.addr == 10.10.10.0/24`: Belirli bir alt ağa (subnet) ait paketler.
    
      
    
- `ip.src == 10.10.10.111`: Yalnızca kaynağı bu IP olan paketler.
    
      
    
- `ip.dst == 10.10.10.111`: Yalnızca hedefi bu IP olan paketler.
    
      
    
- `ip.ttl < 10`: TTL (Time to Live) değeri 10'dan küçük olan paketler.
    
      
    

### B. TCP ve UDP Filtreleri (Transport Layer)

- `tcp.port == 80` / `udp.port == 53`: Belirtilen TCP veya UDP portundaki tüm paketler.
    
      
    
- `tcp.srcport == 1234`: Kaynak portu 1234 olan TCP paketleri.
    
      
    
- `tcp.dstport == 80`: Hedef portu 80 olan TCP paketleri.
    
      
    
- `tcp.port in {3333 4444 9999}`: Belirtilen port kümesinden herhangi birini kullanan paketler.
    
      
    

### C. Uygulama Katmanı Filtreleri (HTTP & DNS)

- `http`: Tüm HTTP trafiğini listeler.
    
      
    
- `http.response.code == 200`: Durum kodu 200 OK olan HTTP yanıtları.
    
      
    
- `http.request.method == "GET"`: HTTP GET istekleri.
    
      
    
- `http.request.method == "POST"`: HTTP POST istekleri.
    
      
    
- `dns`: Tüm DNS trafiğini listeler.
    
      
    
- `dns.flags.response == 0`: DNS İstemci İstekleri (Standard Query).
    
      
    
- `dns.flags.response == 1`: DNS Sunucu Yanıtları (Standard Query Response).
    
      
    
- `dns.qry.type == 1`: DNS "A" (IPv4 Adres) sorguları.
    
      
    

## 🚀 4. İleri Düzey Filtreleme Fonksiyonları ve Operatörleri

Wireshark, dizgi (string) arama, düzenli ifadeler (regex) ve küme kontrolleri için gelişmiş operatörler barındırır:

  

|**Operatör / Fonksiyon**|**Türü**|**İşlev ve Tanımı**|**Canlı Filtre Örneği**|
|---|---|---|---|
|**`contains`**|Karşılaştırma|Paket içinde belirtilen metni/baytı arar (**Büyük/Küçük harfe duyarlıdır - Case Sensitive**).|`http.server contains "IIS"`|
|**`matches`**|Regex / Kalıp|Düzenli ifade (Regular Expression) kalıbı arar (**Harf büyüklüğüne duyarsızdır - Case Insensitive**).|`http.host matches "\.(php\|html)"`|
|**`in`**|Küme Üyeliği|Değerin belirtilen liste/aralık içinde olup olmadığını kontrol eder.|`tcp.port in {80 443 8080}`|
|**`upper()`**|Fonksiyon|Hedef alandaki metinsel değeri tamamen büyük harfe dönüştürerek filtreler.|`upper(http.server) contains "APACHE"`|
|**`lower()`**|Fonksiyon|Hedef alandaki metinsel değeri tamamen küçük harfe dönüştürerek filtreler.|`lower(http.server) contains "apache"`|
|**`string()`**|Fonksiyon|Sayısal/bayt tipindeki veriyi dizgiye (string) çevirerek regex ile aranabilir kılar.|`string(ip.ttl) matches "[02468]$"` _(Çift TTL'ler)_|

> [!EXAMPLE]
> 
> **İleri Düzey Kombinasyon Filtreleri:**
> 
>   
> 
> - **IIS Web Sunucusu 7.5 Versiyonu Arama:**
>     
>     `http.server contains "IIS" && http.server contains "7.5"`
>     
>       
>     
> - **Port 80 Dışından Gelen IIS Yanıtları:**
>     
>     `http.server contains "IIS" && tcp.srcport != 80`
>     
>       
>     
> - **Tek Sayılı Çerçeve Numaralarını Bulma:**
>     
>     `string(frame.number) matches "[13579]$"`
>     
>       
>     

## 🗂️ 5. Profiller (Profiles), Yer İmleri ve Filtre Butonları

Farklı analiz vakalarında (Örn: Web Trafiği, TLS İncelemesi, TCP Checksum Kontrolü) sürekli renk kurallarını ve filtreleri baştan yapılandırmamak için **Configuration Profiles** kullanılır:

  

- **Profil Değiştirme:** `Edit -> Configuration Profiles` veya Durum Çubuğu sağ altındaki profil alanına tıklanarak yapılır.
    
      
    
- **Checksum Control Profili:** TCP doğrulama hatalarını ve bozuk paketleri otomatik yakalamak için önceden yapılandırılmış kuralları ve butonları yükler.
    
      
    
- **Filtre Butonları (Filter Buttons):** Sık kullanılan karmaşık sorgular (`+` simgesi ile) doğrudan arama çubuğunun sağına tek tıkla uygulanabilir buton olarak eklenebilir.
