## 🏗️ Mimari Yapı

**Splunk**, kurum ağında veya uç noktalarda üretilen sunucu, uygulama, güvenlik duvarı ve sistem loglarını gerçek zamanlı olarak toplamaya, indekslemeye, korele etmeye ve analiz etmeye yarayan lider bir **SIEM (Security Information and Event Management)** çözümüdür.

```
                  [ SPLUNK BİLEŞEN VE İŞLEME MİMARİSİ ]
                                    │
    ┌───────────────────────────────┼───────────────────────────────┐
    ▼                               ▼                               ▼
[ Web Servers ]         [ Windows Event / Sysmon ]         [ Linux / DB Logs ]
    │                               │                               │
    └───────────────────────────────┴───────────────────────────────┘
                                    │
                                    ▼
                          [ 1. Splunk Forwarder ]
                   (Hafif Ajan / Log Toplayıcı & Gönderici)
                                    │
                                    ▼
                          [ 2. Splunk Indexer ]
              (Ayrıştırma, Alan-Değer Çifti Oluşturma & İndeksleme)
                                    │
                                    ▼
                         [ 3. Splunk Search Head ]
              (Search & Reporting App / SPL Sorguları & Görselleştirme)
```

### Splunk'ın 3 Temel Bileşeni (Core Components)

1. **Splunk Forwarder (Aktarıcı / Toplayıcı Ajan):**
    
    - İzlenmek istenen uç noktalara (Endpoint) kurulan oldukça hafif (lightweight) bir ajandır.
        
    - Sistem kaynaklarını neredeyse hiç tüketmez.
        
    - Görevi; Web sunucusu logları, Windows Event Logs / Sysmon, Linux logları ve Veritabanı (DB) bağlantı taleplerini toplayıp **Splunk Indexer**'a iletmektir.
        
2. **Splunk Indexer (İndeksleyici / İşleyici):**
    
    - Forwarder'dan gelen ham veriyi işleyen merkezi bileşendir.
        
    - Ham log verisini ayrıştırır (parse), normalize eder, **alan-değer (field-value)** çiftlerine dönüştürür, veri tiplerini belirler ve hızlı aranabilir olaylar (events) olarak indeks veritabanına kaydeder.
        
3. **Splunk Search Head (Arama Başlığı / Analiz Paneli):**
    
    - Analistlerin **Search & Reporting App** arayüzünde **SPL (Search Processing Language)** kullanarak veri sorguladığı bileşendir.
        
    - Arama isteklerini Indexer'a gönderir ve dönen alan-değer sonuçlarını tablo, pasta grafik (pie-chart), çubuk grafik (bar-chart) gibi görselleştirmelere dönüştürür.
        

## 💻 Tüm Komutlar, SPL Sorguları ve Parametre Analizi

Splunk içerisinde log sorgulaması yapılırken **SPL (Search Processing Language)** kullanılır. Ham JSON verileri sisteme yüklendiğinde alanların otomatik ayrıştırılması ve sorgulanması için aşağıdaki komutlar ve boru hatları (pipeline `|`) kullanılır.

### A. Temel Sorgu ve İstatistik Komutları

#### 1. İndeksteki Toplam Olay Sayısını Bulma

Splunk SPL

```
index=VPN_Logs | stats count
```

- `index=VPN_Logs`: Sorgunun sadece `VPN_Logs` isimli indeks üzerinde çalışacağını belirtir.
    
- `| stats count`: Gelen tüm kayıtların toplam sayısını (`count`) istatistiksel olarak hesaplar.
    

#### 2. JSON Alanlarını Otomatik Ayrıştırma (Spath Pipeline)

Splunk SPL

```
index=VPN_Logs | spath | search UserName="Maleena" | stats count
```

- `| spath`: **Newline-delimited JSON** formatındaki verilerin içinde yer alan key-value (anahtar-değer) çiftlerini Splunk alanlarına (fields) otomatik dönüştürür.
    
- `| search UserName="Maleena"`: Ayrıştırılan alanlar arasından `UserName` değeri tam olarak "Maleena" olanları filtreler.
    

#### 3. Belirli Bir IP İle İlişkili Kullanıcıyı ve Olay Sayısını Çıkarma

Splunk SPL

```
index=VPN_Logs | spath | search Source_ip="107.14.182.38" | stats values(UserName) as UserName count
```

- `search Source_ip="..."`: `Source_ip` alanında belirtilen IP adresini arar.
    
- `stats values(UserName) as UserName`: Belirtilen IP'ye karşılık gelen benzersiz kullanıcı adlarını tek bir liste halinde ve "UserName" başlığıyla gösterir.
    

#### 4. Olumsuz Filtreleme (Not Equal To Operator `!=`)

Splunk SPL

```
index=VPN_Logs | spath | search Source_Country!="France" | stats count
```

- `Source_Country!="France"`: `Source_Country` alanı "France" (Fransa) **olmayan** tüm olayları süzgeçten geçirir.
    

#### 5. Belirli Bir IP'nin Toplam Bağlantı Sayısı

Splunk SPL

```
index=VPN_Logs | spath | search Source_ip="107.3.206.58" | stats count
```

- `Source_ip="107.3.206.58"` adresine ait tüm VPN erişim olaylarının adedini döner.

## 🧠 Uzman Notları ve Kritik Uyarılar

> ⚠️ **MÜLAKAT HAPI - SPLUNK İŞLEME SÜRECİ VE İNDEKS MANTIĞI:**
> 
> Mülakatlarda _"Splunk veriyi nasıl arar?"_ sorusu geldiğinde: Forwarder veriyi toplar, Indexer veriyi **alan-değer (field-value)** çiftlerine ayırıp indeks veritabanına yazar. Search Head ise analistin yazdığı SPL komutunu alıp doğrudan bu indekslenmiş veri üzerinde çalıştırır. İndeks belirtmek (`index=VPN_Logs`) arama performansını katba kat artırır.

> 🚨 **KRİTİK UYARI - JSON LOGLARINDA `| spath` BORU HATTI ZORUNLULUĞU:**
> 
> Eğer Splunk'a JSON formatında log yüklediğinizde sol taraftaki **Selected / Interesting Fields** alanında kullanıcı adı, IP gibi değişkenler görünmüyorsa; ana arama sorgusunun sonuna mutlaka `| spath` boru hattını eklemeniz gerekir. `spath`, JSON objesini okuyarak alt parametreleri sorgulanabilir Splunk alanlarına dönüştürür.

> 💡 **SEKTÖREL İPUCU - PORT 8000 VS DEFAULT HTTP PORT:**
> 
> Gerçek dünya kurulumlarında veya Splunk Web konfigürasyonlarında Splunk arayüzü varsayılan olarak `8000` portundan sunulur (`http://IP:8000`). Ancak bu TryHackMe laboratuvar ortamında özel yapılandırma gereği varsayılan HTTP `80` portundan yayın yapılmaktadır.
