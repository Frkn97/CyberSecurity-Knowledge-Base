## 🌐 1. Web Uygulaması Mimarisi (Front End vs Back End)

Bir kullanıcı tarayıcı (Chrome, Safari vb.) üzerinden bir web sitesini ziyaret ettiğinde, tarayıcı arka planda dünyanın herhangi bir yerinde bulunan ve istekleri işlemek üzere tasarlanmış adanmış bir bilgisayar olan **Web Sunucusuna (Web Server)** istek gönderir. Web mimarisi iki ana bileşenden oluşur:

- **Front End (Client-Side / İstemci Tarafı):** Web sunucusundan dönen verilerin, kullanıcının tarayıcısı tarafından işlenerek (render edilerek) ekrana yansıtıldığı görsel ve etkileşimli kısımdır.
    
- **Back End (Server-Side / Sunucu Tarafı):** İstemciden gelen istekleri arka planda işleyen, veritabanı sorgularını yürüten, mantıksal kararları alan ve istemciye yanıt (response) dönen sunucu sistemidir.
    

## 🏗️ 2. Web'in Ön Yüz Yapı Taşları (HTML & JavaScript)

### A) HTML (HyperText Markup Language) — Sayfa İskeleti

Web sitelerinin yapısını ve içeriğini tanımlayan işaretleme dilidir. Sayfayı oluşturan her bir yapı bloğuna **Element (Etiket / Tag)** adı verilir.

> 🧬 **Standart Bir HTML5 Sayfasının Anatomisi:**
> 
> - `<!DOCTYPE html>`: Sayfanın bir **HTML5** dökümanı olduğunu tanımlar. Farklı web tarayıcılarının sayfayı aynı standartlarda yorumlamasını (standardisation) sağlar.
>     
> - `<html>`: Sayfanın kök (root) elemanıdır. Tüm diğer kodlar bunun içinde yaşar.
>     
> - `<head>`: Sayfa hakkında meta verileri, başlığı (`<title>`) ve harici dosyaların linklerini barındırır. Tarayıcı ekranında doğrudan görünmez.
>     
> - `<body>`: Web sitesinde kullanıcının ekranda gördüğü tüm görünür içeriklerin (başlıklar, paragraflar, resimler) tanımlandığı ana gövdedir.
>     
> - `<h1>` / `<p>`: Sırasıyla büyük başlık (heading) ve paragraf tanımlamak için kullanılır.
>     

#### 🏷️ Öznitelikler (Attributes): ID vs Class Farkı (Mülakat Bilgisi)

Etiketlerin içine onlara ek özellikler kazandırmak için `src`, `class` veya `id` gibi öznitelikler eklenir (`<img src="img/cat.jpg">` gibi).

- **Class Attribute:** Sayfa içindeki birden fazla farklı elemente aynı tasarım stilini uygulamak amacıyla **ortak olarak** kullanılabilir.
    
- **ID Attribute:** Sayfa içinde **tamamen benzersiz (unique)** olmak zorundadır. Birden fazla element aynı ID'yi taşıyamaz. JavaScript'in veya CSS'in o elementi sayfada tekil olarak bulup seçmesi için kullanılır.
    
- 🚩 _Kırık Görsel Tamir Bayrağı:_ Sayfa kaynağındaki hatalı `src` resim yolu düzeltilerek kedilerin yüklenmesi sağlandığında ortaya çıkan gizli flag: **`HTMLHERO`**
    
- 🚩 _Görsel Ekleme Bayrağı:_ Satır 11'e yeni bir dog görseli (`<img src="img/dog-1.png">`) eklendiğinde resim üzerinden okunan flag: **`DOGHTML`**
    

### B) JavaScript (JS) — Sayfa Fonksiyonu ve Dinamik Yapı

HTML web sitesinin statik iskeletini oluştururken, JavaScript bu iskelete can veren, sayfayı interaktif (etkileşimli) hale getiren programlama dilidir. JS sayesinde sayfa yenilenmeden gerçek zamanlı olarak içerikler güncellenebilir veya animasyonlar oynatılabilir.

- **Yükleme Yöntemi:** Sayfa kodlarının içine doğrudan `<script>` etiketleri arasında yazılabileceği gibi, `src` özniteliği kullanılarak harici bir dosyadan da çağrılabilir (`<script src="main.js"></script>`).
    
- **DOM Manipülasyonu (Sayfa İçeriğini Değiştirme):** JavaScript sayfa içindeki bir HTML elementini ID'sine göre yakalayıp içeriğini anlık değiştirebilir:
    
    JavaScript
    
    ```
    document.getElementById("demo").innerHTML = "Hack the Planet";
    ```
    
- **Event (Olay) Tetikleyicileri:** HTML elementleri, kullanıcı bir işlem yaptığında JavaScript kodlarını çalıştırabilecek `onclick` (tıklandığında) veya `onhover` (fareyle üzerine gelindiğinde) gibi olay niteliklerine sahiptir. Bu olaylar doğrudan element içinde tanımlanabileceği gibi script etiketleri içinden de yönetilebilir.
    
- 🚩 _JavaScript DOM Manipülasyon Bayrağı:_ Editör üzerinde demo elementinin içeriğini "Hack the Planet" olarak değiştiren JS kodu çalıştırıldığında alınan flag: **`JSISFUN`**
    

## 💀 3. İlk Web Zafiyetleri ve Analist Yaklaşımı

### A) Sensitive Data Exposure (Hassas Veri İfşası)

Geliştiricilerin, kullanıcıların (veya dış dünyanın) kesinlikle görmemesi gereken hassas bilgileri web sitesinin ön yüz (frontend) kodlarında, temiz metin (clear-text) olarak unutması veya düzgün gizleyememesi zafiyetidir.

- **Saldırgan / Analist Taktiği:** Bir web uygulamasının güvenlik değerlendirmesine başlanırken atılacak ilk adım, sayfa kaynağını incelemektir (**View Page Source**). Geliştiriciler HTML yorum satırları (``) içerisine geçici giriş bilgileri, unutulmuş şifreler veya test panellerine giden gizli linkler bırakmış olabilirler.
    
- 🚩 _Exposed Credential Bayrağı:_ Hedef web sitesinin kaynak kodları incelendiğinde yorum satırları arasında unutulan gizli veritabanı/giriş şifresi: **`testpasswd`**
    

### B) HTML Injection (HTML Enjeksiyonu)

Web sitesinin kullanıcıdan formlar, girdi alanları veya arama kutuları aracılığıyla aldığı verileri hiçbir filtrelemeden (**Sanitization / Arındırma**) geçirmeden doğrudan sayfa üzerinde yansıtması (çıktı olarak basması) sonucu oluşan bir enjeksiyon zafiyetidir.

- **Zafiyetin Mantığı:** Sunucu kullanıcı girdisine körü körüne güvenir. Eğer kullanıcı "Adınız nedir?" kutusuna kendi adı yerine zararlı bir HTML veya JavaScript kodu yazarsa (Örn: Bir link veya büyük bir başlık etiketi), tarayıcı bu girdiyi bir metin değil, web sitesinin kendi orijinal koduymuş gibi yorumlar ve çalıştırır. Saldırgan bu sayede sitenin görünümünü manipüle edebilir veya kullanıcıları sahte sitelere yönlendirebilir.
    
- **Önleme Yöntemi (Sanitisation):** Altın kural: **Asla kullanıcı girdisine güvenme!** Geliştirici, kullanıcıdan gelen her veriyi sayfaya basmadan önce filtrelemeli, içerisindeki tehlikeli HTML etiketlerini (`<`, `>`, `/` vb.) temizlemeli veya etkisiz hale getirmelidir.
    
- 🚩 _HTML Injection Sömürü Bayrağı:_ Girdi alanına dış dünyaya yönlendirme yapan sahte/zararlı bir link kodu (`<a href="http://hacker.com">Malicious Link</a>`) enjekte edilerek elde edilen flag: **`HTML_INJ3CTI0N`**
